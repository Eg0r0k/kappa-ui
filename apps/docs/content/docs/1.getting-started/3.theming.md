Colour tokens keep shadcn's names and are written in OKLCH. Every fill comes with a foreground meant to sit on it. In dark mode the fills turn light and their foregrounds dark, so `--primary` works both as a button fill and as link text on the page, in either theme.

Success and warning are the exception. A green or amber dark enough to carry white text turns olive and brown, so in light mode their fills stay bright under dark text, and text on the page uses `--success-text` and `--warning-text` instead: `text-warning-text`, not `text-warning`.

Components read these tokens but do not set them: any shadcn theme works. The values below are delta-ui's own, from the `theme` item described in [Installation](/docs/getting-started/installation#theme). They are read from this page, so the theme toggle changes them too.

## Brand colour

`--primary` and `--ring` are derived from `--brand`, which contributes only its hue and chroma. The lightness is fixed per theme — 0.48 in light, 0.78 in dark — and that is what keeps white on `--primary` above 4.5:1 whatever hue you pick. To rebrand, change one value:

```css
:root {
  --brand: oklch(0.6 0.2 150);
}
```

The [Themes](/themes) page builds this CSS for you: pick a colour, a neutral, a radius and a font, or roll random ones, and copy the result.

The derivation uses relative colour syntax: Chrome 119, Safari 18, Firefox 128 and later. Older browsers fall back to the static values in `:root` and `.dark`, which match the default blue, not your brand. If you support them, update those static values as well.

`--brand` is read where `--primary` is declared, on `:root` and `.dark`. Setting `--brand` on an element further down changes nothing unless you redeclare the derived tokens on the same selector.

## States and shape

Buttons show hover and press as a translucent layer of their own text colour, drawn by the `state-layer` utility, rather than as a separate hover colour per variant. A disabled button takes its colours from `--foreground` whatever its variant. The [ripple](/docs/utilities/ripple) uses the same pressed opacity, and while one is attached, the state layer leaves the press to it.

::css-vars
---
rows:
  - name: --state-hover
    default: 8%
    description: Opacity of the layer under the pointer.
  - name: --state-pressed
    default: 12%
    description: Opacity of the layer, or of the ripple, while pressed.
  - name: --disabled-opacity
    default: 38%
    description: Opacity of `--foreground` for disabled text and icons.
  - name: --disabled-container-opacity
    default: 12%
    description: Opacity of `--foreground` for disabled fills and outlines.
  - name: --radius
    default: 0.75rem
    description: Base corner radius, part of the `theme` item. `--radius-sm`, `-md`, `-lg` and `-xl` are derived from it.
---
::
