title: Sizing

Every control with a `size` prop takes its height, padding, icon size and the gap between icon and text from one scale, `xs` to `xl`. A Button, an Input and a Select of one size line up in a row, and the list a Select or Combobox opens takes its trigger's size, so its items match the trigger.

::

## Scale

::control-anatomy
::

| Size | Height | Padding | Icon | Gap |
| --- | --- | --- | --- | --- |
| `xs` | 28px | 8px | 14px | 6px |
| `sm` | 32px | 10px | 16px | 8px |
| `md` | 36px | 12px | 16px | 8px |
| `lg` | 40px | 12px | 20px | 10px |
| `xl` | 48px | 16px | 20px | 12px |

Each cell is a variable on `:root`, added by the `tokens` item: `--control-height-md`, `--control-padding-md`, `--control-icon-md`, `--control-gap-md` and so on for every size. They're steps of `--spacing`, so `--control-height-md` is `calc(var(--spacing) * 9)`, the same as `h-9`. Button adds `icon-xs` to `icon-xl`: squares of the same heights, for an icon alone.

Leave `size` out and a control is `md`, unless where it sits calls for less: the Toolbar parts start at `sm` and ToastAction at `xs`, so they fit their bar and their toast. InputGroupButton keeps sizes of its own, 24px `xs` and 32px `sm` and their `icon-` squares, to fit inside the group's frame.

## Customising

Override a token on `:root`, and every control of that size follows:

```css
:root {
  --control-height-md: calc(var(--spacing) * 10);
  --control-padding-md: calc(var(--spacing) * 3.5);
}
```

A token set on an element reaches only the controls inside it. Menus, select lists and other overlays render at the end of `<body>`, so they only see `:root`. NavigationMenu's panels are the exception: they open inside the nav, so a token set on the header reaches them.

## What reads it

- **Height**: Button and everything built on it (Toggle, ToggleGroup, Toolbar, Pagination), Input, InputFloating's outline variant, Select, Combobox, InputNumber, TagsInput (as a minimum), PinInput, InputTime, InputDate, InputGroup and the DatePicker and DateRangePicker fields laid over it, Menu items and the lists of Select, Combobox and Command, Menubar triggers and menus, DrawerMenu rows, Listbox options, Tree rows, Tabs triggers, NavigationMenu triggers and links, ColorPicker's controls, the days, weekday columns and arrows of Calendar and RangeCalendar, FileUpload's icon circle, file icons and grid tiles, and Rating's stars, whose box is the control height and the star two thirds of it.
- **Padding**: the text fields (Input, InputFloating, Select, Combobox, InputNumber, TagsInput, InputTime, InputDate, InputGroup's addons and the DatePicker and DateRangePicker fields), Menu items and the lists of Select, Combobox and Command, Menubar triggers and menus, DrawerMenu rows, Listbox options, Tree rows, Tabs triggers, NavigationMenu triggers and links, and FileUpload's drop zone and file list.
- **Icon**: Button and everything built on it, InputTime, InputDate, InputGroup's addons and the DatePicker and DateRangePicker triggers, Menu items and the lists of Select, Combobox and Command, Menubar triggers and menus, DrawerMenu rows, Listbox options, Tree rows, Tabs triggers, NavigationMenu triggers and links, the arrows of Calendar and RangeCalendar, and FileUpload's icons.
- **Gap**: Button, Menu items and the lists of Select, Combobox and Command, Menubar triggers and menus, Listbox options, Tree rows, Tabs triggers, NavigationMenu triggers and links, the header and grid of Calendar and RangeCalendar, FileUpload's zone and file list, and Rating, whose stars sit half the gap apart.

Button pads wider than a field, from 10px at `xs` to 32px at `xl`, so it reads as an action. DrawerMenu adds room for a thumb on top of the tokens; see [below](#menus-and-lists).

Table's row heights are its own, 28px at `xs` to 60px at `xl`: a row holds a line of text with room around it, not a control.

## Component variables

Lists, checkboxes, radios and switches don't size each part on its own. Their root turns `size` into a few variables, and every part inside reads those. An item, its icon and its check mark stay in step, and you get one place to change them.

### Menus and lists

Menu and MenuSubContent, MenubarContent and MenubarSubContent, the lists of Select and Combobox, Command and DrawerMenu set these on their panel. Items, group labels, separators, check marks and the search field at the top of a Command or Combobox list read them.

| Variable | What it sets |
| --- | --- |
| `--menu-item-height` | An item's minimum height. With `--menu-pad`, also the height of the search field. |
| `--menu-item-px` | An item's side padding. Labels and inset items line up on it. |
| `--menu-item-py` | The padding above and below an item's text. It shows once the text wraps. |
| `--menu-item-gap` | The space between an item's icon and its text. |
| `--menu-icon` | The size of an item's icons and check marks. |
| `--menu-pad` | The padding around the items, and the space a separator leaves above and below. |

On Menu, Select, Combobox and Command, height, side padding, gap and icon are the control tokens of the same size:

| Size | Height | Side padding | Above and below | Gap | Icon | Pad |
| --- | --- | --- | --- | --- | --- | --- |
| `xs` | 28px | 8px | 6px | 6px | 14px | 2px |
| `sm` | 32px | 10px | 8px | 8px | 16px | 4px |
| `md` | 36px | 12px | 8px | 8px | 16px | 4px |
| `lg` | 40px | 12px | 8px | 10px | 20px | 4px |
| `xl` | 48px | 16px | 12px | 12px | 20px | 4px |

DrawerMenu is tapped, not clicked. It adds room for a thumb to the same tokens, and its gap follows its side padding:

| Size | Height | Side padding | Above and below | Gap | Icon | Pad |
| --- | --- | --- | --- | --- | --- | --- |
| `xs` | 36px | 10px | 6px | 10px | 14px | 8px |
| `sm` | 40px | 12px | 8px | 12px | 16px | 8px |
| `md` | 48px | 16px | 12px | 16px | 20px | 8px |
| `lg` | 56px | 16px | 12px | 16px | 24px | 8px |
| `xl` | 64px | 20px | 16px | 20px | 24px | 8px |

### Checkbox, Radio and Switch

A 36px checkbox would be absurd, so these keep steps of their own, one variable each:

| Size | `--choice-size` | `--switch-h` |
| --- | --- | --- |
| `xs` | 14px | 16px |
| `sm` | 16px | 20px |
| `md` | 18px | 24px |
| `lg` | 20px | 28px |
| `xl` | 24px | 32px |

`--choice-size` is the box of a Checkbox or Radio. Its touch area, its hover halo, the radio's dot and the space before its label are worked out from it.

`--switch-h` is the height of a Switch's track. The track is 1.625 times as wide (`--switch-w`), and the thumb, the icon in it, the touch area and the halo scale with it.

A horizontal [Field](/docs/components/field) with a description reads both, to set the control level with the first line of its label.

### Calendars

Calendar and RangeCalendar set three on their root: `--calendar-cell`, the size of a day, a weekday column and the arrows (`--control-height-*`); `--calendar-icon`, the chevrons in the arrows (`--control-icon-*`); and `--calendar-gap`, the space in the header and between it and the grid (`--control-gap-*`). Months side by side sit twice the gap apart.

### Overriding them

For one component, put the variable in a class on the part that sets it: the panel of a list, or the control itself. It wins over the size's own value.

```vue
<SelectContent class="[--menu-item-height:2.5rem]">…</SelectContent>
<DrawerMenu class="[--menu-item-gap:--spacing(3)]">…</DrawerMenu>
<Checkbox class="[--choice-size:1.375rem]" />
```

For every one, write a rule outside any CSS layer, so it beats Tailwind's utilities, and key it on the slot. The panels of Menu, MenuSubContent, MenubarContent, MenubarSubContent, Select, Combobox, Command and DrawerMenu also carry `data-size`, and so do Checkbox, Radio and Switch, so a rule can change one size only:

```css
[data-slot='menu'][data-size='md'],
[data-slot='menu-sub-content'][data-size='md'],
[data-slot='select-content'][data-size='md'],
[data-slot='combobox-list'][data-size='md'] {
  --menu-item-height: 2.5rem;
}
```

Setting one on an ancestor does nothing: the panel or control sets its own value, and its parts see that one.
