The [select](/docs/components/select), [dropdown menu](/docs/components/dropdown-menu), [context menu](/docs/components/context-menu) and a modal [popover](/docs/components/popover) are modal: while one is open the rest of the page is shut. An outside click only closes it, the page does not scroll, and screen readers see only the open panel.

## The first outside click

Reka UI shuts the page by setting `pointer-events: none` on `<body>`. That does not reach elements that set `pointer-events: auto` themselves, such as a button in a floating toolbar whose container lets clicks through. Those stay clickable, so the click that closes a menu would also press them.

delta-ui's overlays put a transparent scrim under the open panel that covers the whole window. The first outside click lands on the scrim, closes the overlay and goes no further. The scrim stays until Reka lets go of the page, after the exit animation, and until the press on it ends, so the release cannot land on the element underneath either. The next click works as usual.

Below, open the select or the menu and press the button in the corner: the first press only closes the overlay.

::

Non-modal overlays, such as a popover without `modal` or a menu with `:modal="false"`, have no scrim: an outside click closes them and reaches whatever it lands on.

## Setup

While an overlay is open, Reka UI hides the page's scrollbar and pads `<body>` by its width so the content does not move. Elements with `position: fixed`, such as a header, are not padded and jump sideways by the width of the scrollbar.

The overlay styles set `scrollbar-gutter: stable` on `<html>`, which keeps the space for the scrollbar reserved even while it is hidden, so nothing moves. Reka UI's padding then has to go, or it would shift the content by the same amount the other way. Turn it off once, around the app:

```vue
<script setup lang="ts">
import { ConfigProvider } from 'reka-ui'
</script>

<template>
  <ConfigProvider :scroll-body="false">
    <RouterView />
  </ConfigProvider>
</template>
```

On systems with overlay scrollbars, such as macOS by default and phones, there is no gutter and nothing to reserve.

## Rendering into a container

Overlays render at the end of `<body>`. To render them somewhere else, such as inside an element shown with the Fullscreen API, where content outside the element is not visible, provide the container to the components inside it:

```vue
<script setup lang="ts">
import { provideOverlayPortalTarget } from '@delta-ui/core/overlay'

const container = ref<HTMLElement>()
provideOverlayPortalTarget(container)
</script>

<template>
  <div ref="container">
    <!-- selects, menus and popovers in here render into the container -->
  </div>
</template>
```
