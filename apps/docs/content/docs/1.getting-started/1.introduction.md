Components are not an npm package. Each one is a registry item, and the `shadcn-vue` CLI copies its source into your project: from then on the code is yours to change, and nothing upstream can break it. What should keep receiving fixes, the directives, overlays, the toast manager and the menu parts Reka UI keeps internal, lives in `@kappa-ui/core` on npm, which the CLI installs with the first component and which you update like any dependency.

::

## What you get

- Components built on [Reka UI](https://reka-ui.com) primitives and styled with Tailwind CSS v4.
- shadcn's semantic colour tokens in OKLCH, with a class-based dark mode.
- One `class` prop per component, merged over its own classes with tailwind-merge. A part that needs its own styling is its own component.
- A `data-slot` attribute on every component root, so parts can be targeted from CSS and tests without depending on class names. Button also carries `data-variant` and `data-size`. Under `as-child` they land on your own element.
- Every example on this site is a registry item too, installable with the command under its Code tab.
