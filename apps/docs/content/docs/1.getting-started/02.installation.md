## Requirements

A Vue 3 or Nuxt project with **Tailwind CSS v4**. Components rely on utilities that v3 doesn't have or draws differently, and nothing checks your version for you. Check it before you add anything.

The components are written in TypeScript, so a TypeScript project needs **TypeScript 5 or 6**. vue-tsc, which checks `.vue` files, won't run on anything older than 5.0.

## Set up

1. Run init once:

   ```bash
   npx shadcn-vue@latest init --preset https://kappa-ui.pages.dev/r/init.json
   ```

   It creates `components.json` with the `@kappa-ui` registry, adds the `cn()` helper and writes the tokens and the default theme into your stylesheet.

2. Add a component:

   ```bash
   npx shadcn-vue@latest add @kappa-ui/button
   ```

   Its source lands in your project. From here on, it's your code.

### Already have components.json?

Skip init and add the registry to it instead:

```json [components.json]
{
  "registries": {
    "@kappa-ui": "https://kappa-ui.pages.dev/r/{name}.json"
  }
}
```

Components work with the theme you already have. Want Kappa UI's look as well? Add the [theme](#theme).

## Nuxt

Nuxt registers every file under `components/` as a component. Each component folder holds both `Button.vue` and an `index.ts` that re-exports it, so both claim the name `UiButton` and Nuxt warns about the clash (`NUXT_B3011`). Scan `.vue` files only:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  components: [{ path: '~/components', extensions: ['.vue'] }],
})
```

This array replaces Nuxt's default directories instead of adding to them. Using `components/global` or `components/islands`? List them too.

## Theme

Components read colour tokens but never set them. Your existing theme keeps working, and adding a component never changes a colour you've set.

Kappa UI's own look is the `theme` item. Init adds it. Skipped init? Add it once, and the CLI asks before overwriting your variables:

::install-tabs{name="theme"}
::

The theme makes `--primary` and `--ring` follow `--brand`, so rebrand through `--brand`. See [Brand colour](/docs/getting-started/theming#brand-colour).

## Update

Components are your code, so they change only when you add them again. `--overwrite` replaces the file with the current version, and your edits go with the old one, so commit first:

```bash
npx shadcn-vue@latest add @kappa-ui/button --overwrite
```

The core package updates from npm. Install its latest release:

```bash
npm install @kappa-ui/core@latest
```

`npm update` won't get you there: it stays inside the range the CLI wrote, such as `^0.9.0`, and while the version starts with `0.`, a caret range never reaches the next minor release.

## What installing changes

Some items write to your global stylesheet, not just to their own files. Here's what lands there.

Components that need them bring the `tokens` item. It only adds variables your theme doesn't have, so it never replaces anything:

- the status colours `--success`, `--warning` and `--info`, and `--destructive-foreground`
- the shadow and state tokens from [Theming](/docs/getting-started/theming#states-and-shape)
- the [typescale](/docs/getting-started/typography), [motion](/docs/getting-started/motion) and [control size](/docs/getting-started/sizing) tokens

::install-tabs{name="tokens"}
::

`tokens` also adds the core package as a dependency, and one line to your stylesheet: `@import "@kappa-ui/core/tailwind.css";`. That file holds the utilities components are drawn with, such as `state-layer`, `focus-ring` and `press-scale`, and updates with the package. The tokens stay in your stylesheet, where you can change them.

::callout{type="warning"}
**Keep Kappa UI's `cn()`.** Components size text with utilities like `text-label-lg`. A plain `cn()` takes those for a text colour and drops them next to `text-primary-foreground`. Kappa UI's `lib/utils.ts` tells tailwind-merge about the typescale with `extendTailwindMerge`. Already have a `lib/utils.ts`? The CLI asks before replacing it. If you keep yours, add the same `extendTailwindMerge` call to it.
::

Button also adds the base rule that `shadcn-vue init --pointer` installs. Tailwind v4 dropped the pointer cursor on buttons, and this brings it back for every button in your project, not only Kappa UI's:

```css
@layer base {
  button:not(:disabled),
  [role="button"]:not(:disabled) { cursor: pointer; }
}
```

The core stylesheet has a base rule of its own, and it reaches every page:

::callout{type="warning"}
**`html { scrollbar-gutter: stable }` keeps the scrollbar's space reserved.** The page always leaves room for a vertical scrollbar, so it doesn't shift sideways when an overlay locks scrolling and the scrollbar goes away. The catch:

- Where scrollbars take up space, as on Windows, a page too short to scroll shows an empty strip along its edge.
- Overlays that pad `<body>` for the missing scrollbar now shift the page by its width instead. Reka UI's overlays, Kappa UI's included, stop once `ConfigProvider` has `:scroll-body="false"`, as [Overlays](/docs/getting-started/overlays#setup) sets up. Overlays from other libraries need their own scrollbar padding turned off.
- To opt out, add `html { scrollbar-gutter: auto; }` to your stylesheet and remove `:scroll-body="false"`, so Reka UI pads `<body>` again. Pages then shift whenever they start or stop scrolling, and fixed elements, such as a header, jump by the scrollbar's width while an overlay is open.
::

## Content Security Policy

Got a Content Security Policy? Parts from the core package set the styles they depend on inline: the overlay scrim's position, the ripple's geometry and the scroll area's overflow. With server-side rendering, some of them reach the page as `style=""` attributes. A policy that forbids inline style attributes blocks those, hydration doesn't put them back, and the parts stop working.

If your policy sets `style-src` or `style-src-attr`, allow `'unsafe-inline'` for style attributes.
