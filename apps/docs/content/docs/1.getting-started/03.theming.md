Components never hard-code a colour. They read colour tokens with the usual names, `--primary`, `--background`, `--border` and so on, written in OKLCH. Every fill comes with a foreground meant to sit on it. In dark mode the fills turn light and their foregrounds dark, so `--primary` works as a button fill and as link text, in either theme.

Success, warning and info are the exception. A green, amber or sky blue dark enough to carry white text turns olive, brown and navy, so in light mode their fills stay bright under dark text. For text on the page, use `--success-text`, `--warning-text` and `--info-text`: `text-warning-text`, not `text-warning`.

Components read these tokens but never set them, so any theme with these names works. The values below are Kappa UI's own, from the [theme item](/docs/getting-started/installation#theme). They're read live from this page, so the theme toggle changes them too.

Each card lists the WCAG contrast of its pairs, as rendered in the theme shown. Text needs 4.5:1 and control borders 3:1. Between 3:1 and 4.5:1 is only enough for large text.

## Brand colour

Want your own brand colour? Change one value:

```css
:root {
  --brand: oklch(0.6 0.2 150);
}
```

`--primary` and `--ring` follow `--brand`, but take only its hue and chroma. The lightness is fixed per theme, so white text on `--primary` stays above 4.5:1 whatever hue you pick.

::brand-derivation
::

::callout{type="warning"}
**Set `--brand`, not `--primary`.** The theme derives `--primary` from `--brand`, and in current browsers that overrides a `--primary` you set by hand.
::

Rather click than type? The palette button in the header opens the theme customiser. Pick a colour, a neutral, a radius, surface borders and a font, then press **Copy CSS**.

The derivation needs relative colour syntax: Chrome 119, Safari 18, Firefox 128 or later. Older browsers fall back to the static values in `:root` and `.dark`, which match the default blue. Supporting them? Update those static values too.

`--brand` only works where `--primary` is declared, on `:root` and `.dark`. Setting it on an element further down changes nothing, unless you redeclare the derived tokens on the same selector.

## Tones

A **tone** is the colour a component is drawn in, picked with its `color` prop. `color="success"` sets `data-color="success"` on the root, and that turns into the variables every **variant**, the component's look, reads. Three variables are inputs. The other four are derived from them, and you can override those too.

::tone-anatomy
::

| Variable                | Value                                     | Role                                                                                |
| ----------------------- | ----------------------------------------- | ----------------------------------------------------------------------------------- |
| `--tone`                | input                                     | The fill of the `solid` variant.                                                    |
| `--tone-foreground`     | input                                     | Text and icons on that fill.                                                        |
| `--tone-text`           | input                                     | Text in this colour on the page: `outline`, `ghost`, `link`, and the toast icon.    |
| `--tone-soft`           | 12% of `--tone` over transparent          | The fill of `soft` and `subtle`.                                                    |
| `--tone-soft-foreground` | `--tone-text`                            | Text on the soft fill.                                                              |
| `--tone-border`         | `--tone-text`                             | The edge of `outline`.                                                              |
| `--tone-border-subtle`  | 25% of `--tone-border` over transparent   | The edge of `subtle`.                                                               |

The built-in tones read the tokens above:

- `primary` and `destructive` use their pair, with the fill doubling as the text colour.
- `success`, `warning` and `info` write their text in `--success-text`, `--warning-text` and `--info-text`.
- `neutral` fills with `--foreground`, softens with `--secondary` and draws its edges in `--input`.

Switch, Checkbox, Radio and Slider have no `color` prop. They're `primary`, with `--input` as the edge while unchecked, and turn `destructive` when invalid. To draw one in another tone, set the inputs in its `class`, such as `class="[--tone:var(--success)] [--tone-foreground:var(--success-foreground)]"`.

### Your own tone

Three tokens and one rule. Declare the tokens per theme, next to the rest of your theme, then map them:

```css
:root {
  --pro: var(--color-violet-600);
  --pro-foreground: var(--color-violet-50);
  --pro-text: var(--color-violet-700);
}
.dark {
  --pro: var(--color-violet-400);
  --pro-foreground: var(--color-violet-950);
  --pro-text: var(--color-violet-300);
}

[data-slot][data-color='pro'] {
  --tone: var(--pro);
  --tone-foreground: var(--pro-foreground);
  --tone-text: var(--pro-text);
}
```

```vue
<Button color="pro">Upgrade</Button>
<Badge color="pro" variant="soft">Pro</Badge>
<Alert color="pro" variant="subtle">Your trial ends in 3 days.</Alert>
```

Keep `[data-slot]` in the selector. The derived values live on `[data-slot][data-color]`, and a less specific rule can't override them. To override one, add it to the same rule, such as `--tone-soft: var(--color-violet-50)` when the design has its own tint.

Got a scale from 50 to 950, from Tailwind or a design file? Map it like this:

|                     | Light       | Dark |
| ------------------- | ----------- | ---- |
| `--tone`            | 600         | 400  |
| `--tone-foreground` | white or 50 | 950  |
| `--tone-text`       | 700         | 300  |

Your own elements can join in. Give one `data-slot` and `data-color`, and `bg-tone-soft`, `text-tone-text` and the other `tone-*` colours work on it and its children.

Just one component? Skip the rule and set the inputs in its `class`: `class="[--tone:var(--color-pink-500)] [--tone-foreground:white] [--tone-text:var(--color-pink-700)]"`.

## Dark mode

Want dark mode? Add the `dark` class to `<html>`.

The theme puts the light values on `:root` and the dark ones on `.dark`. Components have no `dark:` utilities: their tokens change value, and every variant follows. `.dark` works on any element, not only `<html>`, so one part of a page can go dark on its own:

::dark-mode-split
::

The theme also sets `color-scheme: dark` under `.dark`, so the browser's own controls, such as date pickers and scrollbars, turn dark with it.

Kappa UI doesn't pick a dark mode mechanism for you. If your `dark:` utilities follow `prefers-color-scheme`, they keep working, and only the `.dark` class switches Kappa UI's colours. Want `dark:` to follow the class instead? Add this variant to your stylesheet:

```css
@custom-variant dark (&:is(.dark *));
```

Using Nuxt? `@nuxtjs/color-mode` with `classSuffix: ''` sets exactly this class. That's how this site switches.

## States and shape

Hover and press show as a translucent layer of the button's own text colour, so no variant needs a hover colour of its own. A disabled button takes its colours from `--foreground`, whatever its variant. The [ripple](/docs/components/ripple) uses the same pressed opacity and takes over the press while it's attached.

Keyboard focus is a 3px outline in `--ring` at half strength, outside the element. Being an outline, it leaves the element's shadow alone and stays visible in forced colours mode. Use it in your own components too: `focus-visible:focus-ring`, or `focus-ring-inset` to draw it inside.

Corners grow with height: `--radius-md` on 28px controls, `--radius-lg` from 32 to 40px and `--radius-xl` from 48px. Badges under 24px take `--radius-sm`. Parts inside a container, like menu items, tabs and the buttons of an input group, take the container's radius minus their distance from its edge, so the corners stay concentric.

**Surfaces** are the panels that sit on or above the page: cards, dialogs, menus, popovers and select lists. Want a hairline around them? Set `--surface-border` to `var(--border)`.

::css-vars
---
rows:
  - name: --state-hover
    default: 8%
    description: Opacity of the layer under the pointer.
  - name: --state-pressed
    default: 12%
    description: Opacity of the layer, or of the ripple, while pressed.
  - name: --state-selected
    default: 8%
    description: Opacity of the primary tint under a selected option, list item or choice card.
  - name: --disabled-opacity
    default: 38%
    description: Opacity of `--foreground` for disabled text and icons.
  - name: --disabled-container-opacity
    default: 12%
    description: Opacity of `--foreground` for disabled fills and outlines.
  - name: --scrim
    default: oklch(0 0 0 / 40%)
    description: The dimmed layer behind a modal dialog; 60% in the dark theme.
  - name: --surface-border
    default: transparent
    description: Border colour of cards, dialogs, menus, popovers and select lists. The default theme draws them without one; set it to `var(--border)` for a hairline. The width is always there, so nothing moves. Set it on `:root` for every surface or on one element for that one.
  - name: --shadow-xs … --shadow-xl
    default: Tailwind's shadow-xs … shadow-xl
    description: Elevation of slider thumbs, the pill tab indicator, popovers, menus, toasts and dialogs, drawn with `shadow-shadow-xs` to `shadow-shadow-xl`. Tailwind's own `shadow-*` classes keep their values.
  - name: --radius
    default: 0.5rem
    description: Base corner radius, part of the `theme` item. `--radius-xs` to `--radius-4xl` are multiples of it, from 0.2× to 2.6× (`lg` is 1×), so `0` squares every corner.
