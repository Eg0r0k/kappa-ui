## Requirements

kappa-ui needs **Tailwind CSS v4**. Components rely on v4-only utilities and semantics — `size-9`, `min-h-svh`, v4 `outline` behaviour — that do not exist or behave differently on v3. The registry-item schema has no field to declare this, so check your project before adding anything.

kappa-ui works in any Vue 3 or Nuxt project that uses Tailwind CSS v4.

## Set up

Run the init command once. It creates `components.json` with the `@kappa-ui` registry and adds the `cn()` helper, the tokens and the default theme:

```bash
npx shadcn-vue@latest init --preset https://kappa-ui.pages.dev/r/init.json
```

## Add a component

```bash
npx shadcn-vue@latest add @kappa-ui/button
```

Every component page shows the command for its own item. The full URL works too, with or without the setup:

::install-tabs{name="button"}
::

### A project that already has components.json

Add the registry to `components.json` instead of running init:

```json [components.json]
{
  "registries": {
    "@kappa-ui": "https://kappa-ui.pages.dev/r/{name}.json"
  }
}
```

## Update

Components are your code, so they change only when you add them again: `npx shadcn-vue@latest add @kappa-ui/button --overwrite` replaces the file with the current version, including your edits. Their mechanism is in `@kappa-ui/core`, which updates like any dependency:

```bash
npm update @kappa-ui/core
```

## Nuxt

Nuxt registers every file under `components/` as a component. A kappa-ui component folder holds both `Button.vue` and an `index.ts` that re-exports it, so both claim the name `UiButton` and Nuxt warns about the clash (`NUXT_B3011`). Limit the scan to `.vue` files:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  components: [{ path: '~/components', extensions: ['.vue'] }],
})
```

An explicit `components` array like this one replaces Nuxt's default directories instead of extending them, so if your project relies on `components/global` or `components/islands`, list those directories too.

## Theme

Components work with any shadcn theme. They read shadcn's colour tokens and bring along only the tokens shadcn does not define, so adding one never changes a colour you have set.

kappa-ui's own look is a separate item. Add it once to replace your colours and radius with kappa-ui's; the CLI asks before overwriting existing variables:

::install-tabs{name="theme"}
::

It also adds an `@supports` block that derives `--primary` and `--ring` from `--brand`. A `--primary` set by hand is overridden by that block in current browsers, so change `--brand` instead. See [Theming](/docs/getting-started/theming).

## What installing changes

Some items write to your global stylesheet, not only to their own files. Decide before you install rather than after.

Every component that needs them adds the `tokens` item: the status colours `--success` and `--warning`, the state tokens from [Theming](/docs/getting-started/theming), the [typescale](/docs/getting-started/typography) and [motion](/docs/getting-started/motion) tokens, and `--destructive-foreground`. These names are not shadcn's, so they are added without replacing anything.

::install-tabs{name="tokens"}
::

`tokens` also adds one line to your stylesheet: `@import "@kappa-ui/core/tailwind.css";`. That file, from the `@kappa-ui/core` package, which `tokens` adds as a dependency, carries the utilities they are drawn with: `state-layer`, `focus-ring`, `press-scale`, the overlay, accordion and skeleton motion, `scrollbar-hidden` and the scroll fades. It updates with the package, while the tokens stay in your stylesheet, where you can change them. Tailwind only emits a theme variable once something uses it, so unused tokens are absent from your compiled CSS.

::callout{type="warning"}
**`cn()` has to know the typescale.** Components size text with utilities such as `text-label-lg`, which tailwind-merge takes for a text colour unless it is told otherwise, and then drops next to `text-primary-foreground`. kappa-ui's `lib/utils.ts` registers the scale with `extendTailwindMerge`. If your project already has a `lib/utils.ts`, the CLI asks before replacing it; if you keep yours, add the same `extendTailwindMerge` call to it.
::

The button also adds the base rule `shadcn-vue init --pointer` installs. Tailwind v4 removed the pointer cursor from buttons; this restores it for every button in your project, not only kappa-ui's:

```css
@layer base {
  button:not(:disabled),
  [role="button"]:not(:disabled) { cursor: pointer; }
}
```

## Content Security Policy

Parts from `@kappa-ui/core` set the styles their behaviour depends on inline: the overlay scrim's position, the ripple's geometry, and the scroll area's overflow. Styles set from script are not affected by a Content Security Policy, but with server-side rendering some of them reach the page as `style=""` attributes in the HTML. A policy that forbids inline style attributes blocks those, and the parts do not work: hydration does not re-apply them. If your policy sets `style-src` or `style-src-attr`, allow `'unsafe-inline'` for style attributes.
