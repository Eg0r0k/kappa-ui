## Usage

```vue
<script setup lang="ts">
import { CalendarDate } from '@internationalized/date'
import type { DateValue } from 'reka-ui'
import { InputDate } from '@/components/ui/input-date'

const date = shallowRef<DateValue | undefined>(new CalendarDate(2025, 3, 14))
</script>

<template>
  <InputDate v-model="date" />
</template>
```

Day, month and year are separate segments, in the order the locale writes them. Type digits or use the arrow keys; once a segment is full, focus jumps to the next one. Paste an ISO date such as `2025-03-14` to fill them all at once.

`v-model` is a `CalendarDate` from `@internationalized/date`, or `undefined` until every segment is filled. `toString()` gives the ISO date, and `parseDate()` reads one back.

Set `name`, and it submits as `YYYY-MM-DD`. Give it an `aria-label`, or put it in a [Field](/docs/components/field).

## Examples

### Range

`InputDateRange` puts a start and an end date in one frame. Its `v-model` is `{ start, end }`. An end before the start marks both ends invalid.

With `name`, the form gets two fields, `name[start]` and `name[end]`, each an ISO date and empty until that end is filled. `required` needs both.

::component-preview{name="input-date-range"}
::

### Date and time

Pass a `CalendarDateTime` and set `granularity` to `hour`, `minute` or `second`, and the time segments follow the date in the same field. `hour-cycle` picks `24` or `12`; `12` adds the AM/PM segment.

::component-preview{name="input-date-date-time"}
::

### Min and max

A date before `min-value` or after `max-value` marks the segments `aria-invalid`, which turns the frame destructive. Put `invalid` on the field to show the error.

The model updates while the year is typed, so `2025` passes through `0002` and `0020` on the way. Check the date on submit, or after the field loses focus, not on every keystroke.

::component-preview{name="input-date-min-max"}
::

### Unavailable dates

`is-date-unavailable` rules out single dates: weekends, holidays, sold-out days. An unavailable date is invalid, the same as one outside min and max.

::component-preview{name="input-date-unavailable"}
::

### Locale

There is no `format` prop. The segment order and the separators come from `locale`, or from Reka UI's `ConfigProvider` when it's not set.

::component-preview{name="input-date-locale"}
::

### Variants

The five text control variants, the same as on [Input](/docs/components/input).

::component-preview{name="input-date-variants"}
::

### Sizes

The field runs from 28px at `xs` to 48px at `xl`, the heights of the matching inputs.

::component-preview{name="input-date-sizes"}
::

### Loading

`loading` puts a spinner at the end of the field and marks it `aria-busy`. Typing stays on.

::component-preview{name="input-date-loading"}
::

### In an input group

Inside an [InputGroup](/docs/components/input-group) the field drops its own frame and takes the group's variant and size, so icons, text and buttons share one frame with it. Clicking an addon focuses the first segment.

::component-preview{name="input-date-group"}
::

### States

`disabled` fades the frame and the segments; `readonly` keeps the date focusable but not editable.

::component-preview{name="input-date-states"}
::

### Form

Bind `v-model`, `name` and the `focus` and `blur` events rather than spreading a form library's whole field object: `placeholder` here is a date, not hint text, so a string placeholder from the library would break it. `focus` and `blur` fire once per field, not once per segment, so validate-on-blur works.

The field's element is a group, not an input. Register its first segment with the form library so it can focus the field after a failed submit.

A value set from outside the field, by a Today button or a calendar, fires neither event. If your form validates on blur only, validate on input too.

::component-preview{name="input-date-form"}
::

## Accessibility

The frame is a `group`, labelled and described by its field. Each segment is a `spinbutton` with its own value and range, and reads "Empty" until it's filled. The literals and the range's dash are skipped.

- The hidden form input takes the field's `id`, so clicking the label focuses the first segment.
- Clicking the frame outside the segments focuses the first one too.
- Invalid segments carry `aria-invalid`, and the frame turns destructive.
- A readonly field stays in the tab order; a disabled one leaves it.

::keyboard-table
---
rows:
  - keys: Tab / Shift + Tab
    description: Moves through the segments, each one a tab stop, then out of the field.
  - keys: 0–9
    description: Types into the segment and moves to the next one when it is full. Typing into a full segment starts it over.
  - keys: ArrowUp / ArrowDown
    description: Steps the segment by `step`, wrapping around.
  - keys: ArrowLeft / ArrowRight
    description: Moves focus to the previous or next segment. In right-to-left they swap.
  - keys: Backspace
    description: Deletes the last digit, then empties the segment, which makes the value `undefined`. Focus stays on the segment.
  - keys: A / P
    description: Sets AM or PM in the 12-hour cycle.
  - keys: Ctrl + V / ⌘ + V
    description: Pastes an ISO date, `2025-03-14` or `2025-03-14T09:30`. In a range, it fills the end that has focus; `2025-03-14/2025-03-21` fills both.
  - keys: Enter
    description: Submits the form through its submit button, like a native date input. Nothing happens while that button is disabled.
---
::

## Known limits

These come from [Reka UI's DateField](https://reka-ui.com/docs/components/date-field), which is still alpha upstream.

- Typing into the last segment never stops: a fifth year digit starts the year over ([reka-ui#2002](https://github.com/unovue/reka-ui/issues/2002)).
- Backspace in an empty segment doesn't move back to the previous one ([reka-ui#1758](https://github.com/unovue/reka-ui/issues/1758)).
- Copy and select-all are blocked in the segments; paste works ([reka-ui#1897](https://github.com/unovue/reka-ui/issues/1897)).
- A form reset, or clearing `v-model`, doesn't empty a half-typed field: the value was already `undefined`, so nothing changes ([reka-ui#1939](https://github.com/unovue/reka-ui/issues/1939)). Reset the field by remounting it with a new `key`.
- No month-and-year field, for card expiry dates and the like ([reka-ui#2099](https://github.com/unovue/reka-ui/issues/2099)).
- `InputDateRange` has no `step-snapping` ([reka-ui#2789](https://github.com/unovue/reka-ui/issues/2789)).
- The segments' screen reader labels ("day", "month", "year") are English only.
- With a non-Gregorian locale such as `fa-IR` or `th-TH`, `InputDate`'s hidden input writes that calendar's year, month and day. Convert to Gregorian with `toCalendar()` before you trust a submitted value, or send `v-model` instead ([nuxt/ui#6371](https://github.com/nuxt/ui/issues/6371)). `InputDateRange` always submits Gregorian dates.
- A `ZonedDateTime` shows a time zone segment that's a textbox, not a spinbutton, so it doesn't ring the frame when focused. Hide it with `hide-time-zone`.
- TypeScript errors about "separate declarations of a private property" on `CalendarDate` mean two copies of `@internationalized/date` are installed. Keep one, with `pnpm dedupe` or an override ([nuxt/ui#5965](https://github.com/nuxt/ui/issues/5965)).
