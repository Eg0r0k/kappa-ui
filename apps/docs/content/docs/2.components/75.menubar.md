## Usage

```vue
<script setup lang="ts">
import {
  Menubar,
  MenubarContent,
  MenubarItem,
  MenubarMenu,
  MenubarShortcut,
  MenubarTrigger,
} from '@/components/ui/menubar'
</script>

<template>
  <Menubar aria-label="Application">
    <MenubarMenu>
      <MenubarTrigger>File</MenubarTrigger>
      <MenubarContent>
        <MenubarItem @select="create">
          New
          <MenubarShortcut>⌘N</MenubarShortcut>
        </MenubarItem>
        <MenubarItem @select="open">Open…</MenubarItem>
      </MenubarContent>
    </MenubarMenu>
  </Menubar>
</template>
```

A menubar is a row of menus. Click a trigger to open its menu; once one is open, hovering another trigger switches to it, the way desktop menus work. Menus never open on hover alone.

The menus are the same as [Menu](/docs/components/menu)'s: same items, sizes, state layers and shortcuts.

- `MenubarMenu`: one menu, a `MenubarTrigger` plus a `MenubarContent`
- `MenubarItem`: an action; fires `select` and closes the whole bar
- `MenubarCheckboxItem`, `MenubarRadioGroup` + `MenubarRadioItem`: settings
- `MenubarSub`, `MenubarSubTrigger`, `MenubarSubContent`: submenus
- `MenubarLabel`, `MenubarGroup`, `MenubarSeparator`: structure
- `MenubarShortcut`: a key hint at the end, display only

Use the `Menubar*` parts only. A `MenuSubTrigger` inside a menubar opens its submenu and jumps to the next menu on the same keypress.

Give the bar an `aria-label`. It's a desktop pattern: on small screens, a [Menu](/docs/components/menu) or a [DrawerMenu](/docs/components/drawer-menu) is kinder to thumbs.

## Examples

### Sizes

`size` goes from `xs` to `xl` and sets the triggers and every menu in one go. Items match the height of an [Input](/docs/components/input) of the same size. A `MenubarContent` or `MenubarSubContent` with its own `size` wins.

::component-preview{name="menubar-sizes"}
::

### Variants

`outline` frames the bar, `soft` fills it with the muted surface, and `ghost` drops both, for a header that already has a frame of its own.

::component-preview{name="menubar-variants"}
::

### Icons and states

Icons pick up the item size. `inset` lines plain items and labels up with checkbox and radio items. A disabled trigger is skipped by the arrow keys and never opens.

::component-preview{name="menubar-icons"}
::

### Checkbox and radio items

Bind `MenubarCheckboxItem` and `MenubarRadioGroup` with `v-model`. A closed menu is unmounted, so keep the state in your component, not in the items.

::component-preview{name="menubar-checkbox-radio"}
::

### Open state

`v-model` on `Menubar` holds the `value` of the open menu, or `""` when none is. Set it to open a menu from code. The open trigger has `data-state="open"`, so style it with `data-[state=open]:`.

`value` doubles as the trigger's `id`, so pick something unique on the page, like `menubar-file`, or leave it out and let one be generated.

::component-preview{name="menubar-open-state"}
::

### Dialogs and focus

An item can open a [Dialog](/docs/components/dialog) or an [AlertDialog](/docs/components/alert-dialog) from `@select`. Bind the dialog's `open` yourself: the item is gone once the menu closes, so a trigger inside it would go with it. When the dialog closes, send focus back to the bar.

If an item moves focus elsewhere, like Find… here, focus stays there. To keep focus off the trigger in any other case, call `preventDefault()` in `@close-auto-focus` on `MenubarContent`. Reka UI ignores that on its own; the kappa component makes it work.

::component-preview{name="menubar-dialogs"}
::

### Icon triggers

Give an icon-only trigger a name with `aria-label`, or with `v-tooltip.label`, which shows it on hover too. Use the [directive](/docs/components/tooltip), not a `Tooltip` around the trigger: the component takes over the menu's anchor and the menu opens in the wrong place.

::component-preview{name="menubar-icon-triggers"}
::

### Right to left

With `dir="rtl"` on the bar, or from a `ConfigProvider`, the arrows run the other way, menus align to the trigger's right edge and submenu chevrons flip. Shortcuts stay left to right.

::component-preview{name="menubar-rtl"}
::

### With a toolbar

A menubar holds menus and nothing else. For buttons and toggles at bar level, like Bold or Italic, use a [Toolbar](/docs/components/toolbar), and put a [Menu](/docs/components/menu) in one of its buttons when you need a dropdown there.

::component-preview{name="menubar-app-shell"}
::

## Accessibility

The bar is one tab stop. Inside it, the arrow keys move between triggers and wrap around by default. Each trigger is a `role="menuitem"` with `aria-haspopup="menu"` and `aria-expanded`, and points at its menu with `aria-controls` while it's open. The menu is named by its trigger.

Menus are never modal: the page stays live, nothing is hidden from screen readers, and Tab leaves an open menu. Reka's menus would send Tab from the end of the page, since they're portaled there; the kappa parts send it on from the bar, so it reaches the control right after it, or before it with Shift + Tab.

::keyboard-table
---
rows:
  - keys: Tab / Shift + Tab
    description: Moves into the bar, onto the last used trigger, and out again. From an open menu, closes it and moves on from the bar.
  - keys: ArrowRight / ArrowLeft
    description: On a trigger, moves to the next or previous one. In a menu, opens the next or previous menu, or opens a submenu from its trigger. Reversed in right to left.
  - keys: Home / End
    description: Moves to the first or last trigger, or the first or last item.
  - keys: Enter / Space
    description: Opens the trigger's menu and focuses its first item. On an item, chooses it.
  - keys: ArrowDown
    description: Opens the trigger's menu and focuses its first item. In a menu, moves to the next item.
  - keys: ArrowUp
    description: Moves to the previous item. Does nothing on a closed trigger.
  - keys: Escape
    description: Closes the menu, or just the submenu, and focuses its trigger.
  - keys: A–Z
    description: Moves to the next item starting with that letter.
---
::

## Known limits

- No actions or toggles at bar level: every trigger opens a menu ([reka-ui#2048](https://github.com/unovue/reka-ui/issues/2048)). Use a [Toolbar](#with-a-toolbar).
- Horizontal only. Reka fixes the bar's orientation.
- A closed menu is unmounted, along with anything inside it ([reka-ui#2057](https://github.com/unovue/reka-ui/issues/2057)). Keep item state in your component, and use links, not a menubar, for navigation that search engines should see.
- A `Tooltip` component around a trigger breaks the menu's position ([reka-ui#2993](https://github.com/unovue/reka-ui/issues/2993)). Use `v-tooltip`.
- Cancelling a trigger's `pointerdown` or `keydown` to stop the menu from opening needs `reka-ui` 2.11 or later ([reka-ui#2984](https://github.com/unovue/reka-ui/pull/2984)).
- Opening from `default-value` sets an empty `aria-controls` on the trigger until it renders again.
- In a `v-for` menu, give items stable keys and don't build new prop objects on every render. Re-rendering items under the pointer can swallow a click in Chrome ([reka-ui#2783](https://github.com/unovue/reka-ui/issues/2783)).
- The item highlight and focus ring follow the theme's state layer and ring tokens, which may fall below 3:1 against the menu on the default theme ([nuxt/ui#6588](https://github.com/nuxt/ui/issues/6588)).
