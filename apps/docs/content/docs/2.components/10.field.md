## Usage

```vue
<script setup lang="ts">
import { Field, FieldDescription, FieldError, FieldLabel } from '@/ui/field'
import { Input } from '@/ui/input'
</script>

<template>
  <Field :invalid="!!error" required>
    <FieldLabel>Email</FieldLabel>
    <Input v-model="email" type="email" />
    <FieldDescription>Receipts go here.</FieldDescription>
    <FieldError :errors="error" />
  </Field>
</template>
```

`Field` gives its control an `id` and shares it with the parts around it, so none of the wiring is written by hand:

- `FieldLabel` points its `for` at the control.
- The control's `aria-describedby` lists the description and the error, but only while they are rendered, so a screen reader reads the help text and the current error when the control takes focus.
- `invalid`, `disabled` and `required` reach the control as `aria-invalid`, `disabled` and `required`, and restyle the label. A required field gets an asterisk that screen readers skip, since the control already announces itself as required.

Any of it can be overridden: an attribute set directly on the control wins over the one the field provides. To choose the `id`, set it on `Field` so the label follows.

## Validation

Field does not validate. Whatever decides that a value is wrong, be it a form library, a schema or a few lines of your own, passes the result to `invalid` and the message to `FieldError`:

::component-preview{name="field-validation"}
::

`FieldError` takes a single message or a list of strings or `{ message }` objects, the shapes form libraries report, drops duplicates and renders nothing when there are none. A list of several becomes a bulleted list.

The error is not a live region. When a form is submitted with five mistakes, five announcements at once help nobody; instead, move focus to the first invalid control, and its error is read as part of its description.

### Errors for a group

Some errors belong to a group rather than one control: no radio selected, fewer checkboxes ticked than needed. `FieldSet` takes the same `invalid`, `disabled` and `required` as `Field` and wires them to the [radio group](/docs/components/radio-group) or [checkbox group](/docs/components/checkbox) inside it, with its own `FieldDescription` and `FieldError`. Fields inside the set still describe their own controls.

## Examples

### Horizontal

`orientation="horizontal"` puts the label beside the control, for settings pages and for [checkboxes](/docs/components/checkbox), where a `FieldContent` stacks the label over its description and the control lines up with the label's first line. `responsive` stacks them until the surrounding `FieldGroup` is at least 28rem wide.
