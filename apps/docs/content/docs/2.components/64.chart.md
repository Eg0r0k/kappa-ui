Click a legend item to hide its series. The tooltip follows the pointer and a finger alike.

Chart is [Unovis](https://unovis.dev) plus five parts. You compose the Unovis components yourself, `VisXYContainer`, `VisArea`, `VisAxis`, `VisDonut` and the rest, and the parts give them the theme's colours, a tooltip and a legend. The galleries show every kind: [Area](/docs/charts/area), [Bar](/docs/charts/bar), [Line](/docs/charts/line), [Pie](/docs/charts/pie), [Radar](/docs/charts/radar), [Radial](/docs/charts/radial) and [Tooltip](/docs/charts/tooltip).

The item installs `@unovis/vue` and `@unovis/ts`.

## Your first chart

Start from the data and a config. The config names each series, gives it a label and a colour, and the container writes every colour as `--color-<key>`:

```vue
<script setup lang="ts">
import { VisArea, VisAxis, VisXYContainer } from "@unovis/vue";

import { type ChartConfig, ChartContainer, ChartCrosshair, ChartLegend, ChartTooltip, ChartTooltipContent, chartColors } from "@/components/ui/chart";

type Month = { month: Date; desktop: number; mobile: number };

const data: Month[] = [
  { month: new Date(2024, 0, 1), desktop: 186, mobile: 80 },
  { month: new Date(2024, 1, 1), desktop: 305, mobile: 200 },
  { month: new Date(2024, 2, 1), desktop: 237, mobile: 120 },
];

const config = {
  desktop: { label: "Desktop", color: "var(--chart-1)" },
  mobile: { label: "Mobile", color: "var(--chart-2)" },
} satisfies ChartConfig;

const keys = ["desktop", "mobile"];
const x = (d: Month) => d.month;
const y = [(d: Month) => d.desktop, (d: Month) => d.mobile];
const color = chartColors(keys);
</script>

<template>
  <ChartContainer :config="config" class="aspect-auto h-64 w-full">
    <VisXYContainer :data="data">
      <VisArea :x="x" :y="y" :color="color" />
      <VisAxis type="x" :x="x" />
      <ChartCrosshair :x="x" :y="y" :color="color" />
    </VisXYContainer>
    <ChartTooltip>
      <ChartTooltipContent />
    </ChartTooltip>
    <ChartLegend />
  </ChartContainer>
</template>
```

The container takes its width from its parent, never from what it draws, and is 16:9 by default. A chart with a fixed height takes `aspect-auto` as well, or the ratio turns that height into a minimum width.

Four rules keep a chart fast:

- Accessors, formatters and `svgDefs` are constants in `<script setup>`. Unovis compares functions by identity, so an arrow written in the template is new on every render and redraws the whole chart with its 600ms transition.
- Replace the data array; a mutation in place is not seen.
- Dates are built with `new Date(year, month, day)`. A `"YYYY-MM-DD"` string parses as UTC and lands a day early in western time zones.
- Many charts on one page take `lazy` on the container: the slot mounts when it scrolls near.

## Config

```ts
type ChartConfig = Record<string, {
  label?: string | Component;
  icon?: Component;
  color?: string;
  theme?: { light: string; dark: string };
}>;
```

`color` is any CSS colour; the theme tokens `var(--chart-1)` to `var(--chart-5)` switch with the mode. A `theme` pair becomes `light-dark(light, dark)`. A key must be a valid CSS identifier, so `desktop`, not `desktop.total`: the container warns in development.

`chartColors(keys)` returns an Unovis colour accessor that reads `--color-<key>` by series index, for the `y` arrays of areas, lines and bars. A single series writes the variable directly: `:color="'var(--color-desktop)'"`.

## Theming

The five series tokens live in the theme item, light and dark separately, in a fixed order that keeps every neighbouring pair apart under colour-vision deficiency. `fill-chart-1` to `fill-chart-5` and the `bg-` and `stroke-` forms exist as classes.

Unovis' own variables (`--vis-axis-*`, `--vis-crosshair-*`, `--vis-donut-*`, `--vis-radial-bar-*`) are mapped onto the tokens on the chart root: ticks in `--muted-foreground`, grid and domain lines in `--border`, donut and radial backgrounds in `--muted`, segments separated by a 2px `--background` stroke. Override one with a class on the container, `[--vis-donut-segment-stroke-width:0]`.

## Tooltip

`ChartCrosshair` listens to the pointer and reports the hovered point; `ChartTooltip` positions its content beside the pointer, inside the chart, and flips at the right edge. `ChartTooltipContent` lists the config keys found in the datum, in config order, with a zero shown as `0`. Its props and slots are on the [Tooltip gallery](/docs/charts/tooltip).

A chart without a crosshair, a pie or a radial, feeds the tooltip from Unovis events:

```vue
<script setup lang="ts">
import { Donut } from "@unovis/ts";

import { useChart } from "@/components/ui/chart";

const { events } = useChart();
const segmentEvents = events(Donut.selectors.segment);
</script>

<template>
  <VisDonut :value="value" :color="color" :events="segmentEvents" />
</template>
```

`useChart()` works in a component rendered inside `ChartContainer`. Unovis binds events up to half a second after a render, so the first hover right after mount can be missed.

## Legend

`ChartLegend` lists the config. With `toggle` every item is a button that hides its series; the keys arrive through `v-model:hidden` on the container, and `useChartSeries(keys)` turns them into `y` accessors that return `null` for a hidden series, so the remaining series keep their index and colour. Areas, lines and stacked bars draw nothing for it; grouped bars keep its slot empty, and want `:bar-min-height="0"` so no 2px stub remains:

```vue
<script setup lang="ts">
import { useChartSeries } from "@/components/ui/chart";

const hidden = ref<string[]>([]);
const series = useChartSeries<Month>(["desktop", "mobile"], hidden);
</script>

<template>
  <ChartContainer :config="config" v-model:hidden="hidden">
    <VisXYContainer :data="data">
      <VisArea :x="x" :y="series.y.value" :color="series.color" />
    </VisXYContainer>
  </ChartContainer>
</template>
```

Without the second argument the hook reads the hidden keys from the chart context, so it must run in a component rendered inside `ChartContainer`.

## Accessibility

The SVG is hidden from assistive technology by Unovis. Give the container a `label` that says what the chart shows, and put the numbers beside it as a table, visually hidden if the design has no room, so the data is reachable without a pointer.

::api-reference{parts="ChartContainer,ChartCrosshair,ChartTooltip,ChartTooltipContent,ChartLegend"}

### Data attributes

::data-slots
---
rows:
  - slot: chart
    attributes: data-chart, role, aria-label
    description: The root; `data-chart` is the chart id, `role="group"` with `aria-label` when `label` is set.
  - slot: chart-crosshair
    description: Unovis' placeholder for the crosshair.
  - slot: chart-tooltip
    attributes: data-state
    description: "The positioned box; `data-state` is `open` while a point is hovered."
  - slot: chart-tooltip-content
    description: The default content.
  - slot: chart-tooltip-item
    description: One row of the content.
  - slot: chart-tooltip-indicator
    description: The colour mark of a row.
  - slot: chart-legend
    description: The legend.
  - slot: chart-legend-item
    attributes: data-state, aria-pressed
    description: "One series; `data-state` is `visible` or `hidden`, and with `toggle` the item is a button with `aria-pressed`."
  - slot: chart-legend-swatch
    description: The colour square.
---
::

### CSS variables

::css-vars
---
rows:
  - name: --chart-1 … --chart-5
    default: theme
    description: The series colours, per mode.
  - name: --color-<key>
    default: from the config
    description: Set on the chart root for every config key with a colour.
  - name: --vis-*
    default: mapped to the tokens
    description: Unovis' variables, set on the chart root; override on the container.
---
::
