## Usage

```vue
<script setup lang="ts">
import {
  AlertDialog,
  AlertDialogAction,
  AlertDialogCancel,
  AlertDialogContent,
  AlertDialogDescription,
  AlertDialogFooter,
  AlertDialogHeader,
  AlertDialogTitle,
  AlertDialogTrigger,
} from '@/components/ui/alert-dialog'
import { Button } from '@/components/ui/button'
</script>

<template>
  <AlertDialog>
    <AlertDialogTrigger as-child>
      <Button variant="outline" color="neutral">Show dialog</Button>
    </AlertDialogTrigger>
    <AlertDialogContent>
      <AlertDialogHeader>
        <AlertDialogTitle>Are you absolutely sure?</AlertDialogTitle>
        <AlertDialogDescription>This cannot be undone.</AlertDialogDescription>
      </AlertDialogHeader>
      <AlertDialogFooter>
        <AlertDialogCancel>Cancel</AlertDialogCancel>
        <AlertDialogAction>Continue</AlertDialogAction>
      </AlertDialogFooter>
    </AlertDialogContent>
  </AlertDialog>
</template>
```

An alert dialog is a [Dialog](/docs/components/dialog) that asks for an answer. It has the role `alertdialog`, a press outside does not close it, and focus opens on `AlertDialogCancel`, so Enter on a destructive question backs out rather than going ahead. Escape still closes it. `AlertDialogAction` and `AlertDialogCancel` are [Buttons](/docs/components/button) that close the dialog, and take the button's `variant`, `color` and `size`.

It shares Dialog's window and overlay, so alert dialogs and dialogs stacked on each other dim the page once.

## From code

`useConfirm()` opens alert dialogs from code — an event handler, a store, a router guard — and waits for the answer. It is its own item, built on this one and on the [dialog service](/docs/components/dialog#from-code), which must be set up once with `createDialogs()` and a `DialogHost`.

::install-tabs{name="confirm"}
::

### Confirm

`confirm()` returns a promise of the same result as `openDialog`: `{ ok: true }` when the action was pressed, or `{ ok: false, reason }`, where the reason is `close-button` for Cancel and `escape` for Escape.

```ts
import { useConfirm } from '@/components/ui/confirm'

const { confirm } = useConfirm()

const discard = async () => {
  const result = await confirm({
    title: 'Discard the draft?',
    description: 'Your unsaved changes will be lost.',
    action: 'Discard',
    color: 'destructive',
  })
  if (result.ok) draft.value = ''
}
```

### Waiting for work

`onConfirm` runs when the action is pressed, before the dialog closes. While its promise is pending, the action shows a spinner, both buttons are disabled and Escape is ignored. If it throws, the dialog stays open so the user can try again, and the error goes on to the app's `errorHandler`.

::component-preview{name="confirm-async"}
::

### Alert

`alert()` shows a message with one button, which takes focus. It resolves `{ ok: true }` when pressed and `{ ok: false, reason: 'escape' }` on Escape.

::component-preview{name="confirm-alert"}
::

### Prompt

`prompt()` asks for a line of text and resolves `{ ok: true, value }`. `validate` returns an error message to keep the dialog open, or nothing to accept the value; it may return a promise. Enter submits, except an Enter that ends an input method's composition. Without a `label`, the title labels the input.

::component-preview{name="confirm-prompt"}
::

The handle each call returns is the one from `openDialog`, so `dismiss()` closes the dialog from code and `isOpen` tells whether it is still showing. `ConfirmDialog` and `PromptDialog`, the components behind the three calls, can also be opened with `openDialog` or `defineDialog` directly.

## Accessibility

The dialog is named by its `AlertDialogTitle` and described by its `AlertDialogDescription`, which screen readers announce together when it opens. Always give it a title. Focus stays inside the window until it closes, then returns to the element that opened it.

::keyboard-table
---
rows:
  - keys: Tab / Shift + Tab
    description: Moves between the answers, wrapping around inside the window.
  - keys: Enter / Space
    description: Presses the focused answer. Cancel has focus when the dialog opens.
  - keys: Escape
    description: Closes the dialog as Cancel does. While `onConfirm` runs, or an input method is composing text, it does nothing.
---
::
