## Usage

```vue
<script setup lang="ts">
import {
  AlertDialog,
  AlertDialogAction,
  AlertDialogCancel,
  AlertDialogContent,
  AlertDialogDescription,
  AlertDialogFooter,
  AlertDialogHeader,
  AlertDialogTitle,
  AlertDialogTrigger,
} from '@/components/ui/alert-dialog'
import { Button } from '@/components/ui/button'
</script>

<template>
  <AlertDialog>
    <AlertDialogTrigger as-child>
      <Button variant="outline" color="neutral">Show dialog</Button>
    </AlertDialogTrigger>
    <AlertDialogContent>
      <AlertDialogHeader>
        <AlertDialogTitle>Are you absolutely sure?</AlertDialogTitle>
        <AlertDialogDescription>This cannot be undone.</AlertDialogDescription>
      </AlertDialogHeader>
      <AlertDialogFooter>
        <AlertDialogCancel>Cancel</AlertDialogCancel>
        <AlertDialogAction>Continue</AlertDialogAction>
      </AlertDialogFooter>
    </AlertDialogContent>
  </AlertDialog>
</template>
```

A [Dialog](/docs/components/dialog) that wants an answer. A click outside won't close it: only Escape or a button will.

Focus starts on Cancel, so a reflex Enter backs out instead of deleting everything.
`AlertDialogAction` and `AlertDialogCancel` are regular [Buttons](/docs/components/button) that close the dialog.

## From code

Like `window.confirm()`, but it doesn't look like it's from 1999. `useConfirm()` opens alert dialogs from code and waits for the answer. Set up the [dialog service](/docs/components/dialog#from-code) first.

::install-tabs{name="confirm"}
::

### Confirm

`confirm()` returns the same result as `openDialog`: `ok` is `true` when the action is pressed, `false` on Cancel or Escape.

```ts
import { useConfirm } from '@/components/ui/confirm'

const { confirm } = useConfirm()

const discard = async () => {
  const result = await confirm({
    title: 'Discard the draft?',
    description: 'Your unsaved changes will be lost.',
    action: 'Discard',
    color: 'destructive',
  })
  if (result.ok) draft.value = ''
}
```

### Waiting for work

Pass `onConfirm`, and it runs before the dialog closes. Until it finishes, the action shows a spinner and nothing can close the dialog. If it throws, the dialog stays open for another try.

::component-preview{name="confirm-async"}
::

### Prompt

`prompt()` asks for a line of text and gives it back as `value`. To reject the input, return an error message from `validate`, and the dialog stays open. It can be async.

::component-preview{name="confirm-prompt"}
::

Each call returns the same handle as `openDialog`, so `dismiss()` and `isOpen` work too. Need more control? Open `ConfirmDialog` or `PromptDialog` with `openDialog` or `defineDialog` yourself.

## Accessibility

The dialog is named by its `AlertDialogTitle` and described by its `AlertDialogDescription`, which screen readers announce together when it opens. Always give it a title. Focus stays inside the window until it closes, then returns to the element that opened it.

::keyboard-table
---
rows:
  - keys: Tab / Shift + Tab
    description: Moves between the answers, wrapping around inside the window.
  - keys: Enter / Space
    description: Presses the focused answer. Cancel has focus when the dialog opens.
  - keys: Escape
    description: Closes the dialog as Cancel does. While `onConfirm` runs, or an input method is composing text, it does nothing.
---
::
