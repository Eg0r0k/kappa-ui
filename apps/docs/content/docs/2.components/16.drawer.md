## Usage

```vue
<script setup lang="ts">
import { Button } from '@/components/ui/button'
import {
  Drawer,
  DrawerBody,
  DrawerClose,
  DrawerContent,
  DrawerDescription,
  DrawerFooter,
  DrawerHeader,
  DrawerTitle,
  DrawerTrigger,
} from '@/components/ui/drawer'
</script>

<template>
  <Drawer>
    <DrawerTrigger as-child>
      <Button>Edit profile</Button>
    </DrawerTrigger>
    <DrawerContent>
      <DrawerHeader>
        <DrawerTitle>Edit profile</DrawerTitle>
        <DrawerDescription>Changes are saved when you press Save.</DrawerDescription>
      </DrawerHeader>
      <DrawerBody>
        <!-- the content -->
      </DrawerBody>
      <DrawerFooter>
        <DrawerClose as-child>
          <Button>Save</Button>
        </DrawerClose>
      </DrawerFooter>
    </DrawerContent>
  </Drawer>
</template>
```

`Drawer` holds the state, `DrawerTrigger` opens it, and `DrawerContent` is the panel: it renders the overlay, pins the panel to the edge named by `side` (`bottom` by default) and puts a drag handle on it. `DrawerHeader`, `DrawerBody` and `DrawerFooter` lay out the three parts; the body scrolls when the content is taller than the screen. `DrawerClose` around any button closes the drawer, and `v-model:open` opens it from code.

Underneath is [Dialog](/docs/components/dialog): Reka UI's dialog with kappa-ui's parts, so focus, Escape, the overlay and the title fallback are the dialog's. The drawer adds the gesture. A touch anywhere on the panel drags it towards its edge; past half of its size, or on a quick flick, it closes, otherwise it springs back. Dragging from a scrolled body scrolls the body; from the top of the body it moves the drawer. A mouse drags the same way; a sideways movement over text still selects it, and a press on selected text never starts a drag.

## Gesture

A drag starts only where it makes sense. Elements under `data-no-drag` never start one, nor does a drag while text is selected. `handle-only` on `Drawer` keeps every touch for the content and leaves dragging to `DrawerHandle`. `modal: false` keeps the page live without an overlay and leaves the gesture on.

::callout
A tap on the handle closes the drawer, or with snap points moves it to the next point. Put `data-no-drag` on an element, such as a map or a slider, to keep every drag inside it for itself.
::

## Snap points

`snap-points` lists the sizes a panel can rest at, in ascending order: a number from 0 to 1 is a share of the viewport along the panel's axis, a larger number or a `"320px"` string is pixels. The panel keeps the size its `class` gives it (`h-[95dvh]` below) and the drawer hides the rest below the edge, so make that size at least the largest point. It opens at the first point, or at `v-model:active-snap-point`, reports every change including the ones a drag makes, and returns to the first point after a close.

A release looks at how fast the finger was moving. A quick swipe (over 0.4 px/ms) moves one point in its direction; a fling (over 2 px/ms) goes to the last point or, towards the edge, closes; anything slower settles on the nearest point. Below the smallest point it closes past half of that point's size or on a quick swipe, and a drawer with `dismissible: false` returns to the smallest point instead. `snap-to-sequential-points` keeps every release to one step. A tap on the handle moves to the next point and wraps from the last to the first.

`DrawerBody` scrolls only at the largest point; anywhere lower, every move drags the panel, as in a map sheet. The overlay is fully visible from the point at `fade-from-index` upwards (the last point by default), fades out towards the point below it and is gone at any lower point, so the page stays readable under a small sheet.

## Scaled page

Wrap the app in `DrawerIndent` and the page steps back while a drawer is open: it shrinks a little, rounds its corners and moves off the far edge of the screen, showing the wrapper's colour around it (`bg-black`, changed through `class`). It follows a swipe, so dragging the drawer away brings the page back under the finger. Drawers render through a portal outside the wrapper, so they never scale with the page.

```vue
<!-- App.vue -->
<template>
  <DrawerIndent>
    <RouterView />
  </DrawerIndent>
</template>
```

The page is clipped with `clip-path`, never `overflow: hidden`, so `position: sticky` keeps working inside it, and it scales the part that is on screen, wherever the page is scrolled. While it is scaled, a `position: fixed` element inside it is placed against the page instead of the screen, as under any transform, so render fixed overlays through a portal, as kappa-ui's overlays do. A drawer follows the nearest `DrawerIndent` around it: this site wraps every page in one, and the example below has its own, so only the mock page steps back.

::component-preview{name="drawer-indent"}
::

## Nested drawers

A drawer opened while another one is open stacks on top: the one below shrinks and moves back by a step, and every drawer further down by one more. Swiping the top drawer away brings the stack forward under the finger. Each drawer keeps its own focus, Escape and overlay.

## From code

A drawer opens from code the way a [dialog](/docs/components/dialog#from-code) does, with the same service: `createDialogs()` installed once and one `DialogHost` in the root component. Put the `DialogHost` inside `DrawerIndent`, so drawers opened from code step the page back too.

The component renders `DrawerContent` and closes with `useDialogContext()`, both from the drawer:

```vue
<!-- ShareDrawer.vue -->
<script setup lang="ts">
import { Button } from '@/components/ui/button'
import { DrawerContent, DrawerHeader, DrawerTitle, useDialogContext } from '@/components/ui/drawer'

const { close } = useDialogContext<string>()
</script>

<template>
  <DrawerContent>
    <DrawerHeader>
      <DrawerTitle>Share</DrawerTitle>
    </DrawerHeader>
    <Button @click="close('Mail')">Mail</Button>
  </DrawerContent>
</template>
```

`openDrawer(component, props, options)` opens it and returns the same promise and handle as `openDialog`. `defineDrawer(component, { props, keepMounted, ...options })` defines it once, as `defineDialog` does. The options are `Drawer`'s props: `side`, `dismissible`, `handle-only`, `modal` and the snap point props; the active snap point moves on its own. A swipe that closes the drawer resolves with the reason `swipe`, and while `loading` is `true` a swipe springs back instead of closing.

## Accessibility

The drawer's name comes from its `DrawerTitle` and its description from its `DrawerDescription`; always give it a title. When either is missing, the panel renders an empty hidden one, so Reka UI does not warn. The handle is `aria-hidden`: keyboard users close the drawer with Escape or a button.

::keyboard-table
---
rows:
  - keys: Tab / Shift + Tab
    description: Moves to the next or previous control in the panel, wrapping around inside it.
  - keys: Escape
    description: Closes the drawer and returns focus to the element that opened it.
---
::

## Motion

The panel slides in over `--transition-duration-medium-4` with `--ease-emphasized-decelerate` and out over `--transition-duration-short-4` with `--ease-emphasized-accelerate`. While a finger moves it, `data-swiping` turns transitions off and the panel follows exactly; on release it returns over `--transition-duration-medium-2` with `--ease-standard`, or closes from where it was. Under `prefers-reduced-motion` the panel appears and disappears at once, and still follows a drag. The mechanism is the `drawer-slide`, `drawer-overlay-fade` and `drawer-indent` utilities from `@kappa-ui/core/tailwind.css`, driven by the variables below; `drawer-indent` scales the page, and `drawer-slide` also steps a drawer back while others are open above it, both over `--transition-duration-medium-2` with `--ease-standard`. The variables that change every frame, `--drawer-swipe-movement`, `--drawer-swipe-progress`, `--drawer-nested-progress` and `--drawer-indent-progress`, are registered with `inherits: false`, so a frame restyles one element rather than its subtree: read them in a class on the element that carries them, not in its children.

::css-vars
---
rows:
  - name: --drawer-size
    default: measured
    description: The panel's size along its axis, in px.
  - name: --drawer-swipe-movement
    default: 0px
    description: On the panel, how far a drag has moved it towards its edge.
  - name: --drawer-swipe-progress
    default: "0"
    description: On the panel and the overlay, movement divided by size, from 0 to 1. The overlay fades with it; with snap points it stays 0 on the overlay.
  - name: --drawer-snap-offset
    default: 0px
    description: What the active snap point hides below the edge; added to the swipe movement.
  - name: --drawer-overlay-opacity
    default: "1"
    description: On the overlay, the opacity from `fade-from-index`, 0 to 1; multiplied with the swipe fade.
  - name: --drawer-keyboard-inset
    default: 0px
    description: What the visual viewport lost to the keyboard; a bottom drawer lifts by it.
  - name: --drawer-nested
    default: "0"
    description: On a drawer, the number of drawers open above it.
  - name: --drawer-nested-progress
    default: "0"
    description: On a drawer, how far it has stepped back; each drawer above adds up to 1, less while it is swiped away.
  - name: --drawer-indent-progress
    default: "0"
    description: On the page in DrawerIndent, how far it has stepped back, from 0 to 1; follows the first open drawer.
  - name: --drawer-indent-top
    default: 0px
    description: On the page, how much of it is above the screen when the indent starts; the scale and clip use the part on screen.
  - name: --drawer-indent-bottom
    default: 0px
    description: On the page, how much of it is below the screen when the indent starts.
---
::
