## Usage

```vue
<script setup lang="ts">
import { Field, FieldLabel } from '@/components/ui/field'
import { Rating } from '@/components/ui/rating'

const stars = ref(0)
</script>

<template>
  <Field>
    <FieldLabel>Rate your stay</FieldLabel>
    <Rating v-model="stars" />
  </Field>
</template>
```

`v-model` is a number, `0` while nothing is picked. A rating never writes it on its own, so an untouched form stays untouched.

Under the stars is a radio group: one radio per step, each named "3 out of 5", and a single tab stop. Put it in a [Field](/docs/components/field), or give it an `aria-label`.

## Examples

### Half steps

`step` splits each star: `0.5` for halves, `0.25` for quarters, `0.1` for tenths. Click the start of a star for its first half, the end for the whole star. `hoverable` previews the value under a mouse; a finger never previews, because a tap would leave the preview behind.

::component-preview{name="rating-half"}
::

### Readonly

For showing a score, not asking for one. `readonly` draws the exact value, 4.3 fills the fifth star to 30% whatever the `step`, and screen readers hear one picture, "Rated 4.3 out of 5", instead of five dimmed radios. In a field it reads the label first.

It has no radios and no listeners, so use it for review lists and product grids.

::component-preview{name="rating-readonly"}
::

### Colours

`color` fills the stars in Button's colours or [your own](/docs/getting-started/theming#your-own-tone), `primary` by default. For gold stars, use `warning`: the fill is the bright tone and the edge its [text shade](/docs/getting-started/theming#tones), which keeps the star's outline at 3:1 against the page where amber alone doesn't. Empty stars keep the `--input` outline in every colour.

::component-preview{name="rating-colors"}
::

### Sizes

`size` runs from `xs` to `xl` on the [control tokens](/docs/getting-started/sizing), so a rating lines up with a Button or Input of the same size. Each star's box is the control height, 28px to 48px, and the star is two thirds of it: 18, 22, 24, 26 and 32px. The space between stars is half the control gap.

::component-preview{name="rating-sizes"}
::

### Clearable

With `clearable`, picking the current value again clears it to `0`. On a keyboard, that's Space on the checked star.

::component-preview{name="rating-clearable"}
::

### Hover label

`hover` fires with the value under the pointer, and `0` once it leaves, so you can put a word next to the stars. Give `labels.item` the same words, and screen readers hear them too.

::component-preview{name="rating-hover-label"}
::

### Icons

The `icon` slot replaces the star. It renders once for the empty layer and once per step for the filled one, with `filled` telling them apart; an `svg` in the filled layer is filled with the colour. For a different empty icon, add `empty-icon`.

Stars are clipped from the start for half steps, so pick a symmetric icon.

::component-preview{name="rating-icons"}
::

### States

A disabled rating turns grey, filled and empty alike, and leaves the tab order. A disabled Field or FieldSet disables it too. An invalid one turns `destructive`, outlines included, whatever its `color`.

::component-preview{name="rating-states"}
::

### Form

With Formisch, bind `field.input` and let the schema say a rating is required: `v.minValue(0.5)` rejects both an untouched and a cleared rating.

::component-preview{name="rating-form"}
::

In a plain `<form>`, give it a `name`. Nothing picked submits an empty value, so native `required` stops the form until a star is picked.

```vue
<template>
  <form action="/reviews" method="post">
    <Rating name="rating" required aria-label="Rating" />
    <Button type="submit">Send</Button>
  </form>
</template>
```

### Right to left

In a right-to-left layout, the stars fill from the right, the first half of a star is its right half, and Left and Right swap. Set `dir`, or wrap the app in Reka's `ConfigProvider`.

::component-preview{name="rating-direction"}
::

### Vertical

`orientation="vertical"` stacks the stars from top to bottom. The arrow keys become Up and Down.

::component-preview{name="rating-vertical"}
::

### Touch target

Each star is as wide as the space it takes in the row: 21px at `xs`, 28px at `md`, and a half step is half of that. `touch-target` grows each star to 48px across the row, `expand` when it stands alone, `wrapper` when it sits close to others. It can't grow them along the row, where the stars already touch, so neighbours never overlap and half steps still split in the middle. Where fingers matter, also pick `sm` or larger, which keeps whole stars at least 24px wide, the minimum [WCAG asks for](/docs/getting-started/accessibility#touch-targets).

::component-preview{name="rating-touch-target"}
::

## Known limits

- Reka's Rating is [in alpha](https://github.com/unovue/reka-ui/issues/1966). Its keyboard table lists Up and Down for a horizontal rating, but they only work when vertical; the table below is what it does.
- With `step` below 1, every step is a radio with its own window listeners: `0.1` means 50 radios and about 200 listeners per rating. Use `readonly` in lists.
- A value off the step, like 3.7 with `step` 0.5, shows as 3.5 and checks no radio. Round it, or show it `readonly`.
- On reka-ui before 2.11, a server-rendered rating with `step` below 1 logs a hydration warning ([reka-ui#2964](https://github.com/unovue/reka-ui/issues/2964)). It looks right anyway, because every colour is opaque; 2.11 drops the warning.
- Filled steps carry Reka's `data-state="active"`, which [reka-ui v3 renames](https://github.com/unovue/reka-ui/issues/2823). Style through the `icon` and `empty-icon` slots and `color` rather than `data-state`.
- Clicking the field label doesn't focus the rating, as with [Slider](/docs/components/slider). The label still names it.

### Data attributes

::data-slots
---
rows:
  - slot: rating
    attributes: data-size, data-color, data-orientation, data-touch-target, data-disabled, data-readonly
    description: The root, `role="radiogroup"`, or `role="img"` when readonly. `data-size` and `data-color` are set even when left at their defaults.
  - slot: rating-item
    attributes: data-hovered, data-disabled
    description: One star's box. Draws the hover circle, and holds its own stacking context so the steps' z-index stays inside.
  - slot: rating-empty-icon
    description: The empty star behind the steps. Draws the focus ring.
  - slot: rating-indicator
    attributes: aria-checked, data-disabled
    description: One step, a `role="radio"` button over the start of the star. `aria-checked` is on the picked step only.
  - slot: rating-icon
    description: The filled star inside a step, clipped to the step's share of the box.
---
::

## Accessibility

::keyboard-table
---
rows:
  - keys: Tab
    description: Moves focus to the checked step, or the first one when nothing is picked, without picking it.
  - keys: ArrowRight / ArrowLeft
    description: Moves one step and picks it, stopping at the ends. Only when horizontal; in `rtl` the two swap.
  - keys: ArrowDown / ArrowUp
    description: Moves one step and picks it. Only when vertical.
  - keys: Home / End
    description: Moves focus to the first or last step without picking it.
  - keys: PageUp / PageDown
    description: Same as Home and End.
  - keys: Space
    description: Picks the focused step. On the checked step with `clearable`, clears the rating.
  - keys: Enter
    description: Does nothing, so it never submits the form by accident.
---
::

The rating is a radio group, a pattern screen readers already know, and each step is a radio named after its value. Invalid, required and the field's description and error go on the group, not on each star; the stars themselves are hidden from screen readers.

From nothing picked, Right Arrow picks the second star, as in any radio group. Press Space for the first.
