## Installation

::install-tabs{name="tooltip"}
::

Tooltips under one `TooltipProvider` share their settings and warm up together: once one has opened, the next opens at once while the pointer moves along a toolbar. Put one around the app:

```vue
<script setup lang="ts">
import { TooltipProvider } from '@/components/ui/tooltip'
</script>

<template>
  <TooltipProvider>
    <RouterView />
  </TooltipProvider>
</template>
```

A tooltip outside any provider still works, on the default settings and with no shared warm-up.

## Usage

```vue
<script setup lang="ts">
import { Button } from '@/components/ui/button'
import { Tooltip, TooltipContent, TooltipTrigger } from '@/components/ui/tooltip'
</script>

<template>
  <Tooltip>
    <TooltipTrigger as-child>
      <Button variant="outline">Hover</Button>
    </TooltipTrigger>
    <TooltipContent>Add to library</TooltipContent>
  </Tooltip>
</template>
```

`Tooltip` is shadcn-vue's tooltip on Reka UI, with its behaviour in `@kappa-ui/core/tooltip`. It opens once the pointer has rested on the trigger for `delay` milliseconds, 600 by default; moving the pointer restarts the wait, so a pointer sweeping across a toolbar opens nothing. It opens at once when the trigger takes keyboard focus, but not on focus from a click or a script, and on a long press on a touch screen. It closes when the pointer or focus leaves, the trigger is pressed, Escape is pressed or the trigger scrolls. One tooltip is open at a time.

A tooltip is a hint: it takes no pointer events, so a click on it lands on whatever is underneath. Content to hover, select or click belongs in a [hover card](/docs/components/hover-card) or a [popover](/docs/components/popover). `hoverable` keeps a tooltip open while the pointer moves onto it, for a hint that needs it.

## Examples

### Icon buttons

When the tooltip says what the button is called, give the button that name as `aria-label` and set `role="label"` on the tooltip. Screen readers then read the name once, not the name and then the same text as a description.

::component-preview{name="tooltip-toolbar"}
::

### Keyboard shortcut

A [`Kbd`](/docs/components/kbd) inside a tooltip takes the tooltip's colours.

::component-preview{name="tooltip-shortcut"}
::

### Disabled button

A button with the native `disabled` attribute gets no pointer events and cannot take focus, so its tooltip never opens. A `Button` with `aria-disabled="true"` looks the same and ignores presses, Enter and Space, but keeps both, so its tooltip can say why it is off.

::component-preview{name="tooltip-disabled"}
::

### Side and arrow

`side` and `align` on `TooltipContent` place the tooltip; it flips and shifts to stay 8 pixels inside the window. A `TooltipArrow` inside the content points at the trigger.

::component-preview{name="tooltip-side"}
::

### Follow the cursor

`follow-cursor` keeps the tooltip at the pointer while it moves over the trigger: along `x`, along `y` or on `both` axes. A tooltip opened by touch or the keyboard stays on the trigger.

::component-preview{name="tooltip-follow-cursor"}
::

## Directive

For a plain text hint, `v-tooltip` does what the parts do in one attribute. It comes with the component; import it where you use it, or register it once with `app.directive('tooltip', vTooltip)`:

```vue
<script setup lang="ts">
import { Button } from '@/components/ui/button'
import { vTooltip } from '@/components/ui/tooltip'
</script>

<template>
  <Button v-tooltip="'Save changes'">Save</Button>
</template>
```

::component-preview{name="tooltip-directive"}
::

| Form | Meaning |
| --- | --- |
| `v-tooltip="'Save'"` | The text. An empty string, `false`, `null` or `undefined` shows no tooltip. |
| `v-tooltip:bottom` | The side: `top`, `right`, `bottom` or `left`. |
| `v-tooltip.label` | Label mode, for an icon button: when the element has no name of its own, it gets `aria-label` with the text. |
| `v-tooltip="{ content, side, delay, followCursor, … }"` | The text with any `Tooltip` prop and `side`, `align`, `sideOffset`, `alignOffset`, `avoidCollisions`, `collisionPadding`, `sticky` and `hideWhenDetached` from `TooltipContent`. |

The directive tooltip shares everything else with the parts: the provider's settings and warm-up, touch, reasons and the look of `TooltipContent`. Rich content, a `Kbd` or an arrow need the parts.

## Touch

A touch screen has no hover, so a tooltip opens on a long press: a finger held still on the trigger for `touchDelay` milliseconds, 500 by default. It stays `touchHideDelay` milliseconds after the finger lifts, 1500 by default, or until a tap elsewhere. The press selects no text, opens no context menu and does not click the trigger; a tap shorter than the delay is an ordinary click. A pen touching the screen counts as touch, a hovering pen as a mouse. A tooltip opened by touch sets `data-touch` on the content, which draws it larger.

`touch` sets the policy:

| Value        | Behaviour                                                                                                                                                                                                |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `auto`       | A long press, except where the browser has its own: links, images, text fields, draggable elements and the targets of a [context menu](/docs/components/menu#context-menu). `data-kappa-longpress` on an element adds it to the list. The default. |
| `long-press` | A long press everywhere.                                                                                                                                                                                 |
| `off`        | Touch never opens it.                                                                                                                                                                                    |

## Open and close reasons

`update:open` receives `{ reason, event }` as its second argument:

```vue
<Tooltip @update:open="(open, { reason }) => console.log(open, reason)">
```

| Reason          | When                                                                                   |
| --------------- | -------------------------------------------------------------------------------------- |
| `trigger-hover` | The pointer rested on the trigger, or left it.                                         |
| `trigger-focus` | The trigger took keyboard focus, or lost it.                                           |
| `trigger-press` | A long press opened it, or a press on the trigger closed it.                           |
| `touch-release` | `touchHideDelay` passed after the finger lifted.                                       |
| `outside-press` | A press outside the trigger and the tooltip.                                           |
| `escape-key`    | Escape.                                                                                |
| `scroll`        | An element holding the trigger scrolled.                                               |
| `sibling-open`  | Another tooltip opened. The content gets `data-instant` and skips its exit animation. |
| `disabled`      | The tooltip or its trigger became disabled, or the trigger element was replaced.       |

Opening or closing it through `v-model:open` emits nothing.

## Accessibility

::keyboard-table
---
rows:
  - keys: Tab
    description: Moves focus to the trigger, which opens the tooltip.
  - keys: Escape
    description: Closes the tooltip.
---
::

While the tooltip is open, the trigger's `aria-describedby` points at a hidden copy of its text with `role="tooltip"`, so screen readers read it after the trigger's name. With `role="label"` the trigger's own name is what screen readers read, and the tooltip adds no description.
