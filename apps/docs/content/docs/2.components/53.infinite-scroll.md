## Installation

`InfiniteScroll` and `useInfiniteScroll` ship with the scroll area.

::install-tabs{name="scroll-area"}
::

## Usage

```vue
<script setup lang="ts">
import { InfiniteScroll, ScrollArea } from '@/components/ui/scroll-area'

const load = async ({ index }: { index: number }) => {
  const page = await fetchPage(index)
  items.value = [...items.value, ...page.items]
  if (page.last) return 'stop'
}
</script>

<template>
  <ScrollArea class="h-72">
    <InfiniteScroll :on-load="load">
      <p v-for="item in items" :key="item.id">{{ item.text }}</p>
    </InfiniteScroll>
  </ScrollArea>
</template>
```

`onLoad` is called with `{ direction, index }` once the edge comes within `offset` pixels, and not again in that direction until its promise settles. `index` counts the loads in a direction from 1, so it doubles as a page number. Resolve `'stop'` when there is nothing more: the direction stops until `resume()` or `reset()`. A rejected promise rolls the index back, reports the error to `app.config.errorHandler` and lets the next scroll try the same page again.

The API follows Quasar's `QInfiniteScroll`, with a promise in place of `done()` and four directions in place of `reverse`.

::callout{type="note"}
When the content does not fill the viewport, nothing can scroll, so the first page would be the last. `initialFill` keeps loading after each page until the content overflows or a direction stops.
::

## Examples

### Reverse

`directions="['top']"` loads older content at the top, as a conversation does. The reading position is kept: after the promise settles the scroll moves by the height that was added, in every browser, and the browser's own scroll anchoring is switched off for the duration so it does not move twice. Start the area at the bottom before enabling the loading, or the top edge is reached at mount.

::component-preview{name="infinite-scroll-reverse"}
::

### Horizontal

`start` and `end` load sideways and are logical: under `dir="rtl"`, `end` is the left edge. The root lays its parts out in a row when a horizontal direction is listed.

::component-preview{name="infinite-scroll-horizontal"}
::

### Both directions

Directions are independent: each has its own index, loading state and stop, and one loading does not block the other.

::component-preview{name="infinite-scroll-both"}
::

### The composable

`useInfiniteScroll(options)` is the same thing without markup, for a list that draws its own loading rows. `target` takes an element, the `window` or a `ScrollArea` API; without it, the nearest scrolling ancestor of `anchor` is used, else the window. `shouldLoad(direction)` replaces the pixel check for callers that know their own threshold, such as a virtualized list counting rows. It returns what `InfiniteScroll` exposes.

```ts
const rootRef = useTemplateRef<HTMLElement>('root')
const { state, reset } = useInfiniteScroll({
  anchor: rootRef,
  directions: ['bottom'],
  onLoad: async ({ index }) => {
    /* … */
  },
})
```

### Data attributes

::data-slots
---
rows:
  - slot: infinite-scroll
    attributes: data-orientation, aria-busy
    description: The root. A flex row when a horizontal direction is listed.
  - slot: infinite-scroll-loading
    attributes: data-direction, data-state
    description: The loading part at one edge, present until that direction stops. Invisible but keeping its room while idle.
  - slot: infinite-scroll-end
    attributes: data-direction
    description: The end slot at one edge, rendered once that direction is stopped and the slot is given.
---
::

## Accessibility

The root carries `aria-busy` while any direction loads. The loading parts are hidden from assistive technology; announce a loaded page yourself if that matters to your users.
