## Installation

::install-tabs{name="tooltip"}
::

Put one `TooltipProvider` around the app. Tooltips under it share their settings and warm up together: once one opens, the next opens instantly as you move along a toolbar.

```vue
<script setup lang="ts">
import { TooltipProvider } from '@/components/ui/tooltip'
</script>

<template>
  <TooltipProvider>
    <RouterView />
  </TooltipProvider>
</template>
```

No provider? Tooltips still work, just without the shared warm-up.

## Usage

```vue
<script setup lang="ts">
import { Button } from '@/components/ui/button'
import { Tooltip, TooltipContent, TooltipTrigger } from '@/components/ui/tooltip'
</script>

<template>
  <Tooltip>
    <TooltipTrigger as-child>
      <Button variant="outline">Hover</Button>
    </TooltipTrigger>
    <TooltipContent>Add to library</TooltipContent>
  </Tooltip>
</template>
```

It opens when the pointer rests on the trigger for `delay` milliseconds, 600 by default. Moving the pointer restarts the wait, so sweeping across a toolbar opens nothing. Keyboard focus opens it instantly (focus from a click doesn't), and so does a long press on touch screens.

It closes when the pointer or focus leaves, on a press, on Escape, or when the trigger scrolls. Only one tooltip is open at a time.

A tooltip is just a hint: clicks go right through it. Need something to hover, select or click? Use a [Hover Card](/docs/components/hover-card) or a [Popover](/docs/components/popover). Or set `hoverable` to keep the tooltip open while the pointer moves onto it.

## Examples

### Icon buttons

If the tooltip is the button's name, put the same text in the button's `aria-label` and set `role="label"` on the tooltip. Screen readers then read the name once, not twice.

::component-preview{name="tooltip-toolbar"}
::

### Keyboard shortcut

A [Kbd](/docs/components/kbd) inside a tooltip takes the tooltip's colours.

::component-preview{name="tooltip-shortcut"}
::

### Disabled button

A `disabled` button ignores the pointer and can't take focus, so its tooltip never opens. Use `aria-disabled="true"` on a `Button` instead: it looks the same and ignores clicks and keys, but the tooltip can still explain why it's off.

::component-preview{name="tooltip-disabled"}
::

### Side and arrow

`side` and `align` on `TooltipContent` place the tooltip, and it flips and shifts to stay on screen. Add a `TooltipArrow` inside to point at the trigger.

::component-preview{name="tooltip-side"}
::

### Follow the cursor

`follow-cursor` keeps the tooltip at the pointer: along `x`, `y` or `both`. Opened by touch or the keyboard, it stays on the trigger.

::component-preview{name="tooltip-follow-cursor"}
::

## Directive

For a plain text hint, one attribute is enough. Import `v-tooltip` where you use it, or register it once with `app.directive('tooltip', vTooltip)`:

```vue
<script setup lang="ts">
import { Button } from '@/components/ui/button'
import { vTooltip } from '@/components/ui/tooltip'
</script>

<template>
  <Button v-tooltip="'Save changes'">Save</Button>
</template>
```

::component-preview{name="tooltip-directive"}
::

| Form | Meaning |
| --- | --- |
| `v-tooltip="'Save'"` | The text. An empty string, `false`, `null` or `undefined` shows nothing. |
| `v-tooltip:bottom` | The side: `top`, `right`, `bottom` or `left`. |
| `v-tooltip.label` | For icon buttons: adds `aria-label` with the text if the element has no name of its own. |
| `v-tooltip="{ content, side, delay, followCursor, … }"` | The text plus any `Tooltip` prop and the placement props of `TooltipContent`: `side`, `align`, `sideOffset`, `alignOffset`, `avoidCollisions`, `collisionPadding`, `sticky`, `hideWhenDetached`. |

Everything else works the same as with the parts. For rich content, a `Kbd` or an arrow, use the parts.

## Touch

No hover on touch screens, so a tooltip opens on a long press: hold still on the trigger for `touchDelay` milliseconds, 500 by default. It stays for `touchHideDelay` milliseconds after you lift your finger, 1500 by default, or until you tap elsewhere.

The press doesn't select text, open the context menu or click the trigger. A shorter tap is just a click. Opened by touch, the tooltip gets `data-touch` and draws a bit larger.

`touch` sets the policy:

| Value | Behaviour |
| --- | --- |
| `auto` | The default. A long press, except where the browser has its own: links, images, text fields, draggable elements and [context menu](/docs/components/menu#context-menu) targets. Add `data-kappa-longpress` to an element to put it on that list. |
| `long-press` | A long press everywhere. |
| `off` | Touch never opens it. |

## Open and close reasons

`update:open` gets `{ reason, event }` as a second argument:

```vue
<Tooltip @update:open="(open, { reason }) => console.log(open, reason)">
```

| Reason | When |
| --- | --- |
| `trigger-hover` | The pointer rested on the trigger, or left it. |
| `trigger-focus` | The trigger got keyboard focus, or lost it. |
| `trigger-press` | A long press opened it, or a press on the trigger closed it. |
| `touch-release` | `touchHideDelay` passed after the finger lifted. |
| `outside-press` | A press outside the trigger and the tooltip. |
| `escape-key` | Escape. |
| `scroll` | Something holding the trigger scrolled. |
| `sibling-open` | Another tooltip opened. This one closes without its exit animation (`data-instant`). |
| `disabled` | The tooltip or its trigger got disabled, or the trigger element was replaced. |

Changes through `v-model:open` emit nothing.

## API Reference

`TooltipContent` and `TooltipArrow` take a `class` that merges with their own.

::api-reference{parts="TooltipProvider,Tooltip,TooltipTrigger,TooltipContent,TooltipArrow"}
::

### Data attributes

::data-slots
---
rows:
  - slot: tooltip-trigger
    attributes: data-state
    description: "The trigger, a button by default. `data-state` is `closed`, `delayed-open` or `instant-open`."
  - slot: tooltip-content
    attributes: data-state, data-side, data-align, data-touch, data-instant
    description: "The tooltip. `data-touch` when a long press opened it; `data-instant` when it closes without its exit animation."
  - slot: tooltip-arrow
    description: The arrow.
---
::

## Accessibility

::keyboard-table
---
rows:
  - keys: Tab
    description: Moves focus to the trigger, which opens the tooltip.
  - keys: Escape
    description: Closes the tooltip.
---
::

While the tooltip is open, screen readers read its text after the trigger's name. With `role="label"`, they read only the trigger's name.
