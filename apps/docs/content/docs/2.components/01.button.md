## Examples

### Variants

`variant` is the look, `color` is the colour. 6 × 6 = 36 combos, and all of them work. Yes, even a destructive ghost. Defaults: `solid` + `primary`.

`subtle` is `soft` with an edge, so it survives tinted backgrounds and [button groups](/docs/components/button-group). The edge is an inset ring, not a border, so swapping variants never moves the layout.

::component-preview{name="button-variants"}
::

### Custom colours

Need a colour we didn't ship? Three variables and a name:

```css
[data-slot][data-color='pro'] {
  --tone: var(--color-violet-600);       /* fill */
  --tone-foreground: white;              /* text on the fill */
  --tone-text: var(--color-violet-700);  /* text without a fill */
}
```

```vue
<Button color="pro">Upgrade</Button>
```

It works with every variant. Soft fills and edges are derived from these three. The full variable list lives in [Theming](/docs/getting-started/theming#tones).

Just for one button? Skip the CSS:

```vue
<Button class="[--tone:var(--color-pink-500)] [--tone-foreground:white] [--tone-text:var(--color-pink-700)]">
  Upgrade
</Button>
```

### Icons

An icon inside a button should say which side it sits on, with `data-icon="inline-start"` or `data-icon="inline-end"`. The button then tightens padding on that side only; a rule keyed on `svg` would pull in both sides at once and cramp the label against the far edge. [Spinner](/docs/components/spinner) sets `data-icon="inline-start"` itself, so the ordinary case needs nothing from you.

### Focus ring

A host that clips overflow cuts off the default outward ring, and a keyboard user gets no indicator at all. `focus-ring="inward"` draws it inside. Tab through both.

Smaller than a finger? Add `touch-target`: `expand` when it stands alone, `wrapper` when it sits close to others. [How it works](/docs/getting-started/accessibility#touch-targets).

## Accessibility

::keyboard-table
---
rows:
  - keys: Enter
    description: Activates the button.
  - keys: Space
    description: Activates the button.
---
::

Native `disabled` takes the button out of the tab order: if it had focus, the browser moves focus to `<body>`, so a keyboard user loses their place at the moment they act. It also stops pointer events, so a [tooltip](/docs/components/tooltip) cannot say why the button is off. `aria-disabled="true"` draws the same disabled look but keeps focus and pointer events; the button swallows its click, so neither a press nor Enter or Space reaches your handler. See [W3C's guidance on disabled controls](https://www.w3.org/WAI/ARIA/apg/practices/keyboard-interface/#kbd_disabled_controls).
