## Usage

```vue
<script setup lang="ts">
import { ScrollArea } from '@/components/ui/scroll-area'
</script>

<template>
  <ScrollArea class="h-72 rounded-lg border">
    <div class="p-4">…</div>
  </ScrollArea>
</template>
```

`ScrollArea` hides the native scrollbar and draws its own over a real native scroller. The API follows Quasar's `QScrollArea`. On a touch screen the bars only show where you are: a touch on them passes through to the content, which scrolls natively.

::callout{type="warning"}
The root is `contain: size`, so it takes no height from its content — give it one, or it collapses. Put padding on a wrapper inside the slot rather than on the root: the bars are positioned against the root while the geometry that drives them is measured from the viewport inside it, so padding on the root shifts the bars out of line with the content. A border on the root is fine.
::

### Styling

There is one `class` prop per component. The bar is its own component, `ScrollBar`, with its own `class`; the thumb's look is hardcoded in `ScrollBar.vue`, so edit your copy to change it. Every part carries `data-slot` and every bar and thumb carries `data-axis`, so the root's `class` can still reach them:

::component-preview{name="scroll-area-styled"}

### Horizontal

`orientation` picks the axis, `vertical` by default. It sets the viewport's overflow, chooses the virtualized axis and decides which bars render — so a vertical area does not scroll sideways, and content that must scroll horizontally needs `orientation="horizontal"`, or `both` for content that overflows in both directions. Right-to-left is mirrored either way; switch the example to RTL to see it.

::component-preview{name="scroll-area-horizontal"}
::

### Both axes

`orientation="both"` draws a bar per axis and reports all four `data-overflow-*` edges. The bars share the bottom-end corner, as Quasar's do; `verticalOffset` and `horizontalOffset` keep it free. With `virtualize`, only the vertical axis is virtualized.

::component-preview{name="scroll-area-both"}
::

### Edge fade

The root carries `data-overflow-x-start`, `data-overflow-x-end`, `data-overflow-y-start` and `data-overflow-y-end` while the viewport can still scroll towards that edge. [`scroll-fade-overlay-x`](/docs/utilities/scroll-fade) turns them into gradients over the edges, and the buttons here show through a `group-has-[[data-overflow-x-end]]` variant — no scroll listener of their own. Each press scrolls 80% of the width with `setScrollPosition`.

::component-preview{name="scroll-area-edge-fade"}
::

### Edge events

`reachEdge` fires once as the position enters an edge zone, with `{ edge, ref }`, and again only after it leaves. `edgeOffset` widens the zone in pixels. It reports a fact and nothing more; for loading on reach, use the [infinite scroll](/docs/components/infinite-scroll).

::component-preview{name="scroll-area-reach-edge"}
::

### Virtualize

Set `virtualize` and pass `items`. The default slot then renders once per item in the rendered window — the visible items plus the overscan buffer — with `{ item, index }`. The engine is [TanStack Virtual](https://tanstack.com/virtual/latest), which is why this component installs `@tanstack/vue-virtual`. Nuxt UI and Reka UI use the same engine.

`estimateSize` is only an estimate; real sizes are measured after render, so items of differing size work.

### Programmatic scroll

`scrollTo(index, edge?)` scrolls to an item. `edge` is `'start'`, `'center'` or `'end'` and always aligns; omit it to leave an already visible item where it is. `@virtual-scroll` fires with `{ index, from, to, direction, ref }` whenever the item at the scroll position changes.

::component-preview{name="scroll-area-scroll-to"}
::

### External scroll element

`virtualize` also accepts `getScrollElement` and `scrollMargin`, which virtualize the list against an ancestor scroller instead of the component's own viewport. In that mode the component grows to the list's full size, its viewport stops scrolling and no bar is drawn. `scrollMargin` is the list's offset from the top of that scroller. The getter must return the element at mount: one that returns `null` then and resolves later leaves the list attached to neither scroller.

### Data you do not hold

Pass `items-size` and `items-fn` instead of `items`. The function is called with `(from, size)` for the rendered window only.

## Accessibility

`tabindex` lands on the viewport, since that is the element that scrolls and receives focus. Fallthrough attributes, `aria-label` included, land on the root — so an `aria-label` on the component labels the wrapper, not the focusable element. Once focused, the viewport scrolls with the keyboard natively:

::keyboard-table
---
rows:
  - keys: ↑ ↓ ← →
    description: Scrolls by a line on the active axis.
  - keys: Page Up / Page Down
    description: Scrolls by a page.
  - keys: Home / End
    description: Scrolls to the start or the end.
  - keys: Space
    description: Scrolls down by a page; Shift+Space scrolls up.
---
::

### Exposed

The `scroll` payload carries the same object as `ref`, so one handler can serve many areas without template refs. The exposed `virtualizer` is outside this component's API stability: if the engine changes, code built on it changes with it.
