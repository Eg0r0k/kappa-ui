## Usage

```vue
<script setup lang="ts">
import { CalendarDate } from '@internationalized/date'
import type { DateValue } from 'reka-ui'
import { Calendar } from '@/components/ui/calendar'

const date = shallowRef<DateValue | undefined>(new CalendarDate(2026, 10, 6))
</script>

<template>
  <Calendar v-model="date" />
</template>
```

`v-model` is a date from `@internationalized/date`, `CalendarDate` for a plain day, or `undefined` when nothing is picked. Clicking the selected day again clears it; `prevent-deselect` stops that. Type your ref as `DateValue`, the type the events carry, not as `CalendarDate`.

Keep one copy of `@internationalized/date` in your app. The install adds it; two copies end in `'#private' refers to a different member` type errors.

The heading sits at the start and the arrows at the end, Material 3 style. The grid always draws six weeks, so the calendar keeps its height from month to month and a popover around it doesn't jump. Set `:fixed-weeks="false"` to draw only the weeks a month needs.

The calendar has no hidden input, so it doesn't submit with a plain `<form>`. Bind `v-model` to your form library instead, as in the [form example](#form). Inside a [Field](/docs/components/field) it takes the field's disabled and invalid state, and the field label names it together with the month.

Need a start and an end date? That's [Range Calendar](/docs/components/range-calendar).

## Examples

### Sizes

`xs` to `xl` on the [control scale](/docs/getting-started/sizing), `md` by default. A day is as tall as a control of the same size: 28px at `xs`, 36px at `md`, 48px at `xl`. The arrows are icon buttons of the same size, so the header lines up with the grid.

::component-preview{name="calendar-sizes"}
::

### Color

`color` tints the selected day and today's outline. `neutral` is the monochrome one. Your own colours work as on [Button](/docs/components/button#custom-colours).

::component-preview{name="calendar-color"}
::

### Multiple

With `multiple`, each click toggles a day and `v-model` is an array.

::component-preview{name="calendar-multiple"}
::

### Min and max

Days before `min-value` and after `max-value` are disabled, and the arrows stop at their months. The arrow keys stop there too.

::component-preview{name="calendar-min-max"}
::

### Disabled dates

`is-date-disabled` takes a function that returns `true` for days that can't be picked. Disabled days fade and the arrow keys skip them.

::component-preview{name="calendar-disabled-dates"}
::

### Unavailable dates

`is-date-unavailable` is for days that exist but are taken. They're struck through and can't be picked, but keyboard focus still lands on them, so a screen reader user hears they're there.

::component-preview{name="calendar-unavailable-dates"}
::

### Week numbers

`week-numbers` adds a column of week numbers. Each one is counted from the first day of its row, so the column stays right when `week-starts-on` differs from the locale's start. `de-DE` counts ISO weeks.

`week-starts-on` runs from `0`, Sunday, to `6`. Leave it out and the locale decides: Sunday for `en-US`, Monday for `de-DE`.

::component-preview{name="calendar-week-numbers"}
::

### Locale

Month names, weekdays and digits follow `locale` or Reka UI's `ConfigProvider`, and so does the direction: in right-to-left the arrows flip and so do the arrow keys. For a non-Gregorian calendar, pass a date in it, here with `toCalendar(date, new PersianCalendar())`.

::component-preview{name="calendar-locale"}
::

### Month and year select

The `heading` slot gets `{ headingValue, date, setPlaceholder }`. `setPlaceholder` moves the view to a date's month without selecting anything, so two [Selects](/docs/components/select) make a quick way back to 1990. Build the year list from your bounds, not from the month on screen, or it drifts as you page.

::component-preview{name="calendar-month-year-select"}
::

### Placeholder

The placeholder is the month on screen. Bind it with `v-model:placeholder` to page from outside, or set `default-placeholder` to open on a month without selecting a day.

::component-preview{name="calendar-placeholder"}
::

### Events

The `day` slot draws a day's content, with `{ day, dayValue, selected, today, ... }`. Keep `dayValue`: it's the number in the locale's digits. The dots are only drawn, so say the same thing in words, here with `aria-describedby` on the calendar.

::component-preview{name="calendar-events"}
::

### Date picker

A [Popover](/docs/components/popover) around the calendar. With `initial-focus`, the selected day or today takes focus when it opens; picking a day closes it.

::component-preview{name="calendar-date-picker"}
::

### Form

[Formisch](/docs/forms/formisch) keeps the date as an ISO string, and the calendar gets `parseDate(field.input)` back. That's a new object on every render, which the calendar takes in its stride: it stays on the month you paged to. Press Sign up without a date.

::component-preview{name="calendar-form"}
::

## Accessibility

Each day is announced with its full date, "Tuesday, October 6, 2026", in the calendar's locale. Only one day is in the tab order: the selected day, or the one the arrow keys last reached. Tab goes Previous, Next, the day, and out.

Reka UI names the root "Event Date, October 2026". In a Field, the field label replaces "Event Date". Elsewhere, set `calendar-label`. The arrows say "Previous page" and "Next page"; pass `aria-label` on `CalendarPrevButton` and `CalendarNextButton` to change it.

The grid is a `<table role="application">`, so screen readers in browse mode hand the arrow keys to the calendar instead of reading the table.

Days are divs with `role="button"`, not buttons: a `<button>` would put disabled days and the neighbouring months' days in the tab order, and submit the form around it on a click.

::keyboard-table
---
rows:
  - keys: ArrowLeft / ArrowRight
    description: Moves to the previous or next day, flipped in right-to-left. Skips disabled days and turns the page at the month's edge.
  - keys: ArrowUp / ArrowDown
    description: Moves to the same day of the previous or next week.
  - keys: Enter / Space
    description: "Selects the day, or clears it if it's selected. With `multiple`, toggles it."
  - keys: Home / End
    description: Moves to the first or last day of the week. Needs reka-ui 2.11 or later.
  - keys: PageUp / PageDown
    description: Moves to the same day of the previous or next month. Needs reka-ui 2.11 or later.
  - keys: Shift + PageUp / Shift + PageDown
    description: Moves to the same day of the previous or next year. Needs reka-ui 2.11 or later.
  - keys: Ctrl + Enter
    description: Isn't taken by the day, so it reaches the form around the calendar, for a submit shortcut.
---
::

## Known limits

- Reka UI marks its Calendar as alpha ([reka-ui#2789](https://github.com/unovue/reka-ui/issues/2789)), so its behaviour still moves between minor versions. The tests pin what kappa relies on.
- Home, End, PageUp and PageDown need reka-ui 2.11 ([reka-ui#2530](https://github.com/unovue/reka-ui/pull/2530)). On 2.10 they do nothing.
- On reka-ui 2.10, a `v-model` rebuilt as a new object for the same day moved the view back to it ([reka-ui#2960](https://github.com/unovue/reka-ui/issues/2960)). The calendar works around it, so you don't have to.
- With `multiple`, clearing a day moves the view to the month of the last day still selected. That comes from Reka UI.
- "Event Date", "Previous page" and "Next page" are English whatever the locale. Use a Field, `calendar-label` and `aria-label` as above.
- Today's outline is worked out where the page renders. A prerendered page shows the day it was built; render the calendar on the client if that matters.
- Some automated checkers flag the `gridcell`s inside `role="application"`. Reka UI keeps the role on purpose, for NVDA ([reka-ui#2438](https://github.com/unovue/reka-ui/issues/2438)).
- `disable-days-outside-current-view` disables the neighbouring months' days but still shows them; with more than one month the calendar hides them itself, since the next grid draws them again ([reka-ui#2730](https://github.com/unovue/reka-ui/issues/2730)).
