## Usage

```vue
<script setup lang="ts">
import { Button } from '@/components/ui/button'
</script>

<template>
  <Button variant="outline" color="neutral">Button</Button>
</template>
```

## Examples

### Variants

Appearance and colour are separate props: `variant` is one of `solid`, `soft`, `subtle`, `outline`, `ghost` and `link`, and `color` one of `primary`, `neutral`, `destructive`, `success` and `warning`. Every pair works, and both default to `solid` and `primary`, so an outline or ghost button without a `color` is primary too. `subtle` is `soft` with an edge in its own colour, so it keeps an edge on a tinted background and joins like `outline` in a [button group](/docs/components/button-group). `outline` and `subtle` draw that edge inside the button, as an inset ring rather than a border, so every variant has the same size and switching one for another never moves the layout.

::component-preview{name="button-variants"}
::

### Sizes

Sizes run from `xs` (28px) to `xl` (48px). Icon sizes are square and match the text sizes' heights, so an icon button lines up with a text button of the same size. `xl` is 48px, exactly the touch-target minimum, so `touch-target` has nothing to add on that size.

::component-preview{name="button-sizes"}
::

### Icons

An icon inside a button should say which side it sits on, with `data-icon="inline-start"` or `data-icon="inline-end"`. The button then tightens padding on that side only; a rule keyed on `svg` would pull in both sides at once and cramp the label against the far edge. [Spinner](/docs/components/spinner) sets `data-icon="inline-start"` itself, so the ordinary case needs nothing from you.

::component-preview{name="button-icon"}
::

### Loading

The button has no `loading` prop and no spinner of its own. You render one inside it. The base styles give any `svg` a 16px size and a gap, so the spinner lands correctly — and any indicator works, not only kappa-ui's. To keep the width from changing with the label, add `min-w-32` yourself.

::component-preview{name="button-loading"}
::

### As a link

`as` renders another element; `as-child` merges the button onto the single element you pass.

::component-preview{name="button-as-child"}
::

### Focus ring

A host that clips overflow cuts off the default outward ring, and a keyboard user gets no indicator at all. `focus-ring="inward"` draws it inside. Tab through both.

::component-preview{name="button-focus-ring"}
::

### Touch target

`touch-target` grows the pressable area to at least 48px without changing how the button looks — adapted from Material Web's touch target. The outlines are drawn by the example, not by the component. It is off by default: turned on everywhere, adjacent buttons in a dense row silently overlap and a press can land on the wrong one. Use `wrapper` when buttons sit close together, `expand` when the button stands alone.

::component-preview{name="button-touch-target"}
::

## Accessibility

::keyboard-table
---
rows:
  - keys: Enter
    description: Activates the button.
  - keys: Space
    description: Activates the button.
---
::

Native `disabled` is a real trade, not an oversight. A disabled control leaves the tab order, so if it had focus the browser moves focus to `<body>` — a keyboard user loses their place at the moment they act, and a screen reader goes quiet. The alternative is `aria-disabled` plus blocking the behaviour yourself: `pointer-events: none` for the mouse, and a prevented default on Enter and Space so no click is synthesised. This component does not do that for you; it is your copy of the source, so add it there if your app needs it. See [W3C's guidance on disabled controls](https://www.w3.org/WAI/ARIA/apg/practices/keyboard-interface/#kbd_disabled_controls).
