## Usage

```vue
<script setup lang="ts">
import { createDataTableColumnHelper, DataTable } from '@/components/ui/data-table'

type Payment = { id: string; email: string; amount: number }

const helper = createDataTableColumnHelper<Payment>()
const columns = helper.columns([
  helper.accessor('email', { header: 'Email' }),
  helper.accessor('amount', { header: 'Amount', size: 120, meta: { align: 'end' } }),
])
</script>

<template>
  <DataTable :data="payments" :columns="columns" :get-row-id="(row) => row.id" sortable />
</template>
```

The engine is [TanStack Table v9](https://tanstack.com/table/latest), which is why this component installs `@tanstack/vue-table`. `createDataTableColumnHelper` binds the column helper to the features the table registers, so column definitions, `getValue()` in slots and the state models are typed. Give every table a `getRowId`: without it a row's id is its index, and anything keyed by id moves when the rows are sorted or replaced. Pass a new array to change the rows; a `push` into the same array is not seen.

The table renders the [Table](/docs/components/table) parts' classes on raw elements instead of mounting a component per cell, so a thousand cells are a thousand elements, not a thousand component instances. Everything the parts do, this does: borders on cells, `--table-row-bg` for row state, the pinned-edge shadow.

## Examples

### Columns and slots

A column renders its `header`, `cell` and `footer` through TanStack's `FlexRender`: a string, a function returning a string or a vnode, or a component. A slot named `cell-<column id>`, `header-<column id>` or `footer-<column id>` replaces that and receives the TanStack context (`getValue`, `row`, `column`, `table`). Column `meta` takes `align` (`start`, `center` or `end`), `truncate` (an ellipsis in a fixed layout), and `class` and `style` for `th` and `td`, each a value or a function of the context. The `toolbar` slot renders above the table, outside the scroller.

::component-preview{name="data-table-slots"}
::

### Sorting

`sortable` gives every column that can sort a header button, `DataTableColumnHeader`, which cycles ascending, descending and off, and marks the `th` with `aria-sort`. Shift-click adds a column to a multi-sort; `{ multi: false }` keeps it single, `{ removable: false }` drops the off state. A column opts out with `enableSorting: false`. `v-model:sorting` holds `[{ id, desc }]`.

### Height, sticky parts and virtualization

`height` puts the table in a [scroll area](/docs/components/scroll-area) on both axes, the one scroller the sticky header, the sticky footer and the pinned columns share. `sticky` sticks the header, the footer or both. `virtualize` renders only the rows near the view: `true` always, `"auto"` from 200 rows, or an object. Each row is one `tbody`, and spacer row groups keep the scroll height, so the table stays a table: `colspan`, sticky parts and `aria-rowcount` all hold. Rows keep the density's height; set `measure: true` for rows of varying height, which are then measured as they render.

Virtualization has costs the browser cannot hide: find-in-page and select-all see only the rendered rows, and printing prints the window. Keep it for tables that need it; `scrollToRow` and `scrollToIndex` reach any row.

::component-preview{name="data-table-virtualized"}
::

### Pinned columns

`v-model:column-pinning` takes `{ start: [...ids], end: [...ids] }`. Pinned columns stick at offsets computed from the column widths, so give pinned columns a `size`; the table writes the widths and offsets as CSS variables on the `<table>` and switches to a fixed layout. When every column has a width and the table is wider than their sum, a filler column takes the rest, so the offsets stay true. The outermost pinned column on each side draws the shadow while the area can scroll under it.

::component-preview{name="data-table-pinned"}
::

### Pagination

`paginate` slices the rows and renders `DataTablePagination` under the table. `v-model:pagination` holds `{ pageIndex, pageSize }`; the page resets when the rows change.

::component-preview{name="data-table-pagination"}
::

### Server mode

`manual` (all of it, or `{ sorting, filtering, pagination, expanding }` per feature) leaves the work to your source: the table shows `data` as it is and reports the state through the models. Give it `rowCount` so it knows the page count; without it the bar shows previous and next only. The page index is not reset for you in manual mode.

::component-preview{name="data-table-server"}
::

### Loading and empty

`loading` shows an indeterminate progress bar under the header, so the rows you have stay in place; with no rows it shows skeleton rows of the density's height, as many as fit the height. Without rows and without loading, the `empty` message shows, or `noResults` when a filter is active.

::component-preview{name="data-table-states"}
::

### Row events

`onRowClick`, `onRowContextmenu` and `onRowHover` are props (bind them as `@row-click` too), so a table knows when its rows are clickable: those rows get `tabindex="0"`, a pointer cursor and `data-clickable`, and fire on Enter and Space. A click on a control inside the row is not a row click, so buttons and inputs in cells keep working. The row keeps no role; give the same action to a control inside the row for keyboard and screen reader users.

### Selection

`selection` prepends a checkbox column: `true` or `"multiple"` for many rows, `"single"` for one, or `{ mode, column, enableRowSelection, selectAll }`, where `column: false` keeps the column out and `enableRowSelection` decides per row. `v-model:row-selection` holds `{ [id]: true }`, and a shift-click selects the range from the last toggled row. The row selection is a plain `v-model`; on top of it `update:rowSelection` carries `{ source }` as a second argument, `header`, `row`, `range` or `imperative`, for the code that wants to know how the change came about.

Under pagination the header checkbox selects the page, and a banner offers the rest, as in Gmail. `v-model:select-all` walks `none`, `page` and `all`: in `all` every row across pages counts as selected and the model holds only the rows taken out, as `{ [id]: false }`, so `getSelection()` returns `{ mode, ids, excluded, count }` for the request. Unchecking a row while `page` drops the mode back to `none`; in manual mode a change of sorting or filters drops `all` to `none`, because the rows the user agreed to are gone. `selectAllLabels` sets the banner texts, and the `select-all-banner` slot replaces the banner. Without pagination the header checkbox selects every filtered row and there is no banner; `selectAll: false` turns the machine off under pagination too.

::component-preview{name="data-table-selection"}
::

### Expanding and trees

`expandable` prepends a chevron column. With an `expanded` slot, a row opens a detail row inside its own row group: hover and selection tint both, and under virtualization the group is measured as one item, so `measure` switches on. `v-model:expanded` holds `{ [id]: true }`, or `true` for every row; `table.toggleAllRowsExpanded()` toggles them all, and `getRowCanExpand` in the prop decides per row.

::component-preview{name="data-table-expanding"}
::

`getSubRows` makes a tree: the children of an expanded row render as rows of their own, indented by depth, counted in `aria-rowcount`, and paginated like the rest unless `paginateExpandedRows: false` keeps them on their parent's page.

::component-preview{name="data-table-tree"}
::

### Grouping

`groupable` lets `v-model:grouping` group the rows by column ids, in order. The grouped columns move to the front; a group row (`data-slot="table-group"`) shows a toggle, the value and the leaf count in the grouping column, and in the others the column's `aggregatedCell`, computed by its `aggregationFn` (`sum`, `count`, `mean`, `unique` and the rest of TanStack's). Groups expand through the `expanded` model, like tree rows.

::component-preview{name="data-table-grouping"}
::

### Pinned rows

`v-model:row-pinning` takes `{ top: [...ids], bottom: [...ids] }`. Pinned rows render in row groups of their own, sticky under the header and above the footer, outside the virtualized window, and they stay while a filter removes them from the rows. `row.pin('top')`, `row.pin('bottom')` and `row.pin(false)` from a cell toggle one. `aria-rowindex` counts the top ones before the rows and the bottom ones after.

::component-preview{name="data-table-pinned-rows"}
::

### Infinite scroll

`onLoadMore` (bind it as `@load-more` too) loads more rows when the scroller nears an edge. It receives `{ direction, index }`, `index` counting loads in that direction from 1, and resolves once the rows are in `data`; resolve `'stop'` when there are no more, or set `hasMore` to `false`, or `{ top, bottom }`, to pause loading until it turns true again. `loadMore` sets the `direction` (`bottom`, `top` or `both`), the `threshold` and `initialFill`. Under virtualization the threshold is in rows and defaults to the overscan; otherwise it is in pixels, 200 by default. A load at the top keeps the reading position. The `loadingMore` slot renders in a row at the loading edge, a spinner by default, and `endOfData` once a direction is stopped. A manual sort or filter change restarts the index, so the next load is 1 again. The scroller is the table's own scroll area, or the nearest scrolling ancestor, or the window; it runs on the scroll area's [`useInfiniteScroll`](/docs/components/infinite-scroll). Do not combine it with manual pagination; the table warns in development.

::component-preview{name="data-table-infinite"}
::

## State

Every TanStack state slice is a `v-model:` on the component: `sorting`, `column-visibility`, `column-pinning`, `column-order`, `column-sizing`, `column-filters`, `global-filter`, `pagination`, `row-selection`, `expanded`, `grouping` and `row-pinning`, plus the table's own `select-all`. A model you do not bind is local, and one you bind is the single source, so binding a model whose initial value is `undefined` works. `tableOptions.initialState` sets starting values for either.

## Known limits

- A mutation of `data` in place is not seen; pass a new array.
- Without `height`, `overflow="x"` clips the table in a container that never scrolls vertically, so a sticky header does not stick; use `overflow="visible"` for a header sticky to the page.
- Browsers lay out about sixteen million pixels of height; past that, paginate on the server. The table warns in development.
- A pinned column without a `size` takes TanStack's default of 150 pixels, with a warning in development.
- There is no `maxHeight`: the scroll area is size-contained, so give the table a `height`. Column resizing is the next stage.

## Accessibility

The table carries `aria-rowcount` and every row `aria-rowindex`, counted over header, pinned, body and footer rows, so a screen reader announces "row 5001 of 10001" even while only a window of rows exists. A detail row belongs to its row and carries no index. Spacer row groups and the loading row are hidden from assistive technology. A focused row stays mounted while it scrolls out of the window, so focus is not lost. The scroll area pads its scroll by the sticky header's and the pinned rows' heights, so focusing a row never lands it under them. The checkboxes and chevrons are labelled buttons, and the banner is a live region.

### Data attributes

The parts carry the [Table](/docs/components/table) slots, `table`, `table-header`, `table-row`, `table-head`, `table-cell`, `table-footer`, `table-caption` and `table-empty`, with the same attributes, plus these:

::data-slots
---
rows:
  - slot: data-table
    attributes: data-density, data-loading
    description: The root. Carries --table-thead-h, --table-tfoot-h, --table-pinned-top-h and --table-pinned-bottom-h, the measured heights of the sticky parts.
  - slot: table-row-group
    attributes: data-index, data-state, data-parity, data-expanded
    description: One tbody per row, the virtual item and the measured element; it carries the row's selected state, stripe parity and expanded state, so a detail row is tinted with its row.
  - slot: table-expanded
    description: The detail row inside an expanded row's group.
  - slot: table-group
    description: A grouped row, in place of table-row.
  - slot: table-pinned-top
    description: The sticky row group of the rows pinned to the top.
  - slot: table-pinned-bottom
    description: The sticky row group of the rows pinned to the bottom.
  - slot: table-spacer
    description: A row group standing in for rows outside the window; hidden from assistive technology.
  - slot: table-filler
    description: The column taking the width left over when every column has a size.
  - slot: table-loading
    description: The header row holding the progress bar while loading.
  - slot: table-loading-more
    attributes: data-direction
    description: The row at an edge while more rows load; hidden from assistive technology.
  - slot: table-end-of-data
    attributes: data-direction
    description: The row at an edge once it has no more rows.
  - slot: table-skeleton
    description: The body of skeleton rows while loading with no data.
  - slot: data-table-column-header
    attributes: data-sorted
    description: The sort button in a header.
  - slot: data-table-select-header
    description: The header checkbox.
  - slot: data-table-select-cell
    description: A row's checkbox.
  - slot: data-table-select-all-banner
    attributes: data-mode
    description: The banner under the toolbar while a page or every row is selected.
  - slot: data-table-expand-cell
    description: A row's chevron.
  - slot: data-table-group-cell
    description: A grouped row's toggle, value and count.
  - slot: data-table-pagination
    description: The bar under the table.
