## Usage

```vue
<script setup lang="ts">
import { createDataTableColumnHelper, DataTable } from '@/components/ui/data-table'

type Payment = { id: string; email: string; amount: number }

const helper = createDataTableColumnHelper<Payment>()
const columns = helper.columns([
  helper.accessor('email', { header: 'Email' }),
  helper.accessor('amount', { header: 'Amount', size: 120, meta: { align: 'end' } }),
])
</script>

<template>
  <DataTable :data="payments" :columns="columns" :get-row-id="(row) => row.id" sortable />
</template>
```

The engine is [TanStack Table v9](https://tanstack.com/table/latest), which is why this component installs `@tanstack/vue-table`. `createDataTableColumnHelper` binds the column helper to the features the table registers, so column definitions, `getValue()` in slots and the state models are typed. Give every table a `getRowId`: without it a row's id is its index, and anything keyed by id moves when the rows are sorted or replaced. Pass a new array to change the rows; a `push` into the same array is not seen.

The table renders the [Table](/docs/components/table) parts' classes on raw elements instead of mounting a component per cell, so a thousand cells are a thousand elements, not a thousand component instances. Everything the parts do, this does: borders on cells, `--table-row-bg` for row state, the pinned-edge shadow.

## Examples

### Columns and slots

A column renders its `header`, `cell` and `footer` through TanStack's `FlexRender`: a string, a function returning a string or a vnode, or a component. A slot named `cell-<column id>`, `header-<column id>` or `footer-<column id>` replaces that and receives the TanStack context (`getValue`, `row`, `column`, `table`). Column `meta` takes `align` (`start`, `center` or `end`), `truncate` (an ellipsis in a fixed layout), and `class` and `style` for `th` and `td`, each a value or a function of the context. The `toolbar` slot renders above the table, outside the scroller.

### Sorting

`sortable` gives every column that can sort a header button, `DataTableColumnHeader`, which cycles ascending, descending and off, and marks the `th` with `aria-sort`. Shift-click adds a column to a multi-sort; `{ multi: false }` keeps it single, `{ removable: false }` drops the off state. A column opts out with `enableSorting: false`. `v-model:sorting` holds `[{ id, desc }]`.

### Height, sticky parts and virtualization

`height` puts the table in a [scroll area](/docs/components/scroll-area) on both axes, the one scroller the sticky header, the sticky footer and the pinned columns share. `sticky` sticks the header, the footer or both. `virtualize` renders only the rows near the view: `true` always, `"auto"` from 200 rows, or an object. Each row is one `tbody`, and spacer row groups keep the scroll height, so the table stays a table: `colspan`, sticky parts and `aria-rowcount` all hold. Rows keep the density's height; set `measure: true` for rows of varying height, which are then measured as they render.

Virtualization has costs the browser cannot hide: find-in-page and select-all see only the rendered rows, and printing prints the window. Keep it for tables that need it; `scrollToRow` and `scrollToIndex` reach any row.

::component-preview{name="data-table-virtualized"}

### Pinned columns

`v-model:column-pinning` takes `{ start: [...ids], end: [...ids] }`. Pinned columns stick at offsets computed from the column widths, so give pinned columns a `size`; the table writes the widths and offsets as CSS variables on the `<table>` and switches to a fixed layout. When every column has a width and the table is wider than their sum, a filler column takes the rest, so the offsets stay true. The outermost pinned column on each side draws the shadow while the area can scroll under it.

::component-preview{name="data-table-pinned"}
::

### Pagination

`paginate` slices the rows and renders `DataTablePagination` under the table. `v-model:pagination` holds `{ pageIndex, pageSize }`; the page resets when the rows change.

::component-preview{name="data-table-pagination"}
::

### Server mode

`manual` (all of it, or `{ sorting, filtering, pagination, expanding }` per feature) leaves the work to your source: the table shows `data` as it is and reports the state through the models. Give it `rowCount` so it knows the page count; without it the bar shows previous and next only. The page index is not reset for you in manual mode.

::component-preview{name="data-table-server"}
::

### Loading and empty

`loading` shows an indeterminate progress bar under the header, so the rows you have stay in place; with no rows it shows skeleton rows of the density's height, as many as fit the height. Without rows and without loading, the `empty` message shows, or `noResults` when a filter is active.

::component-preview{name="data-table-states"}
::

### Row events

`onRowClick`, `onRowContextmenu` and `onRowHover` are props (bind them as `@row-click` too), so a table knows when its rows are clickable: those rows get `tabindex="0"`, a pointer cursor and `data-clickable`, and fire on Enter and Space. A click on a control inside the row is not a row click, so buttons and inputs in cells keep working. The row keeps no role; give the same action to a control inside the row for keyboard and screen reader users.

## State

Every TanStack state slice is a `v-model:` on the component: `sorting`, `column-visibility`, `column-pinning`, `column-order`, `column-sizing`, `column-filters`, `global-filter`, `pagination`, and for the coming stage `row-selection`, `expanded`, `grouping`, `row-pinning`. A model you do not bind is local, and one you bind is the single source, so binding a model whose initial value is `undefined` works. `tableOptions.initialState` sets starting values for either.

## Known limits

- A mutation of `data` in place is not seen; pass a new array.
- Without `height`, `overflow="x"` clips the table in a container that never scrolls vertically, so a sticky header does not stick; use `overflow="visible"` for a header sticky to the page.
- Browsers lay out about sixteen million pixels of height; past that, paginate on the server. The table warns in development.
- A pinned column without a `size` takes TanStack's default of 150 pixels, with a warning in development.
- `maxHeight`, column resizing, selection, expanding, grouping, row pinning and infinite scroll are the next stages.

## Accessibility

The table carries `aria-rowcount` and every row `aria-rowindex`, counted over header, body and footer rows, so a screen reader announces "row 5001 of 10001" even while only a window of rows exists. Spacer row groups are hidden from assistive technology. A focused row stays mounted while it scrolls out of the window, so focus is not lost. The scroll area pads its scroll by the sticky header's height, so focusing a row never lands it under the header.

### Data attributes

The parts carry the [Table](/docs/components/table) slots, `table`, `table-header`, `table-row`, `table-head`, `table-cell`, `table-footer`, `table-caption` and `table-empty`, with the same attributes, plus these:

::data-slots
---
rows:
  - slot: data-table
    attributes: data-density, data-loading
    description: The root. Carries --table-thead-h and --table-tfoot-h, the measured header and footer heights.
  - slot: table-row-group
    attributes: data-index
    description: One tbody per row, the virtual item and the measured element.
  - slot: table-spacer
    description: A row group standing in for rows outside the window; hidden from assistive technology.
  - slot: table-filler
    description: The column taking the width left over when every column has a size.
  - slot: table-loading
    description: The header row holding the progress bar while loading.
  - slot: table-skeleton
    description: The body of skeleton rows while loading with no data.
  - slot: data-table-column-header
    attributes: data-sorted
    description: The sort button in a header.
  - slot: data-table-pagination
    description: The bar under the table.
