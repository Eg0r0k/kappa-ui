## Usage

```vue
<script setup lang="ts">
import { Accordion, AccordionContent, AccordionItem, AccordionTrigger } from '@/ui/accordion'
</script>

<template>
  <Accordion type="single">
    <AccordionItem value="shipping">
      <AccordionTrigger>How long does shipping take?</AccordionTrigger>
      <AccordionContent>Orders arrive three to five days after they ship.</AccordionContent>
    </AccordionItem>
  </Accordion>
</template>
```

`Accordion` is Reka UI's accordion with kappa-ui's styles. With `type="single"` one item is open at a time, and a second click on it closes it again (`collapsible` is on by default). Each trigger sits in a heading, and its chevron turns while the item is open. Height animates open and closed, and not at all under reduced motion.

### Find in page

A closed item keeps its content in the page, marked `hidden="until-found"`. The browser's find in page searches that text, and when it finds a match the item opens to show it. Links to a fragment inside a closed item open it the same way.

::component-preview{name="accordion-find"}
::

This is why `unmount-on-hide` is off by default, and what it costs:

- **Every item's content is mounted from the start.** For a list of questions that costs nothing. For items that hold heavy charts or tables, turn `unmount-on-hide` on, for the whole accordion or for one item.
- **Server rendering keeps working.** The closed items' text is in the HTML, so find in page and search engines see it. If someone finds a match before the page has hydrated, the browser opens the item on its own while Vue still thinks it is closed: the item shows, and the first click on its trigger has nothing to close.
- **Browser support.** Chromium since version 102 and Firefox since 139. Safari has it only in Technology Preview; there, and in any browser without it, the attribute acts as plain `hidden`: closed items are not searched, and everything else works as usual.

### Unmount on hide

With `unmount-on-hide`, a closed item's content leaves the page and mounts again when it opens. An item can override it either way; below, the glossary stays in the page so find in page still reaches it.

## Accessibility

Each trigger is a button inside a heading, with `aria-expanded` and `aria-controls` pointing at its panel, and each panel is a `region` labelled by its trigger.

::keyboard-table
---
rows:
  - keys: Tab
    description: Moves focus to the next trigger.
  - keys: Space
    description: Opens or closes the focused item.
  - keys: Enter
    description: Opens or closes the focused item.
  - keys: ArrowDown
    description: Moves focus to the next trigger, wrapping at the end.
  - keys: ArrowUp
    description: Moves focus to the previous trigger, wrapping at the start.
  - keys: Home
    description: Moves focus to the first trigger.
  - keys: End
    description: Moves focus to the last trigger.
---
::
