## Usage

```vue
<script setup lang="ts">
import { Checkbox } from '@/components/ui/checkbox'
import { Field, FieldLabel } from '@/components/ui/field'

const accepted = ref(false)
</script>

<template>
  <Field orientation="horizontal">
    <Checkbox v-model="accepted" />
    <FieldLabel>Accept terms and conditions</FieldLabel>
  </Field>
</template>
```

`Checkbox` is Reka UI's checkbox with kappa-ui's styles: a `<button role="checkbox">` that, inside a form and given a `name`, also submits a hidden native checkbox. Inside a [Field](/docs/components/field) it takes its `id`, description, error and state from it, and clicking the label toggles it. On its own, give it a name with `aria-label` or a [Label](/docs/components/label).

Its look follows Material's checkbox: a 2px outline that fills with `--primary` when checked, a check that draws itself in, and a circular layer behind the box, at the same opacities as every other [state](/docs/getting-started/theming#states-and-shape). The layer shows while the mouse is over the box itself and while the checkbox is pressed, including through its label; hovering the label alone leaves it off, although browsers count that as hovering the checkbox too. A checkbox followed by a label keeps enough space before it that the layer never runs into the text.

## Examples

### States

`v-model` is `true`, `false` or `'indeterminate'`. The third is for a checkbox that summarises others: some of them are checked, so it is neither. Screen readers announce it as "mixed". Clicking an indeterminate checkbox checks it.

::component-preview{name="checkbox-states"}
::

### Sizes

`size` runs from `xs`, 14px, to `xl`, 24px. `md`, the default, is Material's 18px. The circular state layer grows with the box.

::component-preview{name="checkbox-sizes"}
::

### Touch target

Even `xl` is well under the 48px Material recommends for anything tapped. `touch-target="expand"` grows the pressable area to 48px around the box without moving anything, so neighbours closer than that overlap. `wrapper` also reserves the space with a margin, as Material's `touch-target="wrapper"` does: the box moves in from the edge, and a label next to it moves along. Both areas are outlined below.

::component-preview{name="checkbox-touch-target"}
::

### Description

Put the label and its description in a `FieldContent`. The checkbox lines up with the first line of the label, and the description is added to the checkbox's `aria-describedby`.

### Group

`CheckboxGroup` binds one array: each checkbox adds its `value` while it is checked. Name the group with a [FieldSet](/docs/components/field) and its legend. An error for the whole group, such as nothing being checked, goes on that fieldset: its `invalid` marks the group and turns every checkbox in it red.

::component-preview{name="checkbox-group"}
::

Reka UI makes a group a single tab stop that arrow keys move within. kappa-ui turns that off, so each checkbox is a tab stop of its own, which is how checkboxes behave everywhere else; set `roving-focus` to get Reka UI's behaviour back.

`variant` and `orientation` lay the options out as cards, one bordered list or a table, in a column or a row; they come from [Choice Group](/docs/components/choice-group).
