## Usage

Install the service once, next to the app:

```ts
// main.ts
import { createApp } from 'vue'

import { createToaster } from '@/ui/toast'
import App from './App.vue'

createApp(App).use(createToaster()).mount('#app')
```

In Nuxt, do the same from a plugin:

```ts
// plugins/toaster.ts
import { createToaster } from '@/ui/toast'

export default defineNuxtPlugin((nuxtApp) => {
  nuxtApp.vueApp.use(createToaster())
})
```

Put a `Toaster` in the root component, and add toasts from anywhere below it:

```vue
<!-- App.vue -->
<script setup lang="ts">
import { Toaster } from '@/ui/toast'
</script>

<template>
  <RouterView />
  <Toaster />
</template>
```

```vue
<script setup lang="ts">
import { Button } from '@/ui/button'
import { useToast } from '@/ui/toast'

const toast = useToast()
</script>

<template>
  <Button @click="toast.add({ title: 'Saved', color: 'success' })">Save</Button>
</template>
```

Each app gets its own list of toasts, so on the server one request never sees another's. Outside components — a router guard, an HTTP interceptor, a store — call the object `createToaster()` returned.

`useToast()` returns:

| Method | Description |
|---|---|
| `add(toast)` | Shows a toast and returns its id. With the id of a toast already shown, updates that one instead. |
| `update(id, toast)` | Changes the fields given and keeps the rest. A closing toast opens again. |
| `remove(id)` | Closes the toast; it leaves the list once its exit animation ends. |
| `clear(group?)` | Closes the toasts of one group, or every toast. |
| `promise(promise, { loading, success, error })` | Shows `loading` until the promise settles, then updates the same toast with `success` or `error` — a toast, or a function of the result that returns one. Success is `success` coloured and error `destructive` unless they say otherwise. Returns the id. |
| `toasts` | The current toasts, open and closing. |

A toast takes:

| Field | Description |
|---|---|
| `id` | Your own id, to update the toast or keep it from showing twice. |
| `group` | The `Toaster` that shows it. |
| `title`, `description` | The text. |
| `color` | `neutral` (the default), `primary`, `success`, `warning` or `destructive`. It colours the icon and the progress bar. |
| `icon` | A component, or `false` for none. Each colour but `neutral` has a default. |
| `loading` | Shows a spinner instead of the icon and keeps the toast open until an update turns it off. |
| `duration` | Milliseconds to stay open, `Infinity` until closed. The toaster's `duration` otherwise. |
| `close` | `false` hides the close button. |
| `actions` | Buttons, each `{ label, altText?, onClick? }`. Pressing one closes the toast. |
| `background` | Announce it politely, for toasts that are not the result of what the user just did. |
| `data` | Fields of your own, for the `toast` slot. |
| `onClose` | Called once the toast is gone for good — not when it is closed and added again. |

## Accessibility

Toasts sit in a region labelled "Notifications (F8)"; F8 moves focus to them. Each toast is announced when it appears, assertively unless it is a `background` one. The timers pause while the pointer or focus is on the toasts and while the window is in the background. Escape closes the toast that has focus and leaves the rest — pressing it elsewhere, to close a dialog for instance, keeps them. `altText` on an action tells screen reader users another way to do it, since the toast may close before they reach the button.
