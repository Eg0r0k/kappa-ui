## Usage

```vue
<script setup lang="ts">
import { Input } from '@/components/ui/input'

const email = ref('')
</script>

<template>
  <Input v-model="email" type="email" placeholder="Email" />
</template>
```

Every attribute goes to the `<input>` itself, so `type`, `name`, `autocomplete`, `inputmode` and the native validation attributes work as they do in HTML. Inside a [Field](/docs/components/field) the input takes its `id`, description, error and state from it; on its own, give it an accessible name with a [Label](/docs/components/label) or `aria-label`.

Text is 16px on small screens and 14px from 768px up. Below 16px, iOS zooms the page into an input when it takes focus.

A label that floats inside the input is its own component, [Input Floating](/docs/components/input-floating).

## Examples

### Variants

`outline` draws a border. `soft` swaps the border for a tinted surface. `filled` follows Material's filled text field: a tinted surface, square bottom corners and a line underneath. `ghost` shows nothing until it is hovered or has focus, for text edited in place, such as a title. `subtle` puts the border on the tinted surface. In all five, focus draws a 2px line in `--primary`.

`soft` and `ghost` have no visible edge until they have focus: the tint is barely lighter or darker than the page, well short of the 3:1 that WCAG asks of a control's boundary. Use them where the surroundings already say "this is a field", such as a search box in a toolbar, and `outline`, `filled` or `subtle` in forms.

### Sizes

`size` runs from `xs`, 28px, to `xl`, 48px. `sm`, `lg` and `xl` are as tall as the buttons of the same name and `md`, the default, as the default button, so an input and a button line up in a row, and so does an [Input Floating](/docs/components/input-floating) in `outline`. From 768px up, `xs` sets 12px text and `xl` 16px; below that every size keeps 16px.

::component-preview{name="input-sizes"}
::

### States

A disabled input takes its colours from `--foreground`, like a disabled button. An invalid one turns its line `--destructive`. It shows as invalid in two cases: when `aria-invalid` is set, by a [Field](/docs/components/field) or by hand, and when the browser's own validation fails after the user has interacted with it, through `:user-invalid`, so `required` or `type="email"` work without any script and an empty form does not start out red.
