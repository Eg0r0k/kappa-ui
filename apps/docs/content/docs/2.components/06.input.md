## Usage

```vue
<script setup lang="ts">
import { Input } from '@/components/ui/input'

const email = ref('')
</script>

<template>
  <Input v-model="email" type="email" placeholder="Email" />
</template>
```
Works like a native `<input>`: every attribute goes straight to it.

Inside a [Field](/docs/components/field) it gets its label, error and state for free. On its own, give it a [Label](/docs/components/label) or `aria-label`.

Text is 16px on phones and 14px on desktop. Any smaller, and iOS zooms in on focus.

Want the label inside the input? That's [Input Floating](/docs/components/input-floating).

## Examples

### Variants

- `outline`: a border
- `soft`: a tinted surface, no border
- `subtle`: a tinted surface with a border
- `filled`: a tinted surface with a line underneath
- `ghost`: invisible until hover or focus, for editing in place (like a title)

`soft` and `ghost` barely show where the field is. Fine for a search box in a toolbar, but in forms use `outline`, `filled` or `subtle`.
::component-preview{name="input-variants"}
::

### Sizes

`size` runs from `xs`, 28px, to `xl`, 48px. `sm`, `lg` and `xl` are as tall as the buttons of the same name and `md`, the default, as the default button, so an input and a button line up in a row, and so does an [Input Floating](/docs/components/input-floating) in `outline`. From 768px up, `xs` sets 12px text and `xl` 16px; below that every size keeps 16px.

::component-preview{name="input-sizes"}
::

### States

A disabled input takes its colours from `--foreground`, like a disabled button. An invalid one turns its line `--destructive`. It shows as invalid in two cases: when `aria-invalid` is set, by a [Field](/docs/components/field) or by hand, and when the browser's own validation fails after the user has interacted with it, through `:user-invalid`, so `required` or `type="email"` work without any script and an empty form does not start out red.
