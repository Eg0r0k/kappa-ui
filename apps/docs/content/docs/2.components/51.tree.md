## Usage

```vue
<script setup lang="ts">
import { Tree, TreeItem, TreeItemLabel, TreeItemToggle } from '@/components/ui/tree'

const files = [
  {
    id: 'src',
    label: 'src',
    children: [
      { id: 'src/App.vue', label: 'App.vue' },
      { id: 'src/main.ts', label: 'main.ts' },
    ],
  },
  { id: 'package.json', label: 'package.json' },
]

const opened = shallowRef()
</script>

<template>
  <Tree v-slot="{ items }" v-model="opened" :items="files" aria-label="Files">
    <TreeItem v-for="row in items" :key="row._id" :item="row">
      <TreeItemToggle />
      <TreeItemLabel>{{ row.value.label }}</TreeItemLabel>
    </TreeItem>
  </Tree>
</template>
```

Pass the nodes as `items`. `Tree` flattens what's open into `items`, and you draw each one as a `TreeItem`: a `TreeItemToggle` for the chevron, a `TreeItemIcon`, a `TreeItemLabel`, or anything else. The row's state (`expanded`, `selected`, `checked`, `level` and more) comes with its slot. A node with `children` is a folder; `children: []` is a folder that is empty or not loaded yet. `disabled`, `loading` and `defaultExpanded` do what they say.

`v-model` holds the node you passed in, not a copy, so `opened === files[1]` holds. `v-model:expanded` holds the keys of the open nodes.

::callout{type="warning"}
**Every node needs a unique key.** It's `id`, then `value`, then `label` by default; set `getKey` for anything else. Two nodes with one key open and select together, and the tree warns in development. For files, the path makes a good key: two folders can both be called `src`.
::

Width classes and `aria-label` go straight on `Tree`. Or put it in a [Field](/docs/components/field).

## Examples

### Sizes

`size` runs from `xs` to `xl`. Rows are 28, 32, 36, 40 and 48px tall, as tall as a [Listbox](/docs/components/listbox) option or a [Menu](/docs/components/menu) item of the same size. Each level indents by an icon and a gap, so a child's chevron sits under its parent's icon.

::component-preview{name="tree-sizes"}
::

### Variants

`ghost`, the default, draws no frame: trees mostly live in sidebars and cards that have one. `outline` draws a frame like Listbox's.

::component-preview{name="tree-variants"}
::

### Multiple

With `multiple`, `v-model` is an array. Each click adds or removes a node by default. With `selection-behavior="replace"`, it works like a file manager: a click picks one node, Ctrl or ⌘-click adds to it, and Shift-click or Shift + arrows select a range.

::component-preview{name="tree-multiple"}
::

### Checkboxes

`checkbox` is checkbox mode: rows use `aria-checked`, and a `TreeItemCheckbox` in each row shows the state. Checking a folder checks everything under it, and a folder shows checked, unchecked or indeterminate from what's inside. Disabled nodes keep their state, so the locked permission below stays off whatever its folder does.

`v-model` holds every checked node, folders that are fully checked included. A list of the checked leaves is one `filter` away. Echo a model back with only the leaves, or only a folder, and the tree reads it the same.

Add `multiple` too, so `v-model` is typed as an array. `:cascade="false"` checks nodes one by one.

::component-preview{name="tree-checkbox"}
::

### Form

In a required field the tree gets `aria-required`. When the field is invalid, it gets `aria-invalid` and `--destructive` checkboxes, plus a `--destructive` frame with `outline`. Most forms want keys, not nodes: map them in a computed. Here [vee-validate](https://vee-validate.logaretm.com) and [zod](https://zod.dev) check that something is granted. Press Save without checking anything.

::component-preview{name="tree-field"}
::

Posting a plain form? `name` adds a hidden input per selected key. Add `required` too, and the form won't submit with nothing selected; the tree takes focus instead.

### Select without expanding

By default a click both selects a row and opens it, and a click on the chevron only opens it. With `:toggle-on-click="false"`, a click only selects; the chevron or a double click opens the folder. Arrow keys work the same either way.

::component-preview{name="tree-mail-folders"}
::

### Loading children

Give an unloaded folder `children: []`: it gets a chevron and `aria-expanded`. Fetch in `@update:expanded`, set `loading: true` on the node meanwhile for a spinner and `aria-busy`, then replace the node with its children.

::component-preview{name="tree-lazy"}
::

### Expand, collapse and reveal

The tree exposes `expandAll()`, `collapseAll()` and `scrollToKey(key)`. To reveal a node, say the page the router is on, add `getAncestorKeys(items, key)` to `v-model:expanded`. Selecting a hidden node works without it.

::component-preview{name="tree-reveal"}
::

### Filtering

Filter `items` yourself: keep the matches and the folders leading to them, and open those folders. The tree only renders what it gets.

::component-preview{name="tree-filter"}
::

### Custom rows

A row is whatever you put in `TreeItem`. Its slot gets the node and its state, so the icon can follow `expanded` and a status can follow the node.

::component-preview{name="tree-git-status"}
::

Keep buttons out of rows: a row is one focusable item, so the keyboard can't reach a button inside it. Put actions in a context menu.

### Composition

Rows hold any content: an Avatar, two lines of text, a badge.

::component-preview{name="tree-composition"}
::

### Context menu

Put a [Menu](/docs/components/menu) with `context-menu` around the tree and find the row from the `contextmenu` event's target: rows carry `data-key`. Shift+F10 and the context menu key open it on the focused row. A field inside a row keeps its keys, and `@click.stop` keeps a click in it from selecting the row.

::component-preview{name="tree-context-menu"}
::

### Virtualization

Put a `TreeVirtualizer` in the tree instead of the rows, and only the rows near the view are rendered: it hands you one `item` at a time. The tree scrolls itself, so make it a `div` (`as="div"`) and give it a height; it warns in development when it has none. Rows get a fixed height, read from `--tree-item-height`. Typeahead can only match rows in the page, so `text-content` tells it each node's text, its `label` by default.

::component-preview{name="tree-virtual"}
::

### Disabled

A disabled node can't be selected, and the arrow keys skip it. A disabled tree dims every row and leaves the tab order.

::component-preview{name="tree-disabled"}
::

## Known limits

Tree is built on Reka UI's, which is still [alpha](https://github.com/unovue/reka-ui/issues/2789). Kappa keeps the selection itself, which works around a few of its issues. These remain:

- No open and close animation: rows render as a flat list, so there's no subtree to animate ([reka-ui#1561](https://github.com/unovue/reka-ui/issues/1561)). New rows fade in.
- A virtualized tree has rows of one fixed height ([reka-ui#1266](https://github.com/unovue/reka-ui/issues/1266)), and it has to be the scroller, so it can't sit in a [ScrollArea](/docs/components/scroll-area). With `outline`, the edge fade masks the frame too: put a ghost tree in a framed box, as above.
- `getChildren` can't be async ([reka-ui#1379](https://github.com/unovue/reka-ui/issues/1379)); load children as shown above.
- No `role="treegrid"` ([reka-ui#1866](https://github.com/unovue/reka-ui/issues/1866)). For a tree with columns, use [DataTable](/docs/components/data-table)'s expanding rows.
- No drag and drop.
- A disabled folder can't be opened by the user. Open it with `v-model:expanded`.
- Row clicks don't reach click listeners above the tree. Use `@select`, or `contextmenu` for menus.
- Typeahead matches a row's whole text, everything after the label included. In a virtualized tree it matches `TreeVirtualizer`'s `text-content`.
- Enter, and outside a virtualized tree the arrow keys, Home, End, PageUp and PageDown, stop at the row, so a `@keydown` listener on the tree doesn't hear them. That's what keeps typeahead working right after them. Escape and Tab go through.
- Arrow keys don't wrap from the last row to the first. Reka UI 2.11 adds `loop`, but the tree supports 2.10 too.

`Tree` sets these from `size`, and rows read them. Override one with a class on `Tree`.

::css-vars

  - name: --tree-item-px
    default: var(--control-padding-md)
    description: A row's side padding.
  - name: --tree-item-py
    default: 8px
    description: The padding above and below a row's text.

## Accessibility

The tree follows the [APG tree view pattern](https://www.w3.org/WAI/ARIA/apg/patterns/treeview/). Rows are a flat list of `treeitem`s with `aria-level`, `aria-setsize` and `aria-posinset`, so screen readers announce "level 2, 3 of 5" as in a nested tree. A folder has `aria-expanded`, a loading one `aria-busy`.

- One tab stop. Tab enters on the selected row, or the last focused one.
- In a single-select tree only the selected row has `aria-selected`; with `multiple`, every row has it, `true` or `false`. Checkbox mode uses `aria-checked`, `mixed` for a half-checked folder.
- The chevron and the checkbox are drawn, not buttons, and hidden from screen readers: the row is the control.
- Name the tree with `aria-label`, or put it in a Field.

### Keyboard

Left and Right swap in a right-to-left tree.

::keyboard-table
---
rows:
  - keys: ArrowDown / ArrowUp
    description: Moves to the next or previous visible row, skipping disabled ones.
  - keys: ArrowRight
    description: Opens a closed folder, or moves into an open one.
  - keys: ArrowLeft
    description: Closes an open folder, or moves to the parent.
  - keys: Home / End
    description: Moves to the first or last visible row. PageUp and PageDown do the same.
  - keys: Enter / Space
    description: Selects the row, or checks it in checkbox mode. Enter doesn't open folders. A Space typed mid-name searches on instead.
  - keys: "*"
    description: Opens every folder next to the focused row.
  - keys: Shift + ArrowDown / ArrowUp
    description: Extends the selection, with `multiple` and `selection-behavior="replace"`.
  - keys: A–Z
    description: Moves to the next row starting with the letters typed, right after an arrow key or a Space too.
---
::
