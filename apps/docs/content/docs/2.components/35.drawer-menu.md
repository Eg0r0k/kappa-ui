## Usage

```vue
<script setup lang="ts">
import { Button } from '@/components/ui/button'
import { Drawer, DrawerContent, DrawerHeader, DrawerTitle, DrawerTrigger } from '@/components/ui/drawer'
import { DrawerMenu, DrawerMenuItem, DrawerMenuSeparator } from '@/components/ui/drawer-menu'
</script>

<template>
  <Drawer>
    <DrawerTrigger as-child>
      <Button>Actions</Button>
    </DrawerTrigger>
    <DrawerContent>
      <DrawerHeader>
        <DrawerTitle>report.pdf</DrawerTitle>
      </DrawerHeader>
      <DrawerMenu>
        <DrawerMenuItem>Rename</DrawerMenuItem>
        <DrawerMenuSeparator />
        <DrawerMenuItem variant="destructive">Delete</DrawerMenuItem>
      </DrawerMenu>
    </DrawerContent>
  </Drawer>
</template>
```

Put `DrawerMenu` in `DrawerContent`, after the header. The drawer's title names the menu.

Picking an item closes the drawer. To keep it open, prevent the item's `select` event.

The parts take the same props and events as [Menu](/docs/components/menu)'s, so one menu can render as either. See [Responsive menu](#responsive-menu).

## Examples

### Selection

Checkbox items and radio items close the drawer like any other item; `@select.prevent` keeps it open while the user changes several of them.

::component-preview{name="drawer-menu-selection"}
::

### Submenus

A `DrawerMenuSub` drills down: its content replaces the list, slides in from the end and starts with a back row named after its trigger. `textValue` on the trigger names the back row instead of the trigger's text.

::component-preview{name="drawer-menu-submenus"}
::

### Sizes

`size` takes Menu's names, `xs` to `xl`, and reads the same [control scale](/docs/getting-started/sizing), plus room for a thumb: a row is 8px taller than a Menu item of its size at `xs` and `sm`, 12px at `md` and 16px at `lg` and `xl`, with a little more padding and, from `md` up, a larger icon. Rows come out at 36, 40, 48 (the default), 56 and 64px. Retune the scale and the drawer follows.

From `sm` up, every row is large enough to tap. `xs` packs a long list tighter.

::component-preview{name="drawer-menu-sizes"}
::

### Responsive menu

Desktop gets a dropdown or a right-click menu, phones get a drawer. Write the items once against a set of parts, and pass in the set that fits:

```ts
// menu-parts.ts
export interface MenuPartSet {
  Item: Component
  Separator: Component
  Label: Component
  Group: Component
  Sub: Component
  SubTrigger: Component
  SubContent: Component
  RadioGroup: Component
  RadioItem: Component
  CheckboxItem: Component
}

export const menuParts: MenuPartSet = { Item: MenuItem, Sub: MenuSub /* … */ }
export const sheetParts: MenuPartSet = { Item: DrawerMenuItem, Sub: DrawerMenuSub /* … */ }
```

In the demo, the same items render as a [Menu](/docs/components/menu) next to the ⋯ button and on right-click, and as a `DrawerMenu` below 768px.

Keep checkbox and radio state outside the menu, so it survives the switch.

::component-preview{name="drawer-menu-responsive"}
::

### Custom motion

Every panel carries `data-motion` while it slides, `from-end` or `from-start` when it arrives and `to-start` or `to-end` when it leaves, and `data-state` (`active` or `inactive`). A leaving panel stays on screen until its own animation or transition ends, so any CSS on those attributes replaces the slide: keyframes on `data-motion`, or a transition on `data-state` with `@starting-style` for the arriving panel.

## Accessibility

Each panel is a `menu`: the root one labelled by the drawer's title, a submenu labelled by its trigger, which carries `aria-haspopup`, `aria-expanded` and `aria-controls`. Checkbox and radio items are `menuitemcheckbox` and `menuitemradio` with `aria-checked`. Only the visible panel can be focused; the others are `hidden` and `inert`.

::keyboard-table
---
rows:
  - keys: ArrowDown
    description: Moves focus to the next item.
  - keys: ArrowUp
    description: Moves focus to the previous item.
  - keys: Home
    description: Moves focus to the first item.
  - keys: End
    description: Moves focus to the last item.
  - keys: Enter
    description: Chooses the focused item, or opens its submenu.
  - keys: Space
    description: Chooses the focused item, or opens its submenu.
  - keys: ArrowRight
    description: Opens the focused submenu (ArrowLeft in right-to-left text).
  - keys: ArrowLeft
    description: Goes back from a submenu (ArrowRight in right-to-left text), unless focus is in a text field.
  - keys: Backspace
    description: Goes back from a submenu, unless focus is in a text field.
  - keys: Escape
    description: Goes back from a submenu; at the top level closes the drawer.
---
