## Usage

```vue
<script setup lang="ts">
import { createDataTableColumnHelper, DataTable } from '@/components/ui/data-table'

type Payment = { id: string; email: string; amount: number }

const helper = createDataTableColumnHelper<Payment>()
const columns = helper.columns([
  helper.accessor('email', { header: 'Email' }),
  helper.accessor('amount', { header: 'Amount', size: 120, meta: { align: 'end' } }),
])
</script>

<template>
  <DataTable :data="payments" :columns="columns" :get-row-id="(row) => row.id" sortable />
</template>
```

It runs on [TanStack Table v9](https://tanstack.com/table/latest), which is why it installs `@tanstack/vue-table`. Build columns with `createDataTableColumnHelper`: it keeps columns, slots and state fully typed.

::callout{type="warning"}
Two rules that save you a debugging session:

- **Always pass `getRowId`.** Without it, a row's id is its index, and selected or expanded rows jump around after sorting.
- **Replace `data` with a new array.** A `push` into the old one goes unnoticed.
::

It's fast by design: cells are plain elements with [Table](/docs/components/table)'s classes, not a component each. A thousand cells are a thousand elements, not a thousand component instances. Borders, `--table-row-bg` and the pinned-column shadow work just like in Table.

## Examples

### Columns and slots

A column's `header`, `cell` and `footer` can be a string, a function or a component. To take over in the template, use a slot: `cell-<id>`, `header-<id>` or `footer-<id>`. It gets the TanStack context: `getValue`, `row`, `column` and `table`.

Column `meta` takes:

- `align`: `start`, `center` or `end`
- `truncate`: cuts long text with an ellipsis (needs a fixed layout)
- `class`, `style`: for the `th` and `td`, as a value or a function of the context

The `toolbar` slot renders above the table, outside the scroll.

::component-preview{name="data-table-slots"}
::

### Sorting

`sortable` gives every sortable column a header button that cycles ascending -> descending -> off. Shift-click adds a column to the sort.

- `{ multi: false }`: one column at a time
- `{ removable: false }`: no "off" step
- `enableSorting: false` on a column: leave it out

`v-model:sorting` holds `[{ id, desc }]`.

`sortFn` and `filterFn` take your own function, `auto` to pick one by the column's values, or the name of a built-in:

- sorting: `alphanumeric`, `alphanumericCaseSensitive`, `text`, `textCaseSensitive`, `datetime`, `basic`
- filtering: `includesString`, `includesStringSensitive`, `equalsString`, `equals`, `weakEquals`, `inNumberRange`, `inDateRange`, `arrIncludes`, `arrIncludesAll`, `arrIncludesSome`

Need another TanStack built-in? Register it in `dataTableFeatures` in your copy.

### Height, sticky parts and virtualization

`height` puts the table in a [ScrollArea](/docs/components/scroll-area). The sticky header, the footer and pinned columns all share that one scroller. `sticky` sticks the header, the footer or both.

`virtualize` renders only the rows near the view: `true` always, `"auto"` from 200 rows, or an object with options. Rows keep a fixed height set by the density. For rows of different heights, add `measure: true`.

It stays a real table, so `colspan`, sticky parts and screen reader row counts keep working.

::callout
Virtualization has a price: Ctrl+F and select-all only see the rendered rows, and printing prints only what's on screen. Turn it on when you actually need it. `scrollToRow` and `scrollToIndex` reach any row.
::

::component-preview{name="data-table-virtualized"}
::

### Pinned columns

`v-model:column-pinning` takes `{ start: [...ids], end: [...ids] }`.

Give pinned columns a `size`, since their offsets are computed from the widths. If every column has a size and the table is wider than their sum, an extra filler column takes the rest. The outermost pinned column casts a shadow while content can scroll under it.

::component-preview{name="data-table-pinned"}
::

### Pagination

`paginate` splits the rows into pages and adds `DataTablePagination` under the table. `v-model:pagination` holds `{ pageIndex, pageSize }`. When the rows change, it goes back to the first page.

::component-preview{name="data-table-pagination"}
::

### Server mode

Data lives on the server? `manual` hands the work to you: all of it, or per feature with `{ sorting, filtering, pagination, expanding }`. The table shows `data` as is and reports the state through the models.

- Pass `rowCount`, so it knows how many pages there are. Without it, the bar shows only Previous and Next.
- The page doesn't reset on its own here: do it yourself when filters change.

::component-preview{name="data-table-server"}
::

### Loading and empty

`loading` shows a progress bar under the header, and the rows you have stay in place. No rows yet? Skeleton rows fill the height instead.

No rows and not loading: the `empty` message shows, or `noResults` when a filter is on.

::component-preview{name="data-table-states"}
::

### Row events

Pass `onRowClick`, `onRowContextmenu` or `onRowHover` (or `@row-click` and friends), and rows become clickable: focusable, with a pointer cursor, and they fire on Enter and Space too. Clicks on buttons and inputs inside a row don't count as row clicks.

A clickable row isn't a button for screen readers, so put the same action on a control inside the row too.

### Row actions

Add a display column with a `cell-<id>` slot. Inside, wrap an icon button in `MenuTrigger` with `as-child`, and the [Menu](/docs/components/menu) next to it opens from that button. `row.original` is right there for the items, and a click on the button isn't a row click.

::component-preview{name="data-table-actions"}
::

### Selection

`selection` adds a checkbox column:

- `true` or `"multiple"`: many rows
- `"single"`: one row
- an object, `{ mode, column, enableRowSelection, selectAll }`: `column: false` hides the column, and `enableRowSelection` decides per row

`v-model:row-selection` holds `{ [id]: true }`. Shift-click selects a range.

Need to know where a change came from? `update:rowSelection` gets a second argument, `{ source }`: `header`, `row`, `range` or `imperative`.

**Select all, Gmail style.** With pagination, the header checkbox selects the current page, and a banner offers to select the rest. `v-model:select-all` goes `none` -> `page` -> `all`.

In `all`, every row on every page counts as selected, and the model stores only the exceptions, as `{ [id]: false }`. For the request to your server, `getSelection()` returns `{ mode, ids, excluded, count }`.

- Unchecking a row in `page` drops back to `none`.
- In server mode, a sort or filter change drops `all` back to `none`: the rows the user agreed to are gone.

`selectAllLabels` changes the banner text, and the `select-all-banner` slot replaces the banner entirely. `selectAll: false` turns it off. Without pagination, the header checkbox just selects every filtered row, with no banner.

::component-preview{name="data-table-selection"}
::

### Expanding and trees

`expandable` adds a chevron column. Add an `expanded` slot, and each row opens a detail row under it. Hover and selection tint both together. With virtualization, `measure` turns on by itself.

`v-model:expanded` holds `{ [id]: true }`, or `true` for every row. `table.toggleAllRowsExpanded()` toggles them all, and `getRowCanExpand` decides per row.

::component-preview{name="data-table-expanding"}
::

For a tree, pass `getSubRows`: children render as regular rows, indented by depth. They paginate with the rest; `paginateExpandedRows: false` keeps them on their parent's page.

::component-preview{name="data-table-tree"}
::

### Grouping

`groupable` with `v-model:grouping` groups rows by column ids, in order. Grouped columns move to the front.

A group row shows a toggle, the value and the row count. Other columns show their `aggregatedCell`, computed by the column's `aggregationFn`: `sum`, `min`, `max`, `extent`, `mean`, `median`, `unique`, `uniqueCount`, `count`, `first`, `last`, or your own function.

Groups open and close through the `expanded` model, like tree rows.

::component-preview{name="data-table-grouping"}
::

### Pinned rows

`v-model:row-pinning` takes `{ top: [...ids], bottom: [...ids] }`. Pinned rows stick under the header and above the footer, never get virtualized away, and stay even when a filter hides them. From a cell, `row.pin('top')`, `row.pin('bottom')` and `row.pin(false)` toggle them.

::component-preview{name="data-table-pinned-rows"}
::

### Infinite scroll

Doomscrolling, table edition. `onLoadMore` (or `@load-more`) loads more rows as you near an edge. It gets `{ direction, index }`, with `index` starting at 1, and should resolve once the new rows are in `data`.

Out of rows? Resolve `'stop'`. To pause and resume, use `hasMore`: `false`, or `{ top, bottom }` per edge.

`loadMore` options:

- `direction`: `bottom`, `top` or `both`
- `threshold`: how close to the edge to start loading; rows with virtualization (the overscan by default), pixels without it (200 by default)
- `initialFill`: keep loading until the table overflows

Loading at the top keeps your reading position. The `loadingMore` slot shows at the loading edge (a spinner by default), and `endOfData` shows once there's nothing left. In server mode, a sort or filter change restarts `index` at 1.

It watches the table's own scroll area, or the nearest scrolling parent, or the window, and runs on [`useInfiniteScroll`](/docs/components/infinite-scroll). Don't combine it with server-side pagination: the table warns in development.

::component-preview{name="data-table-infinite"}
::

## State

Every TanStack state slice is a `v-model:` on the component: `sorting`, `column-visibility`, `column-pinning`, `column-order`, `column-sizing`, `column-filters`, `global-filter`, `pagination`, `row-selection`, `expanded`, `grouping` and `row-pinning`, plus the table's own `select-all`.

Don't bind a model, and the table keeps it inside. Bind it, and yours becomes the only source, even if it starts as `undefined`. Starting values for either go in `tableOptions.initialState`.

## Known limits

- Mutating `data` in place goes unnoticed. Pass a new array.
- Without `height`, `overflow="x"` breaks the sticky header. For a header that sticks to the page, use `overflow="visible"`.
- Browsers can lay out about 16 million pixels of height. Past that, paginate on the server. The table warns in development.
- A pinned column without a `size` gets 150px and a warning in development.
- There's no `maxHeight` yet, so give the table a `height`. Column resizing is coming next.

## Accessibility

Screen readers hear "row 5001 of 10001" even when only a handful of rows exist in the DOM: the table has `aria-rowcount`, and every row has `aria-rowindex`.

- A focused row stays mounted when it scrolls out of view, so focus isn't lost.
- Focused rows never hide under the sticky header or pinned rows.
- Checkboxes and chevrons are labelled buttons, and the select-all banner is announced.
- Spacers and loading rows are hidden from screen readers.
