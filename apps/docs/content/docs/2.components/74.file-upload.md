## Usage

```vue
<script setup lang="ts">
import { FileUpload } from '@/components/ui/file-upload'

const photo = ref<File | null>(null)
</script>

<template>
  <FileUpload v-model="photo" accept="image/*" label="Drop your image here" />
</template>
```

`v-model` is a `File`, or `null` once it's cleared. Add `multiple` and it's a `File[]` instead, `[]` when empty. Every change hands you a new value, so watchers and form libraries notice it.

Three ways in: click the zone for the file dialog, drop files on it, or paste them with Ctrl+V while focus is inside. All three go through the same checks.

Give it a `name`, and the files submit with the form like a plain `<input type="file">`. The hidden input always holds exactly the files on screen, including the ones that were dropped or removed, so `FormData` and `required` never disagree with what the user sees.

## Examples

### Multiple

With `multiple`, new files join the list instead of replacing the old one. A file that is already there, same name, size and date, is turned away as a `duplicate`.

::component-preview{name="file-upload-multiple"}
::

### Rejected files

`accept`, `max-size` and `max-files` keep files out of the model. The dialog's own filter is only a hint: the user can pick "All files", and a drop or a paste ignores it. So the component checks every file itself. `accept` takes MIME types, `type/*` and `.ext`, the same list the input does.

Whatever doesn't get in comes back through `reject`, once per pick, drop or paste, as `{ file, reason }`. The reason is `type`, `size`, `count`, `duplicate` or `directory` (a folder dropped in). Say why, or the user is left wondering where their file went.

::component-preview{name="file-upload-rejections"}
::

### Button

`mode="button"` swaps the zone for a [Button](/docs/components/button) that still takes drops. Files are listed under it. With no `label`, it's a square icon button: give it an `aria-label` or a FieldLabel.

With `layout="grid"` and one file, the picked image fills the button and Remove sits on its corner, which makes a quick photo picker.

::component-preview{name="file-upload-button"}
::

### Layouts

`layout="list"` shows each file as a row with a name and a size; `grid` as a tile with its picture. Tiles without a picture keep their name, since a grid of identical document icons tells nobody anything.

`position="inside"` moves the files into the frame, and then the whole frame takes drops.

::component-preview{name="file-upload-layouts"}
::

### Variants

The frame comes `outline` (dashed), `soft` (filled) or `subtle` (both). In `button` mode, `variant` goes to the Button.

::component-preview{name="file-upload-variants"}
::

### Sizes

`xs` to `xl` on the [control scale](/docs/getting-started/sizing). The icon circle is a control's height, the glyph a control's icon, and the list rows and Remove buttons scale with them. The zone is as tall as its content; for a taller one, set a height on it with `class="*:data-[slot=file-upload-dropzone]:min-h-48"`.

::component-preview{name="file-upload-sizes"}
::

### Field

Inside a [Field](/docs/components/field) the trigger takes the field's `id`, so clicking the label opens the dialog. It also takes the description, the error and the field's invalid, disabled and required state. Press Apply without a file.

::component-preview{name="file-upload-field"}
::

### Form validation

Bind `v-model` to a Formisch field and let a Valibot schema check the files: `v.file()` for one, `v.array(v.file())` for many, with `v.mimeType()` and `v.maxSize()`. A schema error on one file has a path like `['floorPlans', 1]`; show it in that file's `file-size` slot. Formisch focuses the first invalid field on submit, so pass it the exposed `triggerRef`, not the component.

The built-in checks run first. Leave `max-size` off if the schema should own that message.

::component-preview{name="file-upload-form"}
::

### Upload progress

The component never uploads anything; it holds files. To upload as soon as files arrive, watch the model, start an upload for each new file, and draw its progress in the `file-size` slot. Removing a file is the cancel button.

::component-preview{name="file-upload-progress"}
::

### Existing files

The model holds `File`s only, so a photo that's already on the server can't go in it. Show it yourself while the model is empty. Here the default slot replaces the zone with an [Avatar](/docs/components/avatar) and two buttons, and spreads `triggerAttrs` on Change so it takes the field's label. Drops on the avatar still count.

::component-preview{name="file-upload-avatar"}
::

### Custom trigger

With `:interactive="false"` the zone is plain content and only your own button opens the dialog: call `open` from the `actions` slot and spread `triggerAttrs` on it. `files-bottom` takes extra actions such as Remove all.

::component-preview{name="file-upload-custom"}
::

### Drop anywhere

A drop outside the zone opens the file in the browser, and the component doesn't touch the page to stop that. For a page-wide drop, listen on `window` yourself, call `preventDefault` on `dragover` and `drop`, and hand the files to the exposed `addFiles`, which runs the same checks. Skip a `drop` whose default is already prevented: the component took that one.

::component-preview{name="file-upload-page-drop"}
::

## Accessibility

The trigger is a real `<button type="button">`, so it never submits a form, and Enter and Space work without any key handling of ours. It holds only text and an icon. The list, its Remove buttons and the hidden input sit next to it, not inside it, because anything interactive inside a button disappears for screen readers.

Each Remove button is labelled "Remove" and the file name. After a removal, focus moves to the next file's Remove button, then the previous one, then the trigger, so removing several files in a row is a few presses of Enter.

The hidden input is `aria-hidden` and out of the tab order. When a `required` upload is empty, the browser focuses it to show its message; the frame shows that focus, and Tab moves on to the trigger.

::keyboard-table

## Known limits

- Files only. A file already on the server can't sit in the model; see [Existing files](#existing-files). Nuxt UI is working out a shape for this in [nuxt/ui#6927](https://github.com/nuxt/ui/pull/6927); widening the model later won't break yours.
- Nothing is announced when files are added, removed or rejected, and the Remove label is English. Use `reject` and a `role="status"` region as in [Rejected files](#rejected-files), and the `file-trailing` slot for another language.
- `required` reaches assistive tech only through the label and the browser's own message: `aria-required` isn't allowed on a button.
- `open()` works only straight from a click or a key press. After an `await` or a timer, the browser blocks the dialog without a word.
- Safari doesn't say what's being dragged until the drop, so a file that will be rejected looks welcome until then.
- Safari before 14.1 can't put dropped files into the hidden input. `v-model` still works; native form submission misses them.
- Long lists aren't virtualised. File lists rarely run past a few dozen.
