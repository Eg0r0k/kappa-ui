## Usage

```vue
<script setup lang="ts">
import { Button } from '@/components/ui/button'
import {
  Drawer,
  DrawerBody,
  DrawerClose,
  DrawerContent,
  DrawerDescription,
  DrawerFooter,
  DrawerHeader,
  DrawerTitle,
  DrawerTrigger,
} from '@/components/ui/drawer'
</script>

<template>
  <Drawer>
    <DrawerTrigger as-child>
      <Button>Edit profile</Button>
    </DrawerTrigger>
    <DrawerContent>
      <DrawerHeader>
        <DrawerTitle>Edit profile</DrawerTitle>
        <DrawerDescription>Changes are saved when you press Save.</DrawerDescription>
      </DrawerHeader>
      <DrawerBody>
        <!-- the content -->
      </DrawerBody>
      <DrawerFooter>
        <DrawerClose as-child>
          <Button>Save</Button>
        </DrawerClose>
      </DrawerFooter>
    </DrawerContent>
  </Drawer>
</template>
```


- `Drawer`: holds the state; `v-model:open` opens it from code
- `DrawerTrigger`: opens it
- `DrawerContent`: the panel, with an overlay and a drag handle; `side` picks the edge, `bottom` by default
- `DrawerHeader`, `DrawerBody`, `DrawerFooter`: the three parts; the body scrolls when needed
- `DrawerClose`: wrap any button in it to make it close the drawer

Under the hood it's a [Dialog](/docs/components/dialog), so focus, Escape and the overlay work the same. The drawer adds gestures on top.

Drag the panel towards its edge: past halfway or with a quick flick, it closes; otherwise it springs back. If the body is scrolled, it scrolls first; at the top, the drawer moves. A mouse works too, and selecting text never starts a drag.

## Gesture

Drags start only where they make sense. Got a map or a slider inside? Add `data-no-drag`, and it keeps its drags for itself. Want dragging only by the handle? Set `handle-only`. `modal: false` removes the overlay and keeps the page clickable, and the gestures still work.

::callout
Tap the handle to close the drawer, or to jump to the next snap point.
::

## Snap points

Like the sheet in a maps app. `snap-points` lists where the panel can stop, smallest first: `0.5` is half the screen, `320` or `"320px"` is pixels. Make the panel at least as tall as the largest point (`h-[95dvh]` in the demo).

It opens at the first point, or at `v-model:active-snap-point`, and goes back there after closing.

A slow release settles on the nearest point, a quick swipe moves one step, and a hard fling goes all the way. Want one step at a time? Set `snap-to-sequential-points`. Drag below the smallest point to close, unless `dismissible` is `false`. Tapping the handle cycles through the points.

The body scrolls only at the largest point; lower down, every drag moves the panel. The overlay shows only from `fade-from-index` up (the last point by default), so the page stays readable under a small sheet.

## Scaled page

Wrap the app in `DrawerIndent`, and the page politely steps back while a drawer is open: it shrinks, rounds its corners and shows black around it (change it with `class`). It follows your finger too.

```vue
<!-- App.vue -->
<template>
  <DrawerIndent>
    <RouterView />
  </DrawerIndent>
</template>
```

`position: sticky` keeps working inside. `position: fixed` doesn't while the page is scaled, so render fixed things through a portal, as the kit's own overlays do.

## From code

Works like [opening a dialog from code](/docs/components/dialog#from-code), with the same service. Put `DialogHost` inside `DrawerIndent`, so drawers opened from code step the page back too.

Render `DrawerContent` and close with `useDialogContext()`, both imported from the drawer:

```vue
<!-- ShareDrawer.vue -->
<script setup lang="ts">
import { Button } from '@/components/ui/button'
import { DrawerContent, DrawerHeader, DrawerTitle, useDialogContext } from '@/components/ui/drawer'

const { close } = useDialogContext<string>()
</script>

<template>
  <DrawerContent>
    <DrawerHeader>
      <DrawerTitle>Share</DrawerTitle>
    </DrawerHeader>
    <Button @click="close('Mail')">Mail</Button>
  </DrawerContent>
</template>
```

`openDrawer(component, props, options)` and `defineDrawer()` work like `openDialog` and `defineDialog`. The options are `Drawer`'s props: `side`, `dismissible`, `handle-only`, `modal` and snap points. A swipe that closes the drawer gives the reason `swipe`, and while `loading` is `true`, a swipe springs back instead of closing.

## Motion

| | Duration | Easing |
|---|---|---|
| Open | `--transition-duration-medium-4` | `--ease-emphasized-decelerate` |
| Close | `--transition-duration-short-4` | `--ease-emphasized-accelerate` |
| Spring back, page scale, stacking | `--transition-duration-medium-2` | `--ease-standard` |

While you drag, there's no transition: the panel follows your finger exactly. With reduced motion, it appears and disappears at once, but still follows a drag.

It all runs on the `drawer-slide`, `drawer-overlay-fade` and `drawer-indent` utilities from `@kappa-ui/core/tailwind.css`.

Using the per-frame variables (`--drawer-swipe-movement`, `--drawer-swipe-progress`, `--drawer-nested-progress`, `--drawer-indent-progress`)? Read them on the element that has them, not on its children. They don't inherit, for performance.

::css-vars
---
rows:
  - name: --drawer-size
    default: measured
    description: The panel's size along its axis, in px.
  - name: --drawer-swipe-movement
    default: 0px
    description: On the panel, how far a drag has moved it towards its edge.
  - name: --drawer-swipe-progress
    default: "0"
    description: On the panel and the overlay, movement divided by size, from 0 to 1. The overlay fades with it; with snap points it stays 0 on the overlay.
  - name: --drawer-snap-offset
    default: 0px
    description: What the active snap point hides below the edge; added to the swipe movement.
  - name: --drawer-overlay-opacity
    default: "1"
    description: On the overlay, the opacity from `fade-from-index`, 0 to 1; multiplied with the swipe fade.
  - name: --drawer-keyboard-inset
    default: 0px
    description: What the visual viewport lost to the keyboard; a bottom drawer lifts by it.
  - name: --drawer-nested
    default: "0"
    description: On a drawer, the number of drawers open above it.
  - name: --drawer-nested-progress
    default: "0"
    description: On a drawer, how far it has stepped back; each drawer above adds up to 1, less while it is swiped away.
  - name: --drawer-indent-progress
    default: "0"
    description: On the page in DrawerIndent, how far it has stepped back, from 0 to 1; follows the first open drawer.
  - name: --drawer-indent-top
    default: 0px
    description: On the page, how much of it is above the screen when the indent starts; the scale and clip use the part on screen.
  - name: --drawer-indent-bottom
    default: 0px
    description: On the page, how much of it is below the screen when the indent starts.
---
::

## API Reference

Every part except `Drawer`, which renders no element, accepts `class`, merged over its own classes with tailwind-merge. On `DrawerContent` it styles the panel, so `h-[85dvh]` sets a bottom drawer's height and `bg-*` replaces its background.

### Data attributes

::data-slots
---
rows:
  - slot: drawer-trigger
    attributes: data-state
    description: The element that opens the drawer.
  - slot: drawer-overlay
    attributes: data-state, data-swiping
    description: The scrim; fades with the swipe.
  - slot: drawer-content
    attributes: data-state, data-side, data-swiping, data-expanded, data-nested-open, data-nested-swiping
    description: The panel; carries the variables above. data-expanded while it shows its full size, without snap points or at the largest one; data-nested-open while a drawer is open above it, data-nested-swiping while that one is swiped.
  - slot: drawer-handle
    description: The drag bar; a tap on it closes, or with snap points moves to the next point.
  - slot: drawer-swipe-area
    attributes: data-side
    description: The strip that opens the drawer with a swipe; its gesture is live while the drawer is closed.
  - slot: drawer-indent
    description: The wrapper around the page; its background shows around the scaled page.
  - slot: drawer-indent-page
    attributes: data-open, data-side, data-swiping
    description: The page. data-open while a modal drawer is open; data-side and data-swiping from the first open drawer, kept until the page has returned.
  - slot: drawer-header
    description: The title block.
  - slot: drawer-title
    description: The heading that names the drawer.
  - slot: drawer-description
    description: The text under the title.
  - slot: drawer-body
    description: The scrolling middle.
  - slot: drawer-footer
    description: The actions row.
  - slot: drawer-close
    description: A button that closes the drawer, including the optional corner one.
---

## Accessibility

The drawer's name comes from its `DrawerTitle` and its description from its `DrawerDescription`; always give it a title. When either is missing, the panel renders an empty hidden one, so Reka UI does not warn. The handle is `aria-hidden`: keyboard users close the drawer with Escape or a button.

::keyboard-table
---
rows:
  - keys: Tab / Shift + Tab
    description: Moves to the next or previous control in the panel, wrapping around inside it.
  - keys: Escape
    description: Closes the drawer and returns focus to the element that opened it.
---
::
