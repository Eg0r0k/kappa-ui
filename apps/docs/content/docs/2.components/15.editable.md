## Usage

```vue
<script setup lang="ts">
import { Editable, EditableArea, EditableInput, EditablePreview } from '@/components/ui/editable'

const title = ref('Q4 roadmap')
</script>

<template>
  <Editable v-model="title" placeholder="Untitled" class="text-headline-sm font-semibold">
    <EditableArea>
      <EditablePreview />
      <EditableInput />
    </EditableArea>
  </Editable>
</template>
```

- `Editable`: the root; the value, the modes and the slot with `edit`, `submit` and `cancel`
- `EditableArea`: the box the text and the field share; a tint on hover, the focus ring while editing
- `EditablePreview`: the text, or the placeholder while the value is empty
- `EditableInput`: the field, in the same type as the text

There is no size: the text and the field take the font, size and weight of the place they sit in, so a heading stays a heading while you edit it. Set the type on `Editable` or on its parent.

`autoResize` is on, so the field is exactly as wide as its text and nothing moves when editing starts: the area is a grid with the text and the field in one cell, so a width, background or font class on `EditableInput` applies as on any other part. Turn it off and give the area a width when the field should fill a column instead.

`activationMode` decides what starts editing: `focus` (a click or Tab), `dblclick` or `none`. `submitMode` decides what saves: `blur`, `enter`, `both` or `none`. Escape always cancels and brings the old value back.

## Examples

### Buttons

Want a pencil to start and buttons to save or cancel? Put them in the root and wire them to its slot. Clicks inside the root don't count as leaving it, so the buttons work in every `submitMode`.

::component-preview{name="editable-buttons"}
::

### In a table

Each cell holds its own `Editable`. The cell keeps its padding; the box reaches a little past the text.

::component-preview{name="editable-table"}
::

### Double click

With `activationMode="dblclick"` a single click selects the row or opens it, and a double click renames, like files in a file manager. `selectOnFocus` selects the old name, ready to type over.

::component-preview{name="editable-double-click"}
::

## API Reference

Every part accepts `class`, merged over its base classes.

### Data attributes

::data-slots
---
rows:
  - slot: editable
    description: The root.
  - slot: editable-area
    attributes: data-focus, data-empty, data-placeholder-shown, data-readonly, data-disabled
    description: "The shared box. `data-focus` while editing, `data-placeholder-shown` while the text shows, `data-empty` while the value is empty."
  - slot: editable-preview
    attributes: data-placeholder-shown
    description: The text, or the placeholder.
  - slot: editable-input
    attributes: data-readonly, data-disabled
    description: The field.

### Keyboard

::keyboard-table
---
rows:
  - keys: Tab
    description: Moves to the text; with `activationMode="focus"` it starts editing.
  - keys: Enter

  - keys: Escape
    description: Cancels and brings the old value back.
---
::

## Accessibility

The field is a text input. Give it a name with `aria-label` on `EditableInput`, or put the editable in a [Field](/docs/components/field). A `readonly` editable can still be focused and its text selected, like a read-only input; a `disabled` one leaves the tab order.
