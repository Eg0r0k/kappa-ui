## Usage

[CheckboxGroup](/docs/components/checkbox) and [RadioGroup](/docs/components/radio-group) carry these layouts through their `variant` and `orientation` props, so you rarely render `ChoiceGroup` yourself. It exists so both groups draw from one place, and so a set of `Field`s that is neither can be laid out the same way.

```vue
<script setup lang="ts">
import { Checkbox, CheckboxGroup } from '@/components/ui/checkbox'
import { Field, FieldContent, FieldDescription, FieldLabel } from '@/components/ui/field'
</script>

<template>
  <CheckboxGroup variant="card" orientation="horizontal">
    <Field orientation="horizontal">
      <Checkbox value="email" />
      <FieldContent>
        <FieldLabel>Email</FieldLabel>
        <FieldDescription>A daily summary to your inbox.</FieldDescription>
      </FieldContent>
    </Field>
  </CheckboxGroup>
</template>
```

`default` stacks the options with a gap, or wraps them in a row. `card` turns each option into a bordered card, `list` into a row of one bordered list, and `table` into a table row whose label and description sit in columns of their own. In all three the whole card or row is clickable, shows the hover and press layers, and tints once checked; the control's own circle stays off there, since the row already shows the state. `orientation="horizontal"` lays cards out in a grid and list and table rows side by side.

Each option is a horizontal [Field](/docs/components/field): the layout styles the fields it holds as direct children, so keep them that way.
