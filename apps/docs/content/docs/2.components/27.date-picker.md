## Usage

```vue
<script setup lang="ts">
import { CalendarDate } from '@internationalized/date'
import type { DateValue } from 'reka-ui'
import { DatePicker } from '@/components/ui/date-picker'

const date = shallowRef<DateValue | undefined>(new CalendarDate(2026, 10, 6))
</script>

<template>
  <DatePicker v-model="date" locale="en-US" aria-label="Due date" />
</template>
```

It's an [InputDate](/docs/components/input-date) with a calendar button at the end. The button opens a [Calendar](/docs/components/calendar) in a popover, so people who know the date type it and the rest pick it. Both edit the same `v-model`.

`v-model` is a `CalendarDate` from `@internationalized/date`, or `undefined` until every segment is filled. Set `name`, and it submits as `YYYY-MM-DD`.

Picking a day closes the calendar and puts focus back on the button. Clicking the selected day again keeps it; Reka UI would clear it.

Pass `locale`, or set it once on Reka UI's `ConfigProvider`. Without one, you get `en`: month first, Sunday first, whatever your users expect.

Put it in a [Field](/docs/components/field), or give it an `aria-label`.

## Examples

### Button trigger

The shadcn look: an outline button that shows the date. Compose the parts, hand the trigger to your `Button` with `as-child`, and put `DatePickerValue` inside. In a Field, the button takes the label, the description and the invalid state, and a `name` still submits through a hidden input.

::component-preview{name="date-picker-button"}
::

### Unavailable dates

`is-date-disabled` takes days off the calendar, such as weekends. `is-date-unavailable` strikes them through but keeps them in the arrow-key path, for days that exist but are full. Either one, typed into the field, marks it invalid.

`min-value` and `max-value` disable the days outside them and stop the arrows at their months.

::component-preview{name="date-picker-unavailable"}
::

### Date of birth

Paging back forty years a month at a time is nobody's idea of fun. The calendar's `heading` slot takes month and year selects; `setPlaceholder` moves the view without picking a day.

`default-placeholder` sets where the calendar opens while there is no date.

::component-preview{name="date-picker-birthday"}
::

### Date and time

Pass a `CalendarDateTime` and set `granularity`, and the time segments follow the date in the field. Picking a day keeps the typed time.

With time segments the calendar stays open after a pick, so the time can be set next. Add a Done button under the calendar, or set `close-on-select`.

::component-preview{name="date-picker-date-time"}
::

### Presets

`DatePickerContent` takes anything after the calendar. Buttons that set `v-model` and close with `v-model:open` make quick picks.

::component-preview{name="date-picker-presets"}
::

### Locale

The segment order, the month names and the first day of the week all come from the locale. In right-to-left, the arrows and the arrow keys flip too.

::component-preview{name="date-picker-locale"}
::

### Variants

The five text control variants, the same as on [Input](/docs/components/input). While the calendar is open, the frame keeps its focus colour.

::component-preview{name="date-picker-variants"}
::

### Sizes

The field runs from 28px at `xs` to 48px at `xl`, and the calendar takes the same size: an `xl` field opens 48px days. Give `DatePickerCalendar` its own `size` to break the pair. For touch, `lg` or `xl` days are easier to hit.

::component-preview{name="date-picker-sizes"}
::

### In an input group

Inside an [InputGroup](/docs/components/input-group) the picker drops its own frame and takes the group's variant and size.

::component-preview{name="date-picker-input-group"}
::

### States

`disabled` turns off the segments, the button and the calendar. `readonly` keeps the field focusable and the calendar viewable, but nothing can be picked. Field's `invalid` and `required` reach it too.

::component-preview{name="date-picker-states"}
::

### In a dialog

The calendar opens above the dialog, and picking a day doesn't close it.

::component-preview{name="date-picker-dialog"}
::

### Form

`focus` and `blur` fire once for the whole picker: moving from the segments to the button to the calendar, or to a select in the calendar's heading, isn't leaving it. So a form that validates on blur doesn't flag an empty field the moment the calendar opens, and a pick in the calendar is checked like typing.

To keep an ISO string in the form, convert at the boundary, and parse each string only once: a new `CalendarDate` on every render is a new value each time. Register the first segment with the form library so it can focus the field after a failed submit.

::component-preview{name="date-picker-form"}
::

## Known limits

The picker is built from Reka UI's DateField and Calendar, which are still alpha upstream ([reka-ui#2789](https://github.com/unovue/reka-ui/issues/2789)).

- Typing into the last segment never stops: a fifth year digit starts the year over ([reka-ui#2002](https://github.com/unovue/reka-ui/issues/2002)).
- A half-typed date is `undefined`, the same as an empty one, so "required" and "incomplete" read alike ([nuxt/ui#6244](https://github.com/nuxt/ui/issues/6244)).
- Home, End, PageUp and PageDown in the calendar need reka-ui 2.11 ([reka-ui#2530](https://github.com/unovue/reka-ui/pull/2530)). On 2.10 they do nothing.
- The segments' screen reader labels ("day", "month", "year") and the calendar's "Previous page" and "Next page" are English whatever the locale ([reka-ui#2366](https://github.com/unovue/reka-ui/issues/2366)). The trigger's "Open calendar" takes an `aria-label`.
- Without `locale` or a `ConfigProvider`, the order is `en`'s: month, day, year ([nuxt/ui#5552](https://github.com/nuxt/ui/issues/5552)).
- On reka-ui 2.10, a `v-model` rebuilt as a new object for the same day moved the calendar back to it ([reka-ui#2960](https://github.com/unovue/reka-ui/issues/2960)). The picker works around it, so paging survives a form that re-parses its value.

## API Reference

`DatePicker` on its own renders the field and the calendar. To change either, put the parts in its default slot. Every part with an element accepts `class`, merged over its base classes; on the root it goes to the field.

`DatePickerCalendar` is a [Calendar](/docs/components/calendar#data-attributes) and the field holds an [InputDate](/docs/components/input-date#data-attributes); their attributes apply.

## Accessibility

The field is a `group` labelled by its Field, with a `spinbutton` for each segment, as on [InputDate](/docs/components/input-date#accessibility). The button after it says "Open calendar" and is announced as opening a dialog; pass your own `aria-label` to change it.

When it opens, focus goes to the selected day, else today, else the first day you can pick. Reka UI's own first focus can land on a hidden copy of the day in the neighbouring month and then focus nothing; the picker skips those. Escape, or a pick, closes it and returns focus to the button.

With a button trigger, the button is the control: it takes the Field's `id`, so the label points at it, and it's named by the label and its text together: "Publish on Oct 6, 2026".

::keyboard-table
---
rows:
  - keys: Tab / Shift + Tab
    description: "Moves through the segments, then to the calendar button, then out. In the open calendar, it goes round the arrows and the days."
  - keys: 0–9
    description: Types into the segment and moves to the next one when it is full.
  - keys: ArrowUp / ArrowDown
    description: In a segment, steps it. In the calendar, moves a week.
  - keys: ArrowLeft / ArrowRight
    description: Moves between the segments. In the calendar, moves a day, flipped in right-to-left.
  - keys: Alt + ArrowDown
    description: Opens the calendar from a segment, as on a native date input.
  - keys: Enter / Space
    description: On the button, opens or closes the calendar. On a day, picks it.
  - keys: Home / End
    description: Moves to the first or last day of the week. Needs reka-ui 2.11 or later.
  - keys: PageUp / PageDown
    description: Moves a month; with Shift, a year. Needs reka-ui 2.11 or later.
  - keys: Escape
    description: Closes the calendar without a change and returns focus to the button.
  - keys: Enter
    description: In a segment, submits the form, like a native date input.
---
