## Usage

```vue
<script setup lang="ts">
import {
  Tour,
  TourClose,
  TourContent,
  TourDescription,
  TourFooter,
  TourNext,
  TourPrev,
  TourProgress,
  TourTitle,
  useTour,
} from '@/components/ui/tour'

const card = useTemplateRef('card')

const tour = useTour([
  { target: null, title: 'Welcome', body: 'A quick look around.' },
  { target: 'new-file', title: 'Create', body: 'Start something new here.' },
  { target: () => card.value, title: 'Profile', body: 'Your account lives here.', side: 'left' as const },
])
</script>

<template>
  <Button @click="tour.start()">Start the tour</Button>

  <Tour v-slot="{ step }" :tour="tour">
    <TourContent :side="step.side">
      <TourTitle>{{ step.title }}</TourTitle>
      <TourDescription>{{ step.body }}</TourDescription>
      <TourFooter>
        <TourProgress />
        <TourPrev />
        <TourNext />
      </TourFooter>
      <TourClose />
    </TourContent>
  </Tour>
</template>
```

`useTour` holds the steps and which one is showing; `Tour` puts a single [popover](/docs/components/popover) on the current step's element and moves it as the tour goes on. You write the steps, so the copy, the fields and the layout are yours: every field besides `target` rides along to the slot's `step`, typed. Ported from Nuxt UI's composable of the same name, with parts on top.

A step's `target` is the element it points at:

- a plain word is an id, so `'header'` means `#header`, never the `<header>` element;
- anything else is a CSS selector: `'#cta'`, `'.card'`, `'[data-tour="search"]'`;
- an element, a virtual element (anything with `getBoundingClientRect`), or a ref or getter returning one;
- `null`, or no `target`, centres the step in the viewport, for a welcome or a goodbye.

A target that matches nothing centres the step too, and in development `useTour` warns about it once.

The popover stays when you click elsewhere on the page and finishes on Escape. When it opens, focus moves to `TourNext`; when it closes, focus goes back to whatever started the tour. The current target is scrolled into view at each step.

| Option | Description |
|---|---|
| `initialStep` | The step `start()` opens on. `0` by default. |
| `loop` | Go back to the first step after the last instead of finishing. |
| `scrollIntoView` | `false` leaves the scroll alone; an object is passed to `scrollIntoView`. `{ behavior: 'smooth', block: 'center' }` by default. |

It returns `open`, `index`, `current`, `total`, `hasNext`, `hasPrev`, `reference` (the anchor for a popover of your own), `centered`, and `start(index?)`, `next()`, `prev()`, `goTo(index)`, `finish()`. `next()` on the last step finishes, or loops with `loop`.

## API Reference

`class` is also accepted on every part except `Tour` and merged over its classes.

::api-reference{parts="Tour,TourContent,TourTitle,TourDescription,TourFooter,TourProgress,TourPrev,TourNext,TourClose"}
::

### Data attributes

::data-slots
---
rows:
  - slot: tour-content
    attributes: data-state, data-side, data-align, data-centered
    description: The popover. `data-centered` is set while the step has no element to point at.
  - slot: tour-title
    description: The step's heading, which names the popover.
  - slot: tour-description
    description: The step's text, which describes the popover.
  - slot: tour-footer
    description: The row of progress and buttons.
  - slot: tour-progress
    description: The step count.
  - slot: tour-prev
    attributes: aria-disabled
    description: Back, disabled on the first step.
  - slot: tour-next
    description: Next, or Finish on the last step.
  - slot: tour-close
    description: Ends the tour.
---
::

## Accessibility

::keyboard-table
---
rows:
  - keys: Escape
    description: Ends the tour.
  - keys: Tab
    description: Moves between the buttons in the popover, then on to the page.
---
::

The popover is labelled by `TourTitle` and described by `TourDescription`. Back stays focusable on the first step and says it is disabled, so going back to the start does not drop focus. Buttons read "Back", "Next", "Finish" and "Close": pass your own text in their slots, and an `aria-label` on `TourClose`, to translate them.
