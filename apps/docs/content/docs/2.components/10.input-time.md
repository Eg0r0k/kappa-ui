## Usage

```vue
<script setup lang="ts">
import { Time } from '@internationalized/date'
import type { TimeValue } from 'reka-ui'
import { InputTime } from '@/components/ui/input-time'

const time = shallowRef<TimeValue | undefined>(new Time(9, 30))
</script>

<template>
  <InputTime v-model="time" />
</template>
```

Hours, minutes and AM/PM (in 12-hour time) are separate segments. Type digits or use the arrow keys; once a segment is full, focus jumps to the next one.

`v-model` is a `Time` from `@internationalized/date`, or `undefined` until every segment is filled.

Set `name`, and it submits as `HH:mm:ss`. Enter submits the form, like a native time input. Give it an `aria-label`, or put it in a [Field](/docs/components/field).

`focus` and `blur` fire once when focus enters or leaves the field, not for every segment, so a form library's validate-on-blur works. Clicking the frame outside the segments focuses the first one.

## Examples

### Range

`InputTimeRange` puts a start and an end time in one frame. Its `v-model` is `{ start, end }`.

With `name`, the form gets two fields, `name[start]` and `name[end]`, each `HH:mm:ss` and empty until that end is filled. `required` needs both.

::component-preview{name="input-time-range"}
::

### Hour cycle

`hour-cycle` is `24` or `12`. It defaults to the locale's cycle; `12` adds the AM/PM segment, which `A` and `P` set.

::component-preview{name="input-time-hour-cycle"}
::

### Granularity

`granularity` decides the last segment: `hour`, `minute` (the default) or `second`.

::component-preview{name="input-time-granularity"}
::

### Step

`step` sets how far an arrow key moves each segment, here 15 minutes. With `step-snapping`, a typed value snaps to the step.

::component-preview{name="input-time-step"}
::

### Min and max

A time before `min-value` or after `max-value` marks the segments `aria-invalid`, which turns the frame destructive. Put `invalid` on the field to show the error.

::component-preview{name="input-time-min-max"}
::

### Variants

The five text control variants, the same as on [Input](/docs/components/input).

::component-preview{name="input-time-variants"}
::

### Sizes

The field runs from 28px at `xs` to 48px at `xl`, the heights of the matching inputs.

::component-preview{name="input-time-sizes"}
::

### Loading

`loading` puts a spinner at the end of the field and marks it `aria-busy`. Typing stays on.

::component-preview{name="input-time-loading"}
::

### In an input group

Inside an [InputGroup](/docs/components/input-group) the field drops its own frame and takes the group's variant and size, so icons, text and buttons share one frame with it. Clicking an addon focuses the first segment.

::component-preview{name="input-time-group"}
::

### States

`disabled` fades the frame and the segments; `readonly` keeps the time focusable but not editable.

::component-preview{name="input-time-states"}
::

### Keyboard

::keyboard-table
---
rows:
  - keys: 0–9
    description: Types into the segment and moves to the next one when it is full.
  - keys: ArrowUp / ArrowDown
    description: Steps the segment by `step`, wrapping around.
  - keys: ArrowLeft / ArrowRight
    description: Moves focus to the previous or next segment.
  - keys: Backspace
    description: Deletes the last digit, then empties the segment.
  - keys: A / P
    description: Sets AM or PM in the 12-hour cycle.
  - keys: Enter
    description: Submits the form like a native time input: through its submit button, nothing while that button is disabled, and without one only when this is the form's single text field.
---
::
