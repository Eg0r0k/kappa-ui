## Usage

```vue
<script setup lang="ts">
import { Button } from '@/components/ui/button'
import {
  Dialog,
  DialogBody,
  DialogClose,
  DialogContent,
  DialogDescription,
  DialogFooter,
  DialogHeader,
  DialogTitle,
  DialogTrigger,
} from '@/components/ui/dialog'
</script>

<template>
  <Dialog>
    <DialogTrigger as-child>
      <Button>Edit profile</Button>
    </DialogTrigger>
    <DialogContent>
      <DialogHeader>
        <DialogTitle>Edit profile</DialogTitle>
        <DialogDescription>Changes are saved when you press Save.</DialogDescription>
      </DialogHeader>
      <DialogBody>
        <!-- the content -->
      </DialogBody>
      <DialogFooter>
        <DialogClose as-child>
          <Button>Save</Button>
        </DialogClose>
      </DialogFooter>
    </DialogContent>
  </Dialog>
</template>
```

- `Dialog`: holds the state; `v-model:open` opens it from code
- `DialogTrigger`: opens it
- `DialogContent`: the window, with an overlay and a close button
- `DialogHeader`, `DialogBody`, `DialogFooter`: the three parts
- `DialogClose`: wrap any button in it to make it close the dialog

Putting a form inside? Wrap the parts in `<form class="contents">`, so the layout and scrolling keep working.

Escape or a click outside closes it. Focus stays inside while it's open, lands on the first field rather than the close button, and returns to the trigger when the dialog closes. [More on overlays](/docs/getting-started/overlays).

Too much content? The body scrolls, and the header and footer stay put.

### Not dismissible

No escape. Literally. Prevent `escape-key-down` and `interact-outside` on `DialogContent`, and only a button inside can close it. Add `:show-close-button="false"` to hide the close button too.

Yo dawg, I heard you like dialogs. Open one from inside another, and it stacks on top. Only the top one dims the page, and Escape or a click outside closes only that one.

## From code

No template? No problem. Open a dialog from a store, a router guard or a callback, and `await` how it closed.

### Setup

Install it once:

```ts
// main.ts
import { createApp } from 'vue'

import { createDialogs } from '@/components/ui/dialog'
import App from './App.vue'

createApp(App).use(createDialogs()).mount('#app')
```

In Nuxt, use a plugin:

```ts
// plugins/dialogs.ts
import { createDialogs } from '@/components/ui/dialog'

export default defineNuxtPlugin((nuxtApp) => {
  nuxtApp.vueApp.use(createDialogs())
})
```

Add one `DialogHost` to the root component. Dialogs opened from code render there, so they can use the router, i18n and stores:

```vue
<!-- App.vue -->
<script setup lang="ts">
import { DialogHost } from '@/components/ui/dialog'
</script>

<template>
  <RouterView />
  <DialogHost />
</template>
```

### Opening a dialog

Write a component that renders `DialogContent`, just like in a template. `useDialogContext()` gives it `close(value)` and `dismiss()`:

```vue
<!-- DeleteFileDialog.vue -->
<script setup lang="ts">
import { Button } from '@/components/ui/button'
import {
  DialogContent,
  DialogDescription,
  DialogFooter,
  DialogHeader,
  DialogTitle,
  useDialogContext,
} from '@/components/ui/dialog'

const props = defineProps<{ name: string }>()

const { close, dismiss } = useDialogContext()
</script>

<template>
  <DialogContent class="max-w-sm">
    <DialogHeader>
      <DialogTitle>Delete {{ props.name }}?</DialogTitle>
      <DialogDescription>The file moves to the bin for 30 days.</DialogDescription>
    </DialogHeader>
    <DialogFooter>
      <Button variant="outline" color="neutral" @click="dismiss()">Cancel</Button>
      <Button color="destructive" @click="close()">Delete</Button>
    </DialogFooter>
  </DialogContent>
</template>
```

Then open it and wait:

```ts
const result = await openDialog(DeleteFileDialog, { name: 'report.pdf' })

if (result.ok) deleteFile()
```

The promise never rejects. After `close(value)`, `result.ok` is `true` and you get `result.value`. Otherwise it's `false`, and `result.reason` says why:

::component-preview{name="dialog-programmatic"}
::

| Reason | What happened |
|---|---|
| `escape` | Escape was pressed |
| `outside` | A click or focus landed outside |
| `swipe` | A drawer was swiped away |
| `close-button` | A `DialogClose` was pressed |
| `programmatic` | `dismiss()` was called |
| `close-all` | `closeAllDialogs()` was called |
| `unmount` | `DialogHost` unmounted |
| `no-host` | No service or no `DialogHost`. Resolves at once, with a console warning |
| `error` | It failed to render. The error also goes to `app.config.errorHandler` |

The promise is also a handle: `isOpen`, `close(value)` and `dismiss()` work from outside, and `patch(props)` updates the props on the fly. Only the first close counts.

### One dialog, many calls

`defineDialog(component, { props })` sets the component and default props once. Each `open(props)` merges new props over the defaults. Calling `open()` while the dialog is already open returns the same one, not a second window. `isOpen` and `dismiss()` work from anywhere.

In the demo, the caller updates the progress while the dialog is open:

::component-preview{name="dialog-define"}
::

Closing with a value? Type it on both sides: `useDialogContext<string>()` inside, `open<string>()` outside. `openDialog<string>()` works too, but then the props go unchecked. `defineDialog` checks both.

### Waiting for work

While `loading` from `useDialogContext()` is `true`, Escape, outside clicks and `DialogClose` do nothing. Only `close()` or `dismiss()` can close it. Disable the buttons too, so nobody starts the work twice.

::component-preview{name="dialog-async"}
::

### Keeping state

With `keepMounted: true`, a defined dialog is hidden instead of removed, so its state survives until the next open. Each open still gets its own promise.

::component-preview{name="dialog-keep-mounted"}
::

### Closing everything

`closeAllDialogs()` closes them all. Dialogs survive navigation, so to close them on every route change:

```ts
router.afterEach(() => closeAllDialogs())
```

## API Reference

Every part except `Dialog`, which renders no element, accepts `class`, merged over its own classes with tailwind-merge. On `DialogContent` and `DialogScrollContent` it styles the window, so a width class such as `max-w-2xl` resizes it.

## Accessibility

The dialog's name comes from its `DialogTitle` and its description from its `DialogDescription`. Always give it a title: without one, screen readers announce an unnamed dialog. To name a dialog without showing the title, wrap the title in `VisuallyHidden` from `reka-ui`. The description is optional. When either is missing, the window renders an empty hidden one in its place, so Reka UI does not warn in the console.

::keyboard-table
---
rows:
  - keys: Tab / Shift + Tab
    description: Moves to the next or previous control in the window, wrapping around inside it.
  - keys: Escape
    description: Closes the dialog and returns focus to the element that opened it. While an input method is composing text, Escape ends the composition instead.
---
