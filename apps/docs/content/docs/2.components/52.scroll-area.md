## Usage

```vue
<script setup lang="ts">
import { ScrollArea } from '@/components/ui/scroll-area'
</script>

<template>
  <ScrollArea class="h-72 rounded-lg border">
    <div class="p-4">…</div>
  </ScrollArea>
</template>
```

The scrolling stays native. Only the scrollbar is custom. On touch screens, the bars only show where you are, and touches go straight to the content.

::callout{type="warning"}
Give it a height: it doesn't grow with its content. Put padding on a wrapper inside, not on `ScrollArea` itself, or the bars drift out of line with the content. A border on the root is fine.
::

### Horizontal

`orientation` is `vertical` by default, `horizontal`, or `both`. A vertical area won't scroll sideways, so content that overflows horizontally needs `horizontal` or `both`. Right-to-left is mirrored either way.

::component-preview{name="scroll-area-horizontal"}
::

### Both axes

`orientation="both"` draws two bars that meet in the corner. To keep the corner free, use `verticalOffset` and `horizontalOffset`. With `virtualize`, only the vertical axis is virtualized.

::component-preview{name="scroll-area-both"}
::

### Edge fade

While the area can still scroll towards an edge, the root has `data-overflow-x-start`, `-x-end`, `-y-start` or `-y-end`. Pair it with [`scroll-fade-overlay-x`](/docs/components/scroll-fade) for gradients, or show controls with `group-has-[[data-overflow-x-end]]`. No scroll listeners needed.

The buttons in the demo scroll by 80% of the width with `setScrollPosition`.

::component-preview{name="scroll-area-edge-fade"}
::

### Edge events

`reachEdge` fires once when you scroll into an edge zone, with `{ edge, ref }`, and again only after you leave it. `edgeOffset` widens the zone in pixels. Want to load more on reach? That's [Infinite Scroll](/docs/components/infinite-scroll), which ships with this component.

::component-preview{name="scroll-area-reach-edge"}
::

### Virtualize

10,000 rows, 20 in the DOM. Set `virtualize` and pass `items`, and the default slot renders only what's on screen (plus a small buffer), with `{ item, index }`.

`estimateSize` is just a guess: real sizes are measured after render, so items can have different heights. It runs on [TanStack Virtual](https://tanstack.com/virtual/latest), which is why it installs `@tanstack/vue-virtual`.

::component-preview{name="scroll-area-virtualize"}

### Programmatic scroll

`scrollTo(index, edge?)` scrolls to an item. Pass `'start'`, `'center'` or `'end'` to align it; leave `edge` out, and an already visible item stays where it is.

`@virtual-scroll` fires with `{ index, from, to, direction, ref }` whenever the item at the scroll position changes.

::component-preview{name="scroll-area-scroll-to"}
::

### External scroll element

Want to virtualize against a parent scroller, like the page itself? Pass `getScrollElement` and `scrollMargin` (the list's offset from the top of that scroller) to `virtualize`. The component then grows to the list's full size and draws no bars.

`getScrollElement` must return the element right at mount. If it returns `null` first and the element later, the list won't attach to anything.

### Data you don't hold

Pass `items-size` and `items-fn` instead of `items`. The function is called with `(from, size)`, only for what's on screen.

## Accessibility

`tabindex` goes to the viewport, the element that actually scrolls. Other attributes, `aria-label` included, go to the root, so a label names the wrapper, not the focusable element.

Once focused, the viewport scrolls with the keyboard:

::keyboard-table
---
rows:
  - keys: ↑ ↓ ← →
    description: Scrolls by a line on the active axis.
  - keys: Page Up / Page Down
    description: Scrolls by a page.
  - keys: Home / End
    description: Scrolls to the start or the end.
  - keys: Space
    description: Scrolls down by a page; Shift+Space scrolls up.
---
