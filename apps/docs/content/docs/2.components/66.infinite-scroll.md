## Usage

```vue
<script setup lang="ts">
import { InfiniteScroll, ScrollArea } from '@/components/ui/scroll-area'

const load = async ({ index }: { index: number }) => {
  const page = await fetchPage(index)
  items.value = [...items.value, ...page.items]
  if (page.last) return 'stop'
}
</script>

<template>
  <ScrollArea class="h-72">
    <InfiniteScroll :on-load="load">
      <p v-for="item in items" :key="item.id">{{ item.text }}</p>
    </InfiniteScroll>
  </ScrollArea>
</template>
```

Scroll within `offset` pixels of the edge, and `onLoad` gets called with `{ direction, index }`. `index` starts at 1, so it doubles as a page number. It won't fire again until the promise settles.

Out of content? Return `'stop'`. To start again, call `resume()` or `reset()`.

If the promise throws, the next scroll retries the same page, and the error goes to `app.config.errorHandler`.

::callout{type="note"}
First page too short to scroll? Then there's nothing to trigger the next one. Turn on `initialFill`, and it keeps loading until the content overflows.
::

## Examples

### Reverse

`directions="['top']"` loads older content at the top, like a chat. Your reading position stays put while new content appears above.

Scroll the area to the bottom before turning loading on, or it hits the top edge right on mount.

::component-preview{name="infinite-scroll-reverse"}
::

### Horizontal

`start` and `end` load sideways. In right-to-left pages, they flip.

::component-preview{name="infinite-scroll-horizontal"}
::

### Both directions

Each direction lives its own life: its own page count, loading state and stop. One loading doesn't block the other.

### The composable

`useInfiniteScroll()` is the same thing without markup, for lists that draw their own loading rows. It returns the same things `InfiniteScroll` exposes.

```ts
const rootRef = useTemplateRef<HTMLElement>('root')
const { state, reset } = useInfiniteScroll({
  anchor: rootRef,
  directions: ['bottom'],
  onLoad: async ({ index }) => {
    /* … */
  },
})
```

- `target`: what to watch, an element, `window` or a `ScrollArea` API. By default, the nearest scrolling parent of `anchor`, or the window.
- `shouldLoad(direction)`: your own "time to load?" check instead of the pixel offset. Handy for virtualized lists that count rows. `InfiniteScroll` takes it as a prop too.

### Data attributes

::data-slots
---
rows:
  - slot: infinite-scroll
    attributes: data-orientation, aria-busy
    description: The root. A flex row when a horizontal direction is listed.
  - slot: infinite-scroll-loading
    attributes: data-direction, data-state
    description: The loading part at one edge, present until that direction stops. Invisible but keeping its room while idle.
  - slot: infinite-scroll-end
    attributes: data-direction
    description: The end slot at one edge, rendered once that direction is stopped and the slot is given.
---
::

## Accessibility

The root gets `aria-busy` while loading. Loading indicators are hidden from screen readers, so if new content matters to your users, announce it yourself.
